## 摘要
给智能体一个人类的凭据，它就继承了这个人的访问范围，却没有限制其使用的判断力。它可以将所有可达记录扫入模型上下文，隐藏指令在其中操纵其下一次调用，每个请求保持凭据有效，而智能体越权或吸收秘密。提示词是脆弱的护栏：一个易出错的推理者解释任务并执行其限制。我们提出带外策略执行（OBPE），一个位于智能体推理之外的可信边界。它授权类型化操作和资源，在后端调用前缩小查询范围，然后在响应中过滤记录和字段或掩码值。语义门控可以根据参数值或外部状态拒绝或暂缓已授权的调用。数据策略所有者设置最大授权；智能体策略只能缩小它。我们证明，在所述条件下，策略计划是顺序无关的，且智能体策略不能扩大上限。字段移除覆盖一次执行；掩码和历史规则则声明较弱。我们发布了一个从生产系统简化的HTTP代理原型，带有将其类型化Cedar策略核心与模型相联系的合规测试。针对Jira和ServiceNow模拟，我们的基准测试在四个模型上比较了带和不带OBPE的提示智能体，包括20个自适应红队任务。跟踪失败意味着受保护数据进入智能体上下文，答案中出现确切值，或禁止的效果完成。在3621次试验中，它从57.6%下降到0.2%，集群加权减少41.2个百分点[95% CI: 27.7, 54.9]；完成率从79.1%下降到60.9%，而配对的安全有用完成率上升21.8个百分点[9.5, 35.2]。一些答案重建了从未进入上下文的值，或使用过滤后的行计数作为预言：塑造一次执行并非无干扰。写入控制、持久批准、时间和聚合策略不在本次评估范围内。

## Abstract
Give an agent a human's credential and it inherits the person's reach without the judgment that limits its use. It can sweep every reachable record into model context, where hidden instructions steer its next call, and every request stays credential-valid while the agent exceeds its job or absorbs a secret. Prompts are a brittle guardrail: one fallible reasoner interprets the task and enforces its limits.   We present Out-of-Band Policy Enforcement (OBPE), a trusted boundary outside agent reasoning. It authorizes the typed operation and resource, narrows the query before the backend call, then filters records and fields or masks values in the response. Semantic gating can deny or hold an authorized call on argument values or external state. A data policy owner sets the maximum grant; agent policy can only narrow it. We prove, under stated conditions, that the policy plan is order-independent and agent policy cannot widen the ceiling. Field removal covers one execution; masking and history rules claim less.   We release an HTTP proxy prototype simplified from our production system, with conformance tests tying its typed Cedar policy core to the model. Against Jira and ServiceNow mocks, our benchmark compares prompted agents with and without OBPE on four models, including 20 adaptive red-team tasks. A trace failure means protected data entered agent context, an exact value appeared in the answer, or a forbidden effect completed. In 3,621 trials it fell from 57.6% to 0.2%, a cluster-weighted reduction of 41.2 points [95% CI: 27.7, 54.9]; fulfillment fell from 79.1% to 60.9%, while paired safe-useful completion rose 21.8 points [9.5, 35.2]. Some answers reconstructed a value that never entered context or used filtered row counts as an oracle: shaping one execution is not noninterference. Write controls, durable approval, and temporal and aggregate policies lie outside this evaluation.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体在工具调用场景中继承人类凭据后，获得了同等访问范围，却缺少人类在执行任务时的判断力。智能体可能遍历所有可达记录、将敏感数据吸入模型上下文，并被数据中隐藏的提示注入指令操纵。
- **核心问题**：
  - 凭据约束的是“能访问什么”，而不是“本次任务应当访问什么”。
  - 提示词作为护栏不可靠：同一个易出错的推理者既要解释任务，又要执行对自身的限制。
  - 后端授权能回答“凭据允许做什么”，但无法回答“这个智能体为了这个任务应该做什么”。
  - 返回数据可能包含秘密或间接提示注入内容；即使调用合法，也可能需要根据参数或外部状态暂停或拒绝。
- **整体含义**：需要在智能体推理之外的可信工具边界上，对完整工具交换过程进行带外策略执行（Out-of-Band Policy Enforcement, OBPE），在请求发出前和响应进入模型上下文前进行授权、塑造和过滤。

## 2. 论文提出的方法论

- **核心思想**：将控制点置于智能体工具客户端与后端之间的可信边界。每次工具交换经过边界两次：请求（可能造成效果前）和响应（进入模型上下文前）。策略在边界上决定是否放行、如何塑造请求和响应，以及是否需要外部审批。
- **两级策略模型**：
  - 数据策略所有者（data policy owner）编写**所有者策略 S**，建立最大授权上限（permit eligibility）。
  - 注册智能体的**智能体策略 P_A**只能缩小该上限，不能扩大。
  - 后端凭据 C 仍然作为最外层执行限制。
- **策略计划 Π = (g, ρ, η)**：
  - 门控结果 g ∈ {deny, defer, permit}，通过 `GateMeet(κ; DS, DA)` 组合所有者与智能体匹配规则，默认拒绝。
  - 请求塑造 ρ = (q′, n′, w′)：查询约束、记录上限、可写字段/参数。
  - 响应计划 η = (φ_R, F′, μ)：记录过滤谓词、保留字段集合、内容操作（掩码/重写）。
- **执行管线**：
  1. 绑定平台身份，选择适用的智能体策略。
  2. 连接器将工具调用映射为类型化对象：主体、动作、资源、记录、字段。
  3. 所有者策略建立许可资格；智能体策略只能收窄。
  4. 门控在请求发出前执行；拒绝则停止，延期则持有快照等待外部决定。
  5. 请求塑造：缩小查询、限制结果数量、删除或钳制写字段。
  6. 响应返回路径：先按记录过滤，再按字段投影，最后做内容掩码和信封清理。
- **形式化保障**：
  - **置换不变性（Proposition 1）**：在 O1–O5 条件下，匹配规则顺序不影响最终策略计划。
  - **单调性（Proposition 2）**：添加限制不会扩大计划的授权范围。
  - **层级细化（Proposition 3）**：`Π_{S,A}(κ) ⪯_r Π_S(κ)`，即智能体策略只能让计划拥有不超过所有者策略的授权。
  - 条件 O1–O5 包括：身份绑定与完全中介、固定策略输入与默认拒绝、稳定阶段语义、安全写入方向、可信状态与持有调用。
- **实现原型**：使用 Cedar 类型化授权语言提供 permit/forbid 核心；通过 HTTP 代理实现 gate–request–response 合同；提供合规测试套件将代码与形式模型关联。

## 3. 实验设计

- **数据集/场景**：
  - 71 个任务，分 35 个场景簇，针对受控的 Jira 和 ServiceNow 模拟后端。
  - 任务包含 20 个响应自适应、多轮红队任务，由 Claude Opus 4.7 作为攻击者推动，目标是提取受保护数据、触发未授权后端效果或绕过智能体策略。
- **模型**：4 个工具调用智能体模型——Claude Sonnet 4.6、Claude Haiku 4.5、GPT-5、GPT-5 mini。
- **对比方法/配置**：
  - **raw agent**：仅角色和工具提示，直接调用模拟后端。
  - **prompt only**：添加 6 条数据处理规则，工具路径不变。
  - **prompt + full OBPE**：保留提示规则并添加完整 OBPE 边界。
  - **prompt + output reviewer**：保留原始工具路径，由固定 Claude Haiku 4.5 审查每条助手消息。
- **主要对比**：
  - RQ1：prompt only → prompt + full OBPE（4 个模型）。
  - RQ2a：raw → raw + OBPE 与 prompt only → prompt + OBPE 的 2×2 设计（Sonnet）。
  - RQ2b：累积消融——记录控制 → +字段剥离 → +掩码与写保护 → +模式掩码（Sonnet）。
  - RQ3：prompt + output reviewer ↔ prompt + full OBPE（Sonnet）。
- **评估指标**：
  - **确定性跟踪失败（trace failure）**：受保护数据进入智能体上下文、精确受保护值出现在最终答案、或禁止的后端效果完成。越低越好。
  - **任务完成（task fulfilled）**：独立判断是否完成请求工作。
  - **安全有用完成（safe-useful completion）**：无跟踪失败、满足归档工具合同、法官判定允许的工作完成且无语义披露。越高越好。
  - **语义披露**：由主法官 Claude Opus 4.8 和辅助法官 GPT-5 独立判断，两个判断结果均保留，不做人工裁决。
- **统计方法**：以场景簇为独立单元，配对计算配置差异后等权平均；10,000 次自助法获得 95% CI；计划需至少 30 个簇；另有完整块敏感性分析。

## 6. 论文的主要结论与发现

- **主要安全结果**：在 prompt only → prompt + full OBPE 的主要对比中，未加权跟踪失败率从 57.6% 降至 0.2%；聚类加权减少 41.2 个百分点 [95% CI: 27.7, 54.9]。
- **安全有用完成**：未加权独立任务完成率从 79.1% 降至 60.9%，但安全有用完成率在法官 A 下从 22.0% 升至 58.9%，配对提升 21.8 个百分点 [9.5, 35.2]；法官 B 提升 19.1 个百分点 [6.9, 32.2]。
- **提示词的作用有限**：提示词降低了精确值和语义披露，但对上下文暴露（55.1%→52.1%）和禁止后端效果（8.1%→5.5%）几乎没有改善。
- **OBPE 的机制**：添加 OBPE 后，观察到上下文暴露和禁止后端效果均降为 0；剩余失败是重建值，而非边界直接泄漏。
- **红队切片**：20 个自适应任务中，跟踪失败从 74.9%（173/231）降至 0.9%（2/227）。
- **消融发现**：
  - 记录控制单独保护率 46.7%；增加字段剥离提高到 69.4%；增加掩码与写保护到 88.6%；增加模式掩码到 100%（Sonnet 样本）。
  - 聚类加权分析显示各层保护增益为正，但只有模式掩码的增益区间排除零。
- **输出审查器**：运行在暴露和效果之后，跟踪失败率仍为 58.6%，安全有用率仅 19.7%，且增加 930 次额外模型调用；OBPE 无额外模型调用。
- **未解决的问题**：
  - 4 次最终答案重建了从未进入上下文的精确受保护值，说明字段移除仅保证单次执行缺失，不能证明无干扰。
  - 1 次行计数预言攻击：代理通过不断收窄查询谓词并观察返回行数，推断出受保护邮箱的部分值，法官 A 标记为语义披露，但确定性指标未发现失败——这是统计数据库 tracker 问题的现代体现。

- **清晰的证据分离**：明确区分形式模型证明、合规测试、基准观察和生产设计描述，不混淆不同来源的结论。

## 8. 不足与局限

- **原型简化**：发布的是 HTTP 代理，不覆盖流式响应、MCP 资源/提示/采样等表面；远程 A2A 仅本地适配器存在，未进入评估。
- **生产功能未评估**：持久人类批准、安全恢复、超时终止、时间策略、聚合策略等仅停留在设计层面；drop 和 clamp 操作符在发布 schema 中不可达。
- **Schema 依赖强**：连接器 schema 是安全状态；错误或缺失的映射会留下策略缺口；OpenAPI 自动导入器未发布，手工映射可能不可扩展。
- **数据场景局限**：模拟后端省略富文本、递归/多态对象、跨租户测试；没有真实 Jira/ServiceNow 部署的互操作性证据。
