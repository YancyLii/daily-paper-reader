## 摘要
受策略管理的智能体必须在遵循授权程序的同时解读案件证据。我们提出 Stage，一个可执行图框架，将模型判断限制在策略限定节点内，并将程序控制置于确定性代码中。在每个节点，模型接收与任务相关的策略上下文并返回带类型的结果，而协调器强制执行经审查的执行契约。我们在 SOP-Bench Referral Abuse、两个 τ²-bench 领域以及专有银行基准 Smart Dispute 上评估了 Stage。与单一整体式全策略执行相比，Stage 在程序复杂度不同的工作流上普遍提高了任务成功率和重复运行可靠性。最大提升出现在更深的 Telecom 和 Smart Dispute 工作流中，取决于模型，Pass³ 分别提高了 7.5–55.0 和 57.2–65.7 个百分点。这些结果表明，将策略限定上下文与确定性程序控制相结合可以提高策略执行的可靠性。

## Abstract
Policy-governed agents must interpret case evidence while following an authorized procedure. We present \textsc{Stage}, an executable-graph framework that confines model judgment to policy-scoped nodes while placing procedural control in deterministic code. At each node, the model receives task-relevant policy context and returns a typed result, while the coordinator enforces the reviewed execution contract. We evaluate \textsc{Stage} on SOP-Bench Referral Abuse, two $τ^2$-bench domains, and Smart Dispute, a proprietary banking benchmark. Compared with monolithic full-policy execution, \textsc{Stage} generally improves task success and repeated-run reliability across workflows of varying procedural complexity. The largest gains occur on the deeper Telecom and Smart Dispute workflows, where $\mathrm{Pass}^3$ increases by 7.5--55.0 and 57.2--65.7 percentage points, respectively, depending on the model. These results show that combining policy-scoped context with deterministic procedural control can improve the reliability of policy execution.

# STAGE 论文总结

## 1. 论文的核心问题与整体含义

- **研究背景**：大型语言模型（LLM）越来越多地被用作智能体，在受监管和运营环境中需要同时完成语义推理、工具调用、用户协调，并严格遵循政策、规则或手册。
- **核心问题**：政策往往是长程、分支、多阶段的程序。传统的“整体式全政策执行”（monolithic full-policy execution）让单一智能体同时处理语义推理和流程控制，随着上下文增长，容易出现步骤遗漏、错误路由以及未经验证的判断传播。
- **整体含义**：可靠的政策执行不仅取决于模型本身的推理能力，还取决于如何围绕模型组织政策上下文和控制权限。论文主张将“局部语义判断”与“程序控制”分离，以提升长流程、分支多、状态依赖型工作流的执行可靠性。

## 2. 方法论

### 2.1 核心思想

- 提出 **STAGE（Stateful Translation to Agentic Graph Execution）**：一个可执行图框架。
- 关键原则：**LLM 负责局部语义，代码负责控制**。模型只在策略限定的节点内进行判断，流程推进由确定性代码协调器掌控。

### 2.2 可执行政策图（Executable Policy Graph）

- 离线阶段，基于权威政策构建并冻结执行图。
- 图由**动作节点**和**决策节点**组成，通过合法转换连接。
- 构建流程：
  1. LLM 辅助将政策分解为有界任务；
  2. 为每个任务映射精确的源政策段落；
  3. 编写对应节点和转换；
  4. 对候选图中的扇入、扇出、收敛进行政策忠实吸收、串行化或复制重组；
  5. 确定性编译、验证，最终由人类审查并冻结。
- 如果无法实现忠实重组，则停止生成以供人工审查，绝不编造规则。

### 2.3 合规承载执行节点（Compliance-Carrying Execution Nodes）

- 每个节点是一份可执行契约，规定：
  - 局部任务；
  - 允许的技能与工具；
  - 结果验证规则；
  - 失败行为。
- 运行时，协调器解析当前节点，向模型提供：
  - 节点契约；
  - 可用案例信息；
  - 共享记忆；
  - 选定的策略视图（即该节点对应的政策片段）。
- 模型返回**类型化结果**，包括判断、支持证据引用和必要的结果字段。
- 节点契约包含源政策依据，使每个判断都有据可查。

### 2.4 协调器拥有的控制（Coordinator-Owned Control）

- 每次尝试后，协调器根据节点契约验证结果，并执行图声明的路由、重试、升级或终止行为。
- 由于后继节点选择不在模型内部，模型无法引入未声明的转换或绕过尝试次数限制。
- 所有执行过程形成可审计的运行时记录。

## 3. 实验设计

### 3.1 数据集与场景

| 基准 | 特点 |

### 3.2 对比方法 / 条件

- **Baseline（全政策单体执行）**：单一智能体接收完整政策，同时控制语义推理和程序推进。
- **Graph with full policy（图 + 完整政策）**：使用经审查的图控制执行，但每个节点接收完整政策。
- **Node-scoped STAGE（节点范围策略）**：相同图，但每个节点只接收与其任务相关的策略上下文。

两个图条件使用相同的拓扑、节点目标、案例证据、能力、结果接口、路由规则和尝试预算。

- 比较 Baseline 与 node-scoped STAGE：衡量图控制 + 策略局部化的综合效果。
- 比较两个图条件：固定控制结构，隔离策略局部化的单独影响。

### 3.3 模型

- 公共基准：GPT-5.6 Luna、DeepSeek V4 Flash、Claude Haiku 4.5、Claude Sonnet 5。
- Smart Dispute（专有）：仅使用 Claude Haiku 4.5 和 Claude Sonnet 5。

### 3.4 评价指标

- **Pass 1**：单次运行成功率。
- **Pass 3**：三次重复运行全部成功的比例，衡量重复运行可靠性。
- **Token 消耗**：输入、输出、总 token。
- **错误分类**：
  - **Accurate**：正确完成。
  - **Chain error**：完成但跳过或错序所需步骤，即使最终结果也错误也优先归为链错误。
  - **Execution/end error**：未完成、过程或工具失败、或没有链错误但最终结果错误。
