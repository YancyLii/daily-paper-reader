## 摘要
技能增强智能体会将可复用技能作为持久运行时上下文加载，这能提升任务表现，但也为恶意技能提供了持续影响后续行为的通道。此类技能可能泄露机密、破坏代码、绕过审批，或仅在具体用户任务与工作区状态使不安全操作看似有用后，才为数据外传进行准备。因此，安装前审查并不充分，需要运行时且以任务为条件的保护。我们提出 Defense-as-Skill（防御即技能），一种将运行时守卫本身实现为可安装、可检查、可编辑技能的防御范式。我们的守卫 SkillSonar 与不可信任务技能并行运行，依据用户任务边界检查敏感操作，并将每个操作路由为允许、重新规划或确认决策，而无需修改底层智能体运行时。为研究该场景，我们构建了 SCOPE-R，一个以任务为条件的数据集，覆盖 6 个风险家族和 21 个子类别，包含 206 个已确认攻击的恶意实例和 43 个良性任务。随后，我们在 SCOPE-R 训练子集上使用运行时守卫技能演化来改进 SkillSonar；该演化是一种蒙特卡洛树搜索过程，根据 rollout 反馈对磁盘上的守卫技能进行演化。在 Claude Code 和 OpenClaw 上，演化后的守卫显著降低了攻击成功率，同时保持了良好的安全-效用权衡。在多次 GLM-5 运行中，SkillSonar 将 ID ASR 从 0.482 降至 0.104，将 OOD ASR 从 0.606 降至 0.115。进一步分析表明，该守卫可在不同受害模型、留出风险家族和外部基准间迁移，并能对自适应攻击者保持防护。消融实验进一步显示，明确的安全责任分配以及技能原生表示对观测到的收益都很重要。

## Abstract
Skill-augmented agents load reusable skills as persistent runtime context, improving task performance but also giving malicious skills a durable channel for steering future actions. Such skills may leak secrets, corrupt code, bypass approvals, or stage data for exfiltration only after a concrete user task and workspace state make the unsafe action appear useful. This makes pre-install vetting insufficient and calls for runtime, task-conditioned protection. We propose Defense-as-Skill, a defense paradigm that implements the runtime guard itself as an installable, inspectable, and editable skill. Our guard, SkillSonar, runs alongside untrusted task skills and checks sensitive actions against the user's task boundary, routing each action to an allow, replan, or confirmation decision without modifying the underlying agent runtime. To study this setting, we construct SCOPE-R, a task-conditioned dataset covering 6 risk families and 21 sub-categories, with 206 attack-confirmed malicious instances and 43 benign tasks. We then improve SkillSonar on the SCOPE-R training subset using runtime guard-skill evolution, a Monte-Carlo Tree Search procedure that evolves the on-disk guard skill from feedback on the rollouts. Across Claude Code and OpenClaw, the evolved guard substantially reduces attack success while maintaining a favorable safety-utility trade-off. On repeated GLM-5 runs, SkillSonar reduces ID ASR from 0.482 to 0.104 and OOD ASR from 0.606 to 0.115. Further analyses demonstrate transfer across victim models, held-out risk families, and external benchmarks, as well as retained protection against adaptive attackers. Ablations further show that explicit safety responsibility assignment and the skill-native representation are both important to the observed gains.

## 一、核心问题与整体含义

- **研究背景**：技能增强智能体（Skill-Augmented Agents, SAAs）会将可复用技能作为持久运行时上下文加载，以提升任务表现。但恶意或被攻陷的技能也能利用这一机制持续引导后续行为，例如泄露密钥、破坏代码、绕过审批、外传数据等。
- **核心问题**：恶意技能不一定要在安装时触发危害，而可以等到具体用户任务、工作区状态和可用工具使不安全操作“看起来合理”时才发作，因此仅靠安装前审查不足，需要**运行时、以任务为条件的防护**。
- **整体含义**：提出 **Defense-as-Skill** 范式，将运行时守卫本身实现为可安装、可检查、可编辑的技能，让防护逻辑与技能增强智能体的原生工作流一致，从而具备可部署、可检查、可演化和可迁移性。

## 二、方法论

- **核心思想**：
  - 将运行时守卫 **SkillSonar** 作为一个普通技能加载到与任务技能相同的 SAA 环境中。
  - SkillSonar 与不可信任务技能并行运行，在智能体执行前检查每个敏感动作是否仍处于用户任务边界内。
  - 对动作做出三类决策：**allow（允许）**、**replan/narrow（重规划或收窄）**、**require confirmation（要求确认）**，且不修改底层智能体运行时。

- **关键技术细节**：
  - **风险分级与干预**：
    - R0：常规、无副作用，允许。
    - R1：可能良性但需要范围意识，可在收窄后继续。
    - R2：有实质风险，如广范围修改、敏感数据访问、外部状态改变等，需要说明理由并可能要求用户确认。
    - R3：明显越界或匹配恶意模式，如隐蔽外传、伪造授权、破坏性命令、隐藏持久化等，阻止或重规划。
  - **显式安全责任分配**：由于安全技能与任务语义常常不显式相关，论文将“先调用 SkillSonar 再执行动作”的指令作为部署配置的一部分，避免仅靠语义相关性检索守卫。
  - **技能原生表示**：将策略拆分为多个模块化技能组件（入口、运行时、检查清单、阶段组件），而非一次性压入系统提示。

- **守卫技能演化（Runtime guard-skill evolution）**：
  - 使用 **蒙特卡洛树搜索（MCTS）** 优化磁盘上的守卫技能版本。
  - 每个节点代表一个守卫技能候选；维护便宜评估统计 \( (n_v, \bar{Q}^c_v) \)、子树访问次数 \( N_v \)，以及全评估分数 \( Q^f_v \)。
  - 通过 **UCT** 选择扩展节点：
    \[
    \text{UCT}(v) = \bar{Q}^c_v + c \sqrt{\frac{\ln(\max(2, N_{\text{pa}(v)}))}{\max(1, n_v)}}
    \]
  - 全评估依据运行反馈生成 \( k \) 个子候选，用便宜集做初步评估，全评估只对要扩展的候选执行一次。
  - 标量得分：
    \[
    s(v) = (1 - \text{ASR}_v) + \epsilon \big(\lambda_b U^{\text{benign}}_v + \lambda_m U^{\text{malicious}}_v - \lambda_q \hat{C}_v - \lambda_t \hat{K}_v \big)
    \]
    其中 ASR 为主导目标，效用、确认次数和 token 成本作为次要偏好。

- **SCOPE-R 数据集构建**：
  - 从 PinchBench 的良性任务出发，生成初始良性技能，然后由**攻击者智能体**编辑技能以嵌入风险行为，由**受害者智能体**执行原任务，由**法官智能体**根据可观察运行标准判定攻击是否成功。
  - 仅保留攻击成功确认的实例；最终得到 **206 个恶意实例**和 **43 个良性任务**。
  - 风险体系 **SCOPE-R** 的六个家族：Specification Integrity、Capability Control、Operational Side Effects、Privacy & Data Flow、Execution Safety、Resource & Reliability，共 21 个子类别。

## 六、主要结论与发现

- SkillSonar 在 GLM-5 重复运行中，将 **ID ASR 从 0.482 降至 0.104**，**OOD ASR 从 0.606 降至 0.115**。
- 相比系统提示基线（ID 0.414，OOD 0.489），SkillSonar 提供更强防护。
- 相比 Claude Code 默认 AcceptEdits，SkillSonar 在相近或更低 ASR 下通常保留更高的任务效用；allowlist 会恢复效用但重新打开攻击路径，说明权限门控存在明显 trade-off。
- **显式安全责任分配非常重要**：如果仅靠普通技能检索激活守卫，保护效果大幅下降。
- **技能原生表示优于内容相同的扁平提示**：在相同决策内容下，技能原生表示获得更低 ASR、更高效用、更低 token 成本。
- **可迁移性**：优化的守卫可跨受害模型、跨留出风险家族迁移；对自适应攻击仍保留防护。
- **跨风险家族非均匀**：Execution Safety、Specification Integrity 降幅大，Operational Side Effects 和 Capability Control 相对更难。

## 七、优点

- **新颖的 Defense-as-Skill 范式**：将防御实现为可安装、可检查、可编辑的技能，不改动底层运行时，天然适配 SAA 工作流。
- **可演化的守卫**：用 MCTS 从运行反馈中迭代优化守卫技能，使防御本身成为可优化工件。
- **数据集设计严谨**：SCOPE-R 采用攻击者-受害者-法官闭环，仅保留攻击成功确认的实例；风险分类体系清晰。
- **评估维度丰富**：跨平台、跨模型、留出家族、外部基准、自适应攻击、消融和人工审计，多角度验证。
- **对实践有指导意义**：揭示了安全技能需要显式调用、技能原生表示优于扁平提示等可操作结论。

## 八、不足与局限

- **守卫仍是软策略**：SkillSonar 本质上是 Markdown 策略，依赖宿主模型遵循指令，可能被更高级的恶意技能忽略、覆盖或绕过；不能替代沙箱、权限系统等机制级强制控制。
- **资源描述不一致**：正文提到 8 块 A100，附录又说无本地 GPU、主要靠 API；且未给出具体训练时长或 GPU 利用率，难以评估真实算力消耗。
- **演化预算较小**：默认最多 10 次全评估、10 轮迭代，可能导致守卫未充分优化。论文也提到更大预算可能进一步提升，但收益或递减。
- **额外模型结果缺乏重复性**：GPT-5.4、Claude Haiku 4.5 等仅报告点估计，无法评估方差。
- **数据集规模有限**：206 个恶意实例、43 个良性任务，且均源自 PinchBench 任务，外部场景覆盖可能不足；跨基准结果应视为鲁棒性证据而非无限泛化。
- **OOD 风险家族部分模型仍较难**：如 Claude Haiku 4.5 的 OOD ASR 仍为 0.254，Capability Control 和 Operational Side Effects 在部分设置下残余风险较高。
- **与机制级防御比较不完整**：未系统对比 OS 沙箱、污点跟踪、强制信息流控制等更强控制方式。
