## 摘要
LLM智能体在工具调用参数中经常包含超出被调用工具所需的隐私敏感数据（PSD），在每次调用时跨越信任边界传递给第三方服务。对三个生产级LLM（GPT-4o、Claude 3.5 Sonnet、Llama-3.3-70B）的受控测量显示，在默认提示下，81%–88%的工具调用包含不必要的PSD；即使有明确的隐私指令，仍有36%–76%的过度共享。现有防御措施对调用进行门控（允许/阻止）或对数据流进行标记（信息流控制），但无法重写参数值，而且PII检测工具会遗漏隐式PSD，例如“Memorial Sloan Kettering”（一家暗示诊断的医院名称）。我们提出ToolMinimize，这是一个中间件，它拦截工具调用并将其参数重写为工具功能所需的最小数据，结合模式感知的必要性分析与四种操作：删除、泛化、替换和截断。在上述三个LLM的307次工具调用上的实时验证表明，在100%参数级任务有效性下（TOST等价检验 p<0.001，Δ=1.0），隐私成本降低了81.2%–92.0%；在25个未标注的Model Context Protocol（MCP）模式上，在没有minimum_necessary元数据的情况下降低了79.0%。一个可选的LLM内容必要性层从原本必要的自由文本字段中剥离与任务无关的PSD，将实时LLM降低幅度提高至85.1%–95.6%，并将作者模式的降低幅度从71.1%提高到90.9%。中位延迟为1.77ms。

## Abstract
LLM agents routinely include privacy-sensitive data (PSD) in tool call arguments beyond what the invoked tools require, crossing trust boundaries to third-party services on every invocation. A controlled measurement on three production LLMs (GPT-4o, Claude 3.5 Sonnet, Llama-3.3-70B) shows that 81--88\% of tool calls include unnecessary PSD under default prompts; explicit privacy instructions still leave 36--76\% over-sharing. Existing defenses gate calls (allow/block) or label flows (information-flow control) but cannot \emph{rewrite} argument values, and PII detection tools miss implicit PSD like ``Memorial Sloan Kettering'' (a hospital name that implies a diagnosis). We present \system{}, a middleware that intercepts tool calls and rewrites their arguments to the minimum data necessary for tool functionality, combining schema-aware necessity analysis with four operations: removal, generalization, substitution, and truncation. Live validation on 307 tool calls across the three LLMs above reduces privacy cost by 81.2--92.0\% at 100\% argument-level task validity (TOST equivalence $p{<}0.001$ at $Δ{=}1.0$); on 25 unannotated Model Context Protocol (MCP) schemas, by 79.0\% with no \texttt{minimum\_necessary} metadata. An optional LLM content-necessity layer strips task-irrelevant PSD from otherwise-necessary free-text fields, raising live-LLM reduction to 85.1--95.6\% and author-schema reduction from 71.1\% to 90.9\%. Median latency is 1.77\,ms.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体（如 GPT-4o、Claude、Llama）在调用外部工具（天气、日历、邮件等 API）时，常常在参数中携带超出工具功能所需的隐私敏感数据（PSD），例如把“Memorial Sloan Kettering Cancer Center”完整地址传给只需要城市级位置的天气 API，从而向第三方泄露用户健康、财务、位置等敏感信息。
- **核心问题**：这种“工具调用过度共享”（tool call over-sharing）现象普遍存在，且现有防御手段无法有效解决：
  - 允许/阻止门控（allow/block）只能整体放行或拒绝，无法改写参数值；
  - 信息流控制（IFC）只在流粒度打标签，不做逐字段的粒度化重写；
  - PII 检测工具（Presidio、AWS Comprehend 等）是模式匹配，会遗漏“Memorial Sloan Kettering”这类隐式 PSD，且不具备模式感知能力。
- **整体含义**：需要一个位于智能体与工具之间的中间件，在调用执行前自动审计并重写工具调用参数，实现数据最小化，同时保持任务有效性。

## 2. 论文提出的方法论

- **系统定位**：ToolMinimize 是一个中间件，拦截 LLM 智能体发出的工具调用，在参数构造（V3）之后、工具执行（V4）之前介入，无需修改 LLM、框架或工具本身。
- **流水线四阶段**：
  1. **Classify（分类）**：两阶段分类器识别参数中的 PSD。
     - Stage 1：Pattern-Classifier（40+ 正则表达式）+ EntityExtractor（基于正则的实体抽取），覆盖直接标识符、健康、财务、位置等类别。
     - Stage 2：SemanticClassifier，通过敏感机构查找、政府 ID 模式、职业推断（如“破产律师”→财务）、跨字段组合检测来捕捉模式匹配遗漏的隐式 PSD。
     - 可选：base64 解码预处理器，抵御简单编码逃避；可选 spaCy NER 后端提升直接标识符召回率。
  2. **Score（评分）**：计算隐私成本 `PC(t, args) = Σ S(p_j) · E(f) · N(p_j, f)`，其中：
     - `S(p)` 为 PSD 类别敏感度（1–4 级，基于 GDPR 分类）；
     - `E(f)` 为工具信任暴露级别（本地 0.2、同提供商远程 0.5、第三方有 DPA 0.8、第三方无 DPA 1.0）；
     - `N(p, f)` 为必要性二元值：若字段属于工具的 `minimum_necessary` 集合则为 0，否则为 1。
  3. **Analyze（分析）**：
     - SchemaAnalyzer 解析 JSON Schema 抽取必需、可选、最小必要字段集；
     - SemanticNecessityAnalyzer 对必需字段应用工具类型特定处理器（天气→城市级泛化、日历标题→通用占位符、搜索查询→去除标识符等），通用处理器覆盖 62.2% 场景。
  4. **Rewrite（重写）**：四种操作对应分析结论：
     - Removal：删除可选且不必要的字段；
     - Generalization：粗化值（如完整地址→城市名）；
     - Substitution：插入合法但合成的值（如 `user@example.com`）；
     - Truncation：截断精度（如 GPS 四舍五入、ZIP+4 缩短为 ZIP-5）。
- **失败模式**：fail-closed（默认，阻止并报错）、fail-open（放行并记录，需显式开启）、fail-prompt（带确认标志转发）。
- **可选内容感知层**：用 LLM 逐项判断检测到的 PSD 是否对用户任务必要，从原本必要的自由文本字段中剥离与任务无关的 PSD，进一步提升最小化程度。

## 6. 论文的主要结论与发现

- **过度共享是结构性的**：默认提示下 81%–88% 的工具调用包含不必要 PSD；隐私提示最多只能将 GPT-4o 的过度共享率降到 36%，对 Llama 几乎无效（81%→76%）。
- **ToolMinimize 有效**：在 307 次实时工具调用上，**隐私成本降低 81.2%–92.0%**，同时保持 **100% 参数级任务有效性**（TOST p<0.001）；在 25 个未标注 MCP 模式上降低 79.0%；在 50 个外部场景上降低 89.1%。
- **内容感知层进一步提升**：将实时 LLM 降低幅度提升至 85.1%–95.6%，作者模式降低幅度从 71.1% 提高到 90.9%。
- **低延迟**：中位延迟 1.77 ms，P99 在 2s 超时内；内容感知层约 800 ms/调用（可选）。
- **排名稳健**：在 110 种权重扰动下，ToolMinimize 始终是保持效用的方法中隐私成本最低的（Kendall τ=1.0）。
- **残余风险**：分类器召回有限（直接标识符 regex 召回 0.435，NER 提升到 0.739），残余暴露受召回率约束。

## 7. 优点

- **首创参数级重写**：区别于现有 allow/block 和信息流控制，ToolMinimize 通过删除、泛化、替换、截断四种操作真正改写参数值，在保持任务有效性的同时实现数据最小化。
- **模式感知**：利用 JSON Schema 的 required/optional/minimum_necessary 信息，能区分字段结构性必需与内容级必要，比纯 PII 检测更精准。
- **量化隐私成本指标**：PC 指标综合敏感度、暴露信任级别和必要性，且经过排名稳定性验证（Kendall τ=1.0），结论不依赖于具体权重。
- **低延迟、零外部依赖**：确定性正则后端中位 1.77 ms，无需 GPU，适用于多步智能体循环。
- **跨框架适配**：AutoGen、MCP、LangChain 三个适配器结果一致，适配开销 <0.1 ms。
- **可扩展性**：内容感知层可选，能在低延迟与更高最小化之间权衡；通用处理器覆盖超过 60% 场景，无需为每个工具定制处理器。
- **实验全面**：包含实时 LLM 验证、外部场景、真实 MCP 模式、对抗编码、框架对比、端到端执行等，统计检验较严格。

## 8. 不足与局限

- **分类器召回有限**：直接标识符（DI）正则召回仅 0.435，即使加 spaCy NER 也只到 0.739；漏检项会直接传播，真实泄露抑制受限于召回上界。
- **TCR 非端到端任务成功**：TCR 衡量参数级有效性，但端到端执行仅 80% 功能等价，4/20 地图场景因缺少 minimum_necessary 标注而失败；外部场景 TCR 降至 60%，表明在未知模式上泛化有限。
- **模拟与真实差异**：主要对比基于模拟 LLM 配置文件，虽实时验证显示后最小化 PCS 无显著差异（p=0.085），但更严格的等价边界（Δ=0.25）未通过（p=0.23）。
- **生态效度有限**：基准语料是隐私关键场景，基线 PER 高达 99.7%，一般使用场景下过度共享率可能更低，结果不能直接外推。
- **误报率偏高**：在良性输入上检测误报率 20%、重写误报率 10%，存在过度谨慎偏差，可能影响用户体验。
- **对抗逃避不完整**：10 种编码策略中字段拆分（field splitting）完全逃避检测，组合检测仍是未来工作。
- **用户自主性缺失**：ToolMinimize 单方面决定最小化，未提供用户预览/控制界面（未来工作方向）。
- **地域偏差**：分类器主要针对美国格式（地址、ZIP、SSN 等），对国际数据格式覆盖不足。
- **隐私成本指标局限**：未建模交互效应（如姓名+健康状况的联合泄露），且与 LLM 法官严重度的相关性较弱（ρ=+0.04），但论文论证了排名单调性足以支撑比较结论。
