## 摘要
指令层级是一种模型侧防御机制，根据来源为指令分配不同权限级别。这些级别限制哪些内容可以指导模型行为。然而，在智能体执行过程中，智能体框架会为每次模型调用构建上下文。这种构建可能将低级别内容提升到更高的指令层级，并赋予其更大的面向模型的权限。我们提出指令权限提升攻击。在该攻击中，攻击者诱导智能体将低级别恶意内容提升到更高的指令层级。提升后的内容随后导致智能体执行其在原始级别不会遵循的指令。我们通过多智能体机制在六个编码智能体框架上评估这一威胁，以实现13个攻击目标。这些目标涵盖机密性、完整性、可用性和远程代码执行。在无限制动作执行下，攻击在全部六个框架上实现了全部13个目标。在自动权限审查下，攻击在提供此模式的全部三个框架上实现了全部13个目标。我们进一步利用框架提供的持久目标和计划任务复现了该漏洞。这些结果证明了指令权限提升的普遍性。

## Abstract
Instruction hierarchy is a model-side defense that assigns instructions different levels of privilege according to their sources. These levels constrain which content may direct model behavior. During agent execution, however, agent harnesses construct context for each model invocation. This construction can elevate low-level content to a higher instruction level and grant it greater model-facing privilege. We introduce instruction privilege escalation. In this attack, an attacker induces an agent to elevate low-level malicious content to a higher instruction level. The elevated content then causes the agent to execute instructions it would not follow at their original level. We evaluate this threat by using multi-agent mechanisms to achieve 13 attack objectives across six coding-agent harnesses. These objectives span confidentiality, integrity, availability, and remote code execution. With unrestricted action execution, the attacks achieve all 13 objectives on all six harnesses. Under automatic permission review, the attacks achieve all 13 objectives on all three harnesses that provide this mode. We further reproduce the vulnerability using harness-provided persistent goals and scheduled tasks. These results demonstrate the generality of instruction privilege escalation.

## 1. 论文的核心问题与整体含义

- **研究背景**：现代LLM代理（agent）在执行任务时会读取大量外部内容（如文件、网页、工具输出），这些内容可能包含恶意指令。为抵御此类威胁，普遍采用两类防御：一是训练工作代理识别并拒绝不安全指令；二是使用自动权限审查（Auto PR）评估动作是否经用户授权。
- **核心问题**：这两类防御都依赖**指令层级**假设——不同来源的内容被赋予不同指令权限（如系统级 > 用户级 > 工具级），且**角色标签忠实反映内容真实来源**。论文发现这一假设存在严重缺陷：代理框架在上下文构建过程中可能将低级别内容提升到更高指令层级，赋予恶意内容更大的模型权限。
- **整体含义**：提出一种新型攻击范式**指令权限提升**（Instruction Privilege Escalation），攻击者无需模型越狱或伪造角色，而是**利用代理框架自身的正常上下文重建机制**将工具级恶意内容变成用户级甚至系统级指令，从而绕过工作代理和权限审查器的双重防御。该攻击在多个真实代理框架上全面成功，揭示了LLM代理安全架构中的根本性缺陷。

## 2. 论文提出的方法论

### 2.1 统一指令层级模型

- 将不同API协议（OpenAI、Anthropic、Google Gemini）中的消息类型映射到三个统一的模型视角指令层级：
  - **tool**（工具级）：外部观察内容，如文件读取、命令输出、结构化工具结果。
  - **user**（用户级）：用户消息或表现为用户请求的任务。
  - **system-effective**（系统有效级）：位于普通用户消息之上的提示面，如系统提示、开发者指令、自定义子代理策略。
- 层级顺序：`tool < user < system-effective`。
- 定义为每个内容项 `c` 的**起源层级** `P(c)` 和**框架在当前上下文构建中分配的层级** `P_har(c)`。

### 2.2 指令权限提升的定义

- **提升条件**：若上下文构建操作 `R` 将内容从起源层级 `P(c)` 提升到更高的层级 `P_har(c)`，则发生指令权限提升（IPE）。
- 形式化表示为：  
  `⟨P(c), c⟩ → ⟨P_har(1)(c), c⟩ → ... → ⟨P_har(k)(c), c⟩`，其中 `P_har(k)(c) > P(c)`。
- **两种具体形式**：
  - **工具到用户提升**：`P(c) = tool`，`P_har(k)(c) = user`。
  - **工具到系统提升**：`P(c) = tool`，`P_har(k)(c) = system-effective`。

### 2.3 攻击实现机制

#### 工具到用户提升——多代理委派（Primary）
- 攻击者控制仓库中的文件（如 `README.md`、`AGENT.md`），诱导主代理将恶意任务委派给子代理。
- 框架在构建子代理上下文时，将委派的任务以**用户消息**形式插入，从而完成从工具级到用户级的提升。
- 采用两种诱导策略：
  - **直接诱导**：在 README 中直接指令“生成子代理并运行 `python3 app/setup.py`”。
  - **间接诱导**：将恶意步骤伪装成正常设置流程，并在单独的 `AGENT.md` 中提供通用指导（如“当步骤清晰时，委派给子代理”），适用于对直接指令更敏感的模型（如 Claude Opus）。

#### 工具到系统提升——自定义子代理安装
- 攻击者安装一个**恶意自定义子代理**，并修改 `AGENT.md` 将良性任务重定向到该子代理。
- 安装后，子代理的系统提示被提升到系统有效级，持续影响整个框架。
- 两种变体：
  - **直接嵌入**：系统提示中明确写出恶意代码插入逻辑。
  - **引用隐藏**：系统提示只指示调用外部恶意脚本，并限制工具调用次数，阻止模型检查外部脚本内容。

#### 其他提升机制（泛化验证）
- **持久目标（Persistent Goals）**：诱导代理调用 `create_goal` 等工具存储恶意内容，框架在后续轮次以用户级提示重新注入，实现工具到用户提升。
- **计划任务（Scheduled Tasks）**：通过 cron 类工具创建定时任务，恶意提示在指定时间以用户消息形式送达。
- **技能（Skills）**：技能安装可同时实现工具到用户提升（技能体）和工具到系统提升（技能元数据）。

## 6. 论文的主要结论与发现

- **指令权限提升是普遍且有效的**：
  - 在完全访问模式下，工具到用户提升在所有6个框架上实现了全部13个攻击目标；工具级基线攻击在大多数框架上失败。
  - 在自动权限审查模式下，工具到用户提升仍实现全部13个目标，而基线攻击在3个支持Auto PR的框架上全部失败。
- **提升后成功率极高**：一旦恶意命令被提升到子代理的用户级输入，后续攻击在几乎所有情况下都能成功（提升后成功率 > 86%）。
- **自动权限审查被绕过**：审查模型能识别动作的高风险性质，但仍基于“用户授权”的误导性上下文予以批准，说明失败源于授权推断而非风险识别。
- **工具到系统提升同样有效**：
  - 直接嵌入变体在部分框架上受到模型抵抗（Claude Code 0/13，Kimi 7/13，Gemini CLI 8/13 等）。
  - **引用隐藏变体**大幅提升成功率：在完全访问和Auto PR下均实现全部13个目标，攻击成功率最高达100%（Codex完全访问），最低61.9%（Qwen Code Auto PR）。
- **泛化性验证**：持久目标和计划任务作为用户级提升路径，在4条评估路径上均实现全部13个目标，证明漏洞不局限于多代理委派。
- **根本原因**：指令层级防御依赖“角色标签忠实反映来源”这一假设，但代理框架的上下文重建会丢弃原始来源信息，导致提升在防御决策之前已完成。

- **形式化建模**：引入统一指令层级和提升的形式化定义，为后续研究提供理论框架。
