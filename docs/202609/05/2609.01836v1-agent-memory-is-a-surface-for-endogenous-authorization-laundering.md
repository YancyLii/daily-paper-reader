## 摘要
长时间运行的 LLM 智能体依赖持久记忆在交互之间携带状态，包括权限、限制和撤销。当记忆错误呈现这种不断演变的授权状态时，智能体自身的记录可能授予底层历史从未允许的权限，导致在没有任何外部攻击的情况下出现行为失准。我们将这种失效称为内生授权洗白，即写入记忆的虚假权限因其来源被清洗掉而导致未授权行为。我们随后引入 EAL-Bench，用于衡量持久记忆在多大程度上准确保存不断演变的授权状态，以及错误是否会传播到下游未授权行为。我们在采购、网络安全和金融领域评估了五个 LLM 作为记忆写入者、两个作为执行者。我们发现，在增量记忆更新下，写入者为多达 50.2% 的未授权请求制造了虚假权限；一旦虚假权限存在，执行者在 98.6% 的试验中据此采取行动。两种防护措施——要求存储的权限有有效源事件作为依据，以及通过有界事件溯源跟踪权限变化——大幅减少了洗白，但两者也会拒绝更多合法操作，暴露出安全性与实用性之间的权衡。因此，持久记忆不仅是性能组件，而是 LLM 智能体有效授权策略的一部分。

## Abstract
Long-running LLM agents rely on persistent memory to carry state across interactions, including permissions, restrictions, and revocations. When memory misrepresents this evolving authorization state, the agent's own records can grant authority that the underlying history never permitted, resulting in misaligned behavior without any external attacks.   We term this failure endogenous authorization laundering, where spurious permissions written into memory lead to unauthorized actions as their provenance is washed away. We then introduce EAL-Bench, which measures how accurately persistent memory preserves evolving authorization state and whether errors propagate to downstream unauthorized actions.   We evaluate five LLMs as memory writers and two as executors across procurement, cybersecurity, and finance. We find that under incremental memory updates, writers create false authority for up to 50.2% of unauthorized requests; once false authority is present, executors act on it in 98.6% of trials. Two safeguards, requiring stored permissions to be backed by valid source events, and tracking permission changes through bounded event sourcing, substantially reduce laundering, but both also reject more legitimate actions, exposing a safety-utility tradeoff. Persistent memory is therefore not merely a performance component, but a part of an LLM agent's effective authorization policy.

## 2. 论文提出的方法论

- **问题形式化**：
  - 每个实例包含有序组织历史 \(H = (B_1, \dots, B_T)\)，由多个会话块组成。
  - 确定性重放函数 \(R\) 将截至第 \(t\) 块的权威事件映射到规范授权状态 \(S_t = R(B_1, \dots, B_t)\)。
  - 域特定谓词 \(A(S_t, x)\) 判断动作 \(x\) 是否被授权。
  - 记忆写入者 \(W\) 将历史转换为持久工件 \(M_T\)；执行者 \(E\) 仅接收 \(M_T\) 和请求 \(q\)，无法访问原始历史。
  - 对于类型化记忆，存在确定性谓词 \(A_M(M_T, x)\) 判断动作在记忆中是否“看起来被授权”。
  - **形成（Formation）**：\(F(M_T, a_q) = \mathbf{1}\{A(S_T, a_q) = 0 \land A_M(M_T, a_q) = 1\}\)。
  - **传播（Propagation）**：\(G(E, M_T, q) = \mathbf{1}\{E(M_T, q) = a_q\}\)。
  - 端到端洗白事件为 \(F \land G\)，发生率为 \(P(F=1) \cdot P(G=1 \mid F=1)\)。

- **基准设计（EAL-Bench）**：
  - 每个案例包含一段多会话组织历史（嵌入政策变化、过期声明、非权威建议等）和一个后续结构化请求。
  - 隐藏的确定性账本重放有效授权事件，建立真实授权状态。请求与账本共同构成一对“匹配请求”：仅在一个授权相关字段上不同，一个授权、一个未授权。
  - 记忆构造使用 LangMem 的 profile 管理，每个链一个持久 profile。支持两种表示（自由文本、类型化 JSON）和两种更新策略（一次性、增量）。
  - 类型化记忆有严格 schema 验证，允许直接计算 \(A_M\)；自由文本记忆则无法确定性测量形成，只能通过下游行为和记忆干预推断因果。
  - 记忆容量与修复策略受控：容量设置为校准语料库中最大忠实负载的两倍，每次写入最多一次验证知情修复，失败则保留旧 profile。

- **隔离控制与干预**：
  - 执行者必须通过“忠实记忆”控制：100% 授权使用、0% 未授权提交。
  - **精确状态修复**：对自然生成且表现出形成的类型化记忆，在观察执行者行为前，用 oracle 精确状态替换该记忆，重放相同请求，比较结果。
  - **压力干预**：仅添加领域特定的紧迫性陈述，不增加授权信息，用于验证下游执行者是否对压力敏感。
  - **缓解措施**：
    - **黄金引用源权限门**：只保留所有引用源有效、可见且来自授权主体的类型化授权记录。
    - **有界事件溯源架构**：写入者只提取每个新块的变化，外部系统将事件追加到不可变日志，由确定性 reducer 构造当前紧凑状态。

- **增量更新产生最多授权失败**：增量类型化记忆是各领域中最不安全的配置，金融领域未授权提交率达到 51.0%；一次性写入者表现明显更好。

- **精确状态修复消除失败**：将错误记忆替换为 oracle 精确状态后，所有领域的未授权执行率降至 0%，证明瓶颈在记忆形成，而非执行器对齐。
