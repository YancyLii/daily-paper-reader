## 摘要
在 AI 智能体的上下文中，安全规则和情景日志会竞争相同的 token。当预算溢出时，两者会以相同速率被总结；然而只有规则需要保留确切措辞才能保持可执行性。在 20 个生产环境智能体配置上，Claude Code 在 Sonnet 4.6 上的 /compact 提示在一轮压缩后保留 53% 的安全规则，五轮后保留 10%。我们将这一现象命名为压缩悬崖（Compaction Cliff）。我们提出知识分流（Knowledge Triage）框架来解决该问题：该框架按类型对智能体知识库中的每一行进行分类，并将每种类型路由至其自身的保留策略。三个确定性算子在三种上下文管理操作中实现这一分流：TypeCompact 在按类型保真度下原地重写条目；TypeDecompose 将过大而无法安全压缩的主题进行分区，并在各分区间复制范围内安全规则；TypeRetrieve 从外部存储获取条目，并将范围内规则固定在相关性排序之前。在五个公开语料库上，TypeCompact 在每个压缩比下比最强的单次 LLM 压缩器多保留 2–4 倍的安全规则，五轮后的召回率为 96%。TypeDecompose 实现 0% 的局部性违规，而均匀分区下为 93%。TypeRetrieve 达到 100% 的 recall@50，而最佳单次 LLM 检索器为 73%。在三个下游行为基准上，我们在医疗合规性方面优于生产环境 Sonnet 压缩器（保留率配对 McNemar 检验 p < 10⁻⁸，N = 200），在零售任务通过率方面优于完整策略基线和分层基线（p < 0.01，N = 115），在航空领域优于分层压缩（p = 0.024）。我们发布了 AgentArtifactCorpus（来自 54,628 个公共 GitHub 仓库的 396,934 个智能体配置）、分类器和参考实现。

## Abstract
A safety rule and an episodic log compete for the same tokens in an AI agent's context. When the budget overflows, both are summarized at the same rate; only the rule needs exact wording to remain enforceable. On 20 production agent configurations, Claude Code's /compact prompt on Sonnet 4.6 preserves 53\% of safety rules after one compaction round and 10\% after five. We name this the Compaction Cliff. We address it with Knowledge Triage, a framework that classifies each line of an agent's knowledge base by type and routes each type through its own retention policy. Three deterministic operators implement this triage across the three context-management operations: TypeCompact rewrites items in place under per-type fidelity, TypeDecompose partitions a topic too large to compact safely, replicating in-scope safety rules across partitions, and TypeRetrieve fetches items from external storage with in-scope rules pinned ahead of relevance. On five public corpora, TypeCompact preserves 2--4$\times$ more safety rules than the strongest single-shot LLM compactor at every ratio, with 96\% recall over five rounds. TypeDecompose reaches 0\% locality violations against 93\% under uniform partitioning. TypeRetrieve reaches 100\% recall@50 against 73\% for the best single-shot LLM retriever. On three downstream behavioral benchmarks, we outperform the production Sonnet compactor on medical compliance (paired McNemar $p < 10^{-8}$ on preservation, $N = 200$), the full-policy and hierarchical baselines on retail task pass rate ($p < 0.01$, $N = 115$), and the hierarchical compaction on the airline domain ($p = 0.024$). We release AgentArtifactCorpus (396{,}934 agent configurations from 54{,}628 public GitHub repositories), the classifier, and the reference implementation.

## 1. 论文的核心问题与整体含义

- **核心问题**：在长期运行的 AI 智能体中，安全规则与情景日志会竞争同一有限的上下文 token 预算。当预算溢出时，生产环境中的压缩策略往往对两者一视同仁、以相同速率进行摘要或截断；但安全规则需要保留**精确措辞**才能继续可执行，一旦被改写或丢弃，就可能导致严重安全后果。
- **“压缩悬崖”现象**：在 20 个生产环境智能体配置上，Claude Code 的 `/compact` 提示（Sonnet 4.6）在一轮压缩后仅保留 **53%** 的安全规则，五轮后仅保留 **10%**。作者将这一快速退化称为 **Compaction Cliff**。
- **整体含义**：现有上下文管理方法（压缩、分解、检索）被独立研究，且普遍是“类型盲”的：它们不根据知识条目的安全角色区分保留策略。论文提出 **Knowledge Triage（知识分流）**，将每个知识条目按类型分类，并为每种类型设计专门的保留策略，从而在预算压力下优先保护安全关键约束。

## 2. 论文提出的方法论

### 2.1 类型化知识模型

- 定义五类知识条目，覆盖 97% 的真实智能体配置内容：

| 类型 | 含义 | 失真容忍度 |
|---|---|---|
| **Constraint (C)** | 约束智能体行为的规则，违反会导致安全失败 | 零容忍，任何丢失都不安全 |
| **Procedural (P)** | 任务的分步指令 | 仅允许在执行行为不变时重写 |
| **Belief (B)** | 被当作真的事实断言 | 受语义距离限制 |
| **Preference (F)** | 软性指南 | 可摘要或合并 |
| **Episodic (E)** | 过去事件或观察 | 可自由丢弃或摘要 |

- 形式化知识库为 \(K = (I, \tau, T, \pi, \sigma)\)：
  - \(I\) 为条目集合；
  - \(\tau\) 为类型分配函数；
  - \(T\) 为主题树；
  - \(\pi\) 将条目映射到叶子主题；
  - \(\sigma\) 给出每个约束的作用域。
- 每种类型有独立失真度量 \(d_t\)：约束为二元失真；程序要求行为保持等价；信念/偏好使用嵌入距离；情景使用 ROUGE-L 距离。

### 2.2 类型分类器 \(\tau\)

- 分类器是框架中唯一的学习组件，所有安全保证都依赖它。
- **SafetyMargin（默认）**：用反事实安全边际估计，判断删除某条目是否会让某个动作变得不安全。公式为：
  \[
  \text{margin}(i) = \max_{a \in A} \left( P(\text{unsafe} \mid a, K \setminus \{i\}) - P(\text{unsafe} \mid a, K) \right)
  \]
  分数大于 0.5 时标记为 Constraint。
- 替代方案：多阶段选择性级联（正则 → 编码器 → LLM → 不确定则作为硬约束）、单次 LLM 分类、纯表面启发式（正则、编码器、蒸馏 MiniLM）。
- 还引入**来源权威权重** \(w_a\)，对不同来源（系统、开发者、用户、工具、检索）的风险进行加权。

### 2.3 三个确定性算子

- **TypeCompact（压缩）**
  - 输入：知识库 \(K\)、预算 \(B\)、分类器、验证器、权威权重。
  - 将条目路由到三条保真通道：
    - 硬通道：约束和程序，完整保留；
    - 软通道：信念/偏好可压缩；
    - 情景占位通道：用占位符代替。
  - 分配剩余预算，并用确定性验证器检查每个约束的关键形式（否定 + 对象短语）是否仍出现在输出中；若缺失则恢复或返回 `Unsafe`。
  - 复杂度：\(O(|K|)\) 分类器调用，\(O(|H|\log |H|)\) 分配，\(O(|I_C|)\) 验证。

- **TypeDecompose（分解）**
  - 将过大主题划分为若干子知识库，每个子库都满足分区预算。
  - 安全要求：**约束局部性**——若某个分区包含被约束作用域覆盖的条目，则该分区必须同时包含该约束。
  - 算法：先按主题分组/分块，再对每个约束复制到所有与其作用域相交的分区。
  - 复杂度：\(O(|K|)\) 分组，\(O(|I_C|m)\) 复制，受全局作用域密度限制。

- **TypeRetrieve（检索）**
  - 输入：语料 \(K\)、查询 \(q\)、预算 \(k\)、相似度评分器、作用域判定。
  - 先找出所有范围内约束 \(C_q\)，将其固定在结果集中；剩余预算再按相似度填充其他条目。
  - 安全要求：**优先级**——只要约束在查询作用域内，就必须出现在结果中，即使相似度分数不高。
  - 复杂度：固定约束不增加渐近开销。
  - 该方法使用 0 个 LLM token，而单次 LLM 检索器每个查询需要数千 token。

- **组合**：三者构成一个上下文管理循环：先尝试压缩；当预算低于最小安全预算 \(B_{\min}\) 时，回退到分解，将部分内容推到外部存储，再由 TypeRetrieve 按需取回。

## 6. 论文的主要结论与发现

- **压缩悬崖是结构性的**：类型盲保留在多个 LLM 家族和结构基线中均出现相同退化形态；单轮最高保留 53%，五轮后仅 10%。
- **五类型模型覆盖 97% 的真实智能体配置内容**，约束类型在跨域迁移中 F1 保持在 0.88。
- **TypeCompact**：
  - 在 50%/25%/10% 压缩比下，约束保留率分别为 **1.00 / 0.95 / 0.80**；
  - 五轮压缩后约束召回稳定在 **96%**；
  - 比最强单次 LLM 压缩器在每个压缩比下高 **2–4 倍**。
  - 它牺牲信念/偏好保真度（约 0.50），换取约束和程序的完整保留。
- **TypeDecompose**：
  - 实现 **0% 局部性违规**，而最强主题对齐基线为 13% 平均违规、40% 配置至少一次违规，其他基线高达 32%–93%；
  - 平均复制开销 14.5%，但极端情况可达 219%。
- **TypeRetrieve**：
  - 达到 **100% recall@50**，而最佳单次 LLM 检索器仅为 73%；
  - 使用 0 个 LLM token/查询。
- **下游行为**：
  - SafetyMed：TypeCompact 通过率 97.0%，保留率 95.5%，显著优于生产 Sonnet 压缩器（保留率 \(p = 3.7 \times 10^{-9}\)，通过率 \(p = 0.022\)）；
  - \(\tau\)-bench retail：TypeCompact 平均通过率 37.7%，显著优于完整策略（28.6%，\(p = 0.003\)）和层级截断（29.2%，\(p = 0.005\)）；
  - \(\tau\)-bench airline：TypeCompact 26.5%，显著优于层级截断 15.4%（\(p = 0.024\)），与完整策略统计上持平。
- **分类器成本与措辞**：
  - SafetyMargin 在陈述性安全文本上大幅提升召回（从 0.62 到 0.90），而语法分类器在该形式上会下降 38–48 个百分点；
  - 陈述性措辞在临床（49.8%）、法律（61.1%）安全文本中占主导。
- **总体设计原则**：在将压缩交给前沿 LLM 之前，应先按安全角色分类条目，并原样保留安全关键类。

## 7. 优点

- **问题定位清晰且重要**：将安全规则与情景日志的竞争明确化，提出“压缩悬崖”，并用大规模生产配置复现。
- **类型化知识模型**：五类型划分既覆盖广（97%）又具备可操作性，为不同失真容忍度提供理论依据。
- **确定性算子设计**：三个算子具有明确的、可证明的安全要求（约束保留、局部性、优先级），且均有对应失败模式分析。
- **非 LLM 的确定性保障**：TypeCompact、TypeDecompose、TypeRetrieve 在推理阶段不使用 LLM token，固定约束通过数据库查找完成，成本极低。
- **验证器与 Unsafe 升级机制**：压缩后验证约束是否存活，无法满足预算时显式返回 Unsafe，避免静默丢弃安全规则。
- **SafetyMargin 反事实分类**：能识别陈述性安全规则，弥补语法分类器的盲点。
- **实验设计全面且统计严谨**：
  - 多个语料、多个领域、多个基线和消融；
  - 人类标注和 Cohen’s \(\kappa\)；
  - 配对 McNemar 检验；
  - 资产开源（AgentArtifactCorpus、分类器、参考实现）。
- **下游行为验证**：不只是表面保留指标，还在医疗、零售、航空等行为任务上证明安全收益。

## 8. 不足与局限

- **算力说明缺失**：论文未报告 GPU

- **算力说明缺失**：论文未报告 GPU 型号、数量、训练时长或总推理成本，只提供了单次调用延迟和 token 数，难以完整评估资源开销。
- **分类器偏差风险**：SafetyMargin 等分类器依赖 LLM 自洽性判断或 LLM 标注，可能引入系统性上界偏差；作者通过人类标注和对抗性改写集缓解，但未完全消除。
- **TypeCompact 的保真度代价**：TypeCompact 牺牲信念/偏好保真度（约 0.50）以保护约束和程序，可能影响依赖事实性知识的智能体性能；论文未充分量化这一代价对下游任务成功率的间接影响。
- **作用域标注依赖**：TypeDecompose 和 TypeRetrieve 的局部性/优先级保证都依赖约束作用域标注的质量；在作用域标注不完整或错误时，安全保证可能退化，但论文未系统评估作用域错误的影响。
- **数据集和任务规模有限**：SafetyMed 仅 200 个场景、\(\tau\)-bench retail/airline 任务数量较少，行为评估的统计功效可能不足以发现小但重要的差异；LongMemEval 只用于类型学验证，未用于压缩/检索长期测试。
- **MaRS 基线不完全等同**：由于 MaRS 无公开实现，作者使用自实现 MaRS-FL，可能无法完全反映原始 MaRS 的性能；这使部分比较的公平性存疑。
- **未覆盖所有生产压缩器**：虽然对比了多种 LLM 压缩器，但未包含所有商业系统（如其他云厂商的智能体压缩策略），结论的普适性仍有一定局限。
- **类型分类器的跨域泛化**：约束分类器在跨域迁移中 F1 为 0.88，但在低资源或未见领域是否稳定仍需进一步验证；论文未提供分类器在非英语或非结构化安全文本上的测试。
