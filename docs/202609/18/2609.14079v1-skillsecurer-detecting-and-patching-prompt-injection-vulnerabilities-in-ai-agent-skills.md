## 摘要
智能体技能通过可复用的指令、脚本和配置扩展 AI 智能体，但也容易受到新的攻击，从而影响智能体的决策和行动。为应对这些风险，我们提出 SkillSecurer，一个完全智能体化的框架，用于生成、检测、定位和修复智能体技能中的安全风险。其红方智能体在九种威胁类型中生成与上下文兼容的注入，同时记录确切的修改；其蓝方智能体分析完整技能包，产生有依据的证据并提出补丁。对于受控实例，验证器将发现与补丁同记录的注入进行比较，从而实现注入级评估。我们通过选择最佳后端 LLM、将其与竞争对手比较，并人工交叉验证每个评估阶段，对 SkillSecurer 进行了全面评估。凭借表现最佳的后端，SkillSecurer 是唯一实现 100% 注入检测率的扫描器。接下来，我们分析了 skills.sh 上的热门技能，在所检查的技能中发现超过 17% 存在潜在漏洞。测试其中一些技能时，我们触发了实际事件，表明运行未经验证的技能存在风险。我们的结果表明，上下文感知的 LLM 分析能够提供可靠的注入定位和可操作的修复建议，而不仅仅是技能级别的标记。

## Abstract
Agent skills extend AI agents with reusable instructions, scripts, and configuration, but are also open to new attacks to influence an agent's decisions and actions. To address these risks, we present SkillSecurer, a fully agentic framework for generating, detecting, localising, and remediating security risks in agent skills. Its red agent generates context-compatible injections across nine threat types while recording the exact modification; its blue agent analyses complete skill packages, produces grounded evidence, and proposes patches. For controlled instances, a verifier compares findings and patches with the recorded injection, enabling injection-level evaluation.   We thoroughly evaluate SkillSecurer by selecting the best backend LLM, comparing it with competitors, and manually cross-validating each evaluation stage. With its best performing backend, SkillSecurer is the only scanner to achieve a 100% injection detection rate. Next, we analyse popular skills from skills.sh, finding latent vulnerabilities in more than 17% of the skills examined. Testing some of those skills, we trigger actual incidents, showing the risks of running unverified skills. Our results show that context-aware LLM analysis can provide reliable injection localisation and actionable remediation beyond skill-level flagging alone.

# SkillSecurer 论文总结

## 1. 核心问题与整体含义

- **研究背景**：AI 智能体（如 Codex、Claude）越来越多地直接执行用户任务，而“技能”（skills）作为可复用包，包含自然语言指令、脚本、配置、依赖等，成为扩展智能体能力的重要机制。技能通过 skills.sh、ClawHub.ai、OpenAI Codex skills catalog 等公共仓库分发，热门技能下载量可达数百万次。
- **安全问题**：技能构成新的攻击面。恶意或脆弱技能可通过指令操纵智能体、执行不安全代码、访问文件或凭据、调用外部服务、窃取或销毁数据。已有研究（Skill-Inject、SkillJect、POISE 等）证明技能可被滥用。
- **现有方案不足**：
  - 基准测试多手工策划或使用固定模板，缺少精确注入位置标注，难以验证检测器是否正确定位；
  - 现有扫描器多基于静态规则、专用检测器或漏洞特定提示，输出通常是二分类或粗粒度风险标签，缺乏定位和修复能力；
  - 缺乏统一的注入级（injection-level）评估框架。
- **本文目标**：提出 **SkillSecurer**，首个完全智能体化的端到端框架，用于生成、检测、定位和修复智能体技能中的安全风险，并建立基于精确 ground truth 的注入级评估。

## 2. 方法论

SkillSecurer 由三个核心组件组成：

- **BLUE PATCHER（蓝方检测与修复）**：
  - 接收待测技能 SUT，输出结构化发现报告 D 和可选补丁 P。
  - 每个发现记录：安全类别、严重性、解释、引用证据 span 及其在技能中的位置。
  - 证据 span 必须能映射到 SUT 中的实际内容，确保定位有依据。
  - 若发现非空，第二遍生成最小修改的补丁；若 D 为空，则 P=SUT。
  - 形式化：\(B_{\text{detect}}(SUT)=D\)，\(B_{\text{patch}}(SUT,D)=P\)。
  - 只处理静态快照，不执行不可信代码；不接收良性对照或注入说明，保证检测独立性。

- **RED INJECTOR（红方注入生成，仅用于评估）**：
  - 给定良性技能 S 和威胁类型 τ，生成修改后的技能 S′ 和注入规格 Δ。
  - 覆盖九类威胁（如任意脚本执行、凭据暴露、数据外泄、GuardFall、间接注入、权限提升、提示劫持、资源耗尽、供应链攻击）。
  - 要求注入与宿主技能上下文兼容，并记录确切修改内容。

- **VERIFIER（验证器，仅用于受控评估）**：
  - 比较 BLUE PATCHER 的发现与记录的注入。
  - 若 D 为空，直接记为漏检。
  - 否则计算每个发现证据 \(q_i\) 与注入文本 δ 的最大归一化序列相似度 \(r = \max_i \, \text{sim}(\text{norm}(\delta), \text{norm}(q_i))\)。
  - 若 \(r\ge 0.8\)，确认定位；否则交给独立 LLM 法官判断是否命中注入以及补丁是否移除/中和该行为。
  - 输出定位结果 L 和补丁移除结果 R，用于计算 **注入检测率 IDR**。

- **实现**：基于 LangGraph 的智能体工作流，支持通过 OpenRouter 调用多种 LLM；提供 Web 界面浏览发现、证据、补丁和评估结果。

## 6. 主要结论与发现

- **最佳后端**：Claude Sonnet 5 在 Dsi 上实现 100% IDR 和 100% GDR，排名第一；DeepSeek V4 Pro 为低成本高效替代（约为 Sonnet 成本 1/6，IDR 96.3%）。
- **静态扫描器效果差**：在 Dred/Dsi 上，静态配置的 Skill Scanner 仅 7.2%/0.6% GDR，证明签名规则无法应对上下文相关和工作流依赖的攻击。
- **SkillSecurer 优势**：在 345 个受控实例中，Sonnet 后端实现 100% IDR；在 DeepSeek 后端下仍保持最高 IDR（91.7% Dred，97.0% Dsi），优于所有对比扫描器。
- **良性技能中的潜在漏洞**：130 个“可能良性”技能中，34.6% 被标记，其中 85.1% 获人工确认，多为身份/特权滥用、意外代码执行、工具滥用等潜在漏洞。
- **在野风险**：在 954 个热门技能中，SkillSecurer 标记 17.6% 存在潜在安全问题；人工确认 84/100 抽样发现；漏洞分布涵盖意外代码执行、目标劫持、身份特权滥用等。
- **真实利用**：5 个技能中 13/30 次模型-技能组合成功触发攻击，证明部分漏洞确实可利用；补丁后降低到 3/30，但并非完全消除——部分模型忽略补丁中的警告或预防性指令，或攻击路径不经过补丁位置。

## 7. 优点

- **首个端到端智能体框架**：覆盖注入生成、检测、定位、修复和注入级评估，填补了技能安全领域从粗粒度标记到精确修复的空白。
- **注入级 ground truth 与 IDR 指标**：比传统 GDR 更严格，能区分“报告了无关发现”和“正确定位注入”，避免了误报得分。
- **上下文感知分析设计**：不依赖固定漏洞特定检测器，而是让 LLM 理解技能完整工作流和指令含义，因而对多样化、上下文相关攻击更鲁棒。
- **系统性对比与人工验证**：与多种现有扫描器在统一协议下比较，并通过三人评审人工验证 LLM 报告，增强了可信度。
- **真实世界验证**：不仅在基准上表现好，还在真实热门技能中发现并实际利用漏洞，证明了框架的实用价值。
- **成本与可复现性**：开源实现、公开基准输入和结果，支持多种 LLM 后端，便于社区复现。

## 8. 不足与局限

- **算力与资源细节缺失**：论文没有给出 GPU 型号、数量或本地推理资源，仅提供 API 成本和 token 统计，难以评估自托管部署的算力需求。
- **静态验证局限**：VERIFIER 只能静态判断注入是否被识别和补丁是否移除，无法保证补丁保留所有合法功能；功能保持需要任务级运行时测试。
- **补丁可靠性不足**：真实利用实验中，部分模型会忽略补丁中的警告或预防性指令，或漏洞触发路径不经过补丁位置，暴露出“修补指令不一定被智能体遵循”的问题。
- **数据偏差风险**：
  - \(D_{red}\) 由 DeepSeek V4 Pro 生成，虽然检测时用不同模型，但仍可能存在生成器特定的语言模式偏差；

  - 在野人工审查仅抽样 100 个发现，可能低估误报率或漏掉其他类别。
- **样本规模有限**：真实利用只覆盖 5 个技能，无法全面评估补丁在多样化场景下的有效性。
- **LLM 依赖与版本漂移**：性能高度依赖后端 LLM 能力和版本；不同模型表现差异大，部分模型（如 Claude Fable 5）因安全护栏拒绝处理任务，影响可复现性。
- **威胁模型假设较强**：假设技能已被选中并加载，不评估恶意技能被强制选择的场景，也未建模安装后利用、沙箱逃逸或远程内容动态变化。
