## 摘要
网络化大语言模型（LLM）智能体从电子邮件、云存储、日历、交易平台和 Web 服务检索信息，以完成产生持久外部效应的多步任务。合法执行所需的相同内容也可能包含间接提示注入，从而重定向工具使用、篡改敏感参数或破坏任务完成。现有防御主要约束不可信内容或单个工具调用，使得用户意图、运行时证据、实际效果和任务完成之间关联不足。我们提出 TraceGrant，一个通过显式合约治理网络化 LLM 智能体任务-效果生命周期的安全框架。在执行之前，TraceGrant 从可信用户请求建立任务-效果边界。在执行期间，被采纳的证据只能实例化合约已确立的权限。在执行之后，根据实际工具结果验证任务完成情况。在固定基准设置下，针对 949 个 AgentDojo 和 400 个 Agent Security Bench 攻击案例，TraceGrant 未记录任何攻击成功，同时在攻击率分别为 77.32% 和 83.00% 时保留了实用性。我们进一步通过白盒防御感知攻击、合约质量分析、阶段消融、针对性压力测试和运行时开销测量对 TraceGrant 进行评估。结果表明，TraceGrant 提供了一个统一的治理层，将可信用户意图、运行时证据、具体工具执行和经过验证的任务完成关联起来。

## Abstract
Networked large language model (LLM) agents retrieve information from email, cloud storage, calendars, transaction platforms, and Web services to complete multistep tasks that produce persistent external effects. The same content needed for legitimate execution may also contain indirect prompt injections that redirect tool use, alter sensitive arguments, or disrupt task completion. Existing defenses mainly constrain untrusted content or individual tool calls, leaving user intent, runtime evidence, realized effects, and task completion insufficiently connected. We present TraceGrant, a security framework that governs the task-effect lifecycle of networked LLM agents through an explicit Contract. Before execution, TraceGrant establishes a task-effect boundary from the trusted user request. During execution, admitted evidence can instantiate only authority already established by the Contract. After execution, task completion is verified against actual tool results. Across 949 AgentDojo and 400 Agent Security Bench attack cases under fixed benchmark settings, TraceGrant recorded no attack successes while retaining utility under attack rates of 77.32% and 83.00%, respectively. We further evaluate TraceGrant through white-box defense-aware attacks, Contract quality analysis, stage ablations, targeted stress tests, and runtime overhead measurements. The results show that TraceGrant provides a unified governance layer that connects trusted user intent, runtime evidence, concrete tool execution, and verified task completion.

## 2. 论文提出的方法论

- **核心思想**：任务-效果生命周期治理。将智能体安全建模为权限建立、运行时参数实例化、外部效应执行、任务完成验证四个阶段，并通过显式合约统一约束。
- **POEC 合约结构**：
  - 在执行前，语义合约编译器从可信用户请求 \( u \)、已冻结工具模式集 \( \Sigma \)、能力画像 \( P \) 和参数角色目录 \( R_\Sigma \) 生成候选合约：
    \[
    \tilde{C} = F_{sem}(u,\Sigma,P,R_\Sigma)=\langle MAY, MUST, BIND, VERIFY \rangle
    \]
  - **MAY（Permission）**：定义允许的工具、操作、目标范围、参数约束和调用预算。
  - **MUST（Obligation）**：组织证据获取、外部效应和输出要求为依赖感知的义务图。
  - **BIND（Evidence）**：为每个权威参数定义允许的来源、期望类型、证据约束和派生规则。
  - **VERIFY（Completion）**：定义工具、参数、执行状态和可观察后置条件的完成要求。
- **静态合约分析**：候选合约经确定性规范化和静态验证（WellFormed、ControlSafe、FlowSafe、ScopeSafe、VerifySafe）后才能成为可执行权限，避免无效或越权合约进入运行。
- **运行时证据约束授权**：
  - 查询结果先作为普通运行时观察进入上下文，只有满足活跃证据义务、来源匹配、查询匹配、类型匹配和完整性匹配时，才通过证据准入写入 Obligation Ledger。
  - 智能体提出候选效应后，TraceGrant 将其与活跃义务匹配，并为每个权威参数构造类型化证明，证明其来源和可采纳性。
  - PDP 进行状态化决策：`ALLOW`（在 MAY 内、推进活跃义务、证明有效、预算内）、`PROOF-GAP`（缺少证据，提示查询或修正）、`DENY`（越权、越范围、预算耗尽）或 `STEP UP AUTH`（需额外用户认证）。
  - `ALLOW` 后生成一次性 Effect Certificate，将合约、活跃义务、规范参数、参数证明和预算状态绑定到单次执行；PEP 仅当请求工具和规范参数与有效证书完全匹配时才分派原生调用。
- **执行后验证与任务关闭**：
  - 原生调用返回后，Effect Receipt 联合检查实际工具和参数是否与证书匹配、原生执行是否成功、后置条件是否满足、参数证明是否仍然有效。
  - 仅有效 Effect Receipt 才能将对应义务从 ACTIVE 置为 VERIFIED，并解锁后续义务。
  - Final-Answer Gate 要求所有硬义务处于 VERIFIED 或 WAIVED 状态才接受最终成功声明，防止工具失败、参数漂移、未满足后置条件或部分完成被错误宣告为任务完成。
- **形式化安全保证**：在语义合约健全、证据字段语义真实、PEP 完全中介、证书与账本原子操作、受保护 runner 精确执行等条件下，所有实际效应均保持在用户授权边界 \( A(u) \) 内。

## 6. 主要结论与发现

- **安全效果**：在固定基准设置下，TraceGrant 在 AgentDojo 949 个攻击案例和 ASB 400 个攻击案例上均实现 0% 攻击成功率，同时保持攻击下实用性 77.32%（AgentDojo）和 83.00%（ASB）。
- **跨模型稳定性**：四种任务执行模型下均未观察到攻击成功，说明结构化授权层不依赖特定模型，但任务实用性随模型和环境变化。
- **阶段贡献**：
  - 去除预执行规格后，规格违反率和步骤乱序率显著上升，错误完成声明率从 9.78% 升至 42.74%。
  - 去除运行时执行后，ASR 从 0 升至 0.76%，且规格违反率大幅升高，说明合约必须在运行时持续约束具体调用。
  - 去除收据支持完成后，ASR 变化不大但 TSR 下降、FCR 上升，说明其价值主要体现在任务关闭和完成完整性。
  - 仅提示计划在 TSR 上最高，但 ASR、SVR、SOOR、FCR 均明显恶化，证明确定性执行优于纯自然语言引导。
- **合约质量**：97 个生成合约全部通过静态验证，其中 86 个与参考边界无实质偏差，6 个语义等价，5 个保守偏差，0 个越权扩展。
- **白盒攻击结果**：100 个案例中 2 个成功（2.0%），暴露两个边界：
  1. 证据准入验证溯源和可采纳性，但不验证授权字段的语义真实性；
  2. 绑定覆盖不完整，某些可选但影响效应范围的参数未被纳入 BIND 证明。
- **运行时开销**：相对 NoDefense，AgentDojo 上平均端到端延迟 1.32×、Token 1.37×；ASB 上延迟 1.41×、Token 1.25×，开销与任务结构和安全状态上下文量相关。

## 7. 优点

- **任务级生命周期建模**：将用户授权、运行时证据、外部效应和任务完成统一到连续治理链，比单点防御更完整。
- **POEC 合约结构清晰**：通过 MAY/MUST/BIND/VERIFY 分别表达权限、义务、证据和完成条件，并配合确定性静态分析保证合约有效性。
- **证据与权限分离**：明确区分运行时信息的“信息作用”与“效应权限”，防止外部内容引入新权限或扩大范围。
- **一次性 Effect Certificate 与 Receipt 机制**：将授权绑定到单次具体执行，并通过执行后验证防止授权成功但执行失败被误判为完成。
- **实验设计较全面**：多基准、多模型、消融、压力测试、白盒攻击、开销分析，且白盒攻击能主动暴露剩余信任边界，增强了结果可信度。
- **低攻击成功率且保持实用性**：在固定基准下实现零攻击成功，同时 TSR/UUA 均高于多数基线。

## 8. 不足与局限

- **证据语义真实性假设**：当前证据准入只验证来源、类型和约束，不验证授权字段内容是否被攻击者污染；白盒攻击中两例成功均源于此。
- **绑定覆盖可能不完整**：部分工具的可选参数若影响对象或范围，但未被合约编译器识别为权威参数，可能绕过证明要求。
- **假设条件较强**：安全性依赖语义合约健全、PEP 完全中介、证书与账本原子操作、受保护 runner 精确执行等；分布式部署还需额外认证与防重放机制。
- **实验覆盖偏重结构化任务**：Benchmark 集中在办公、通信、旅行、金融等相对结构化、步骤有限的环境，对长期运行、跨会话、多智能体协作、异步执行等场景支持不足。
- **无真实交互认证通道**：AgentDojo/ASB 不提供交互式认证，STEP UP AUTH 候选被门控且未执行，可能影响部分合法任务完成，实用性指标或受此限制。
- **算力信息缺失**：未报告推理 GPU 类型、数量、总运行时间或 Token 成本，削弱了可复现性和资源评估参考。
- **FIDES 兼容性限制**：由于 ASB 未暴露标签传播接口，FIDES 未能参与 ASB 对比，使跨基准防御比较存在缺口。
- **白盒攻击样本有限**：仅选择 100 个高风险案例进行白盒分析，虽能暴露问题，但不足以全面刻画攻击面。
