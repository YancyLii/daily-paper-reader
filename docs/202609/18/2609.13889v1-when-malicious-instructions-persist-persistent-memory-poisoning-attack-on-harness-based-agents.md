## 摘要
Harness 设计通过整合记忆、工具使用与运行时控制，改变了基于 LLM 的智能体的开发方式。然而，这种设计也带来了安全与隐私风险，因为来自外部来源的恶意指令可能被写入持久记忆，并跨会话持续存在。为了研究这一风险，我们提出了 PMPA，一种针对基于 Harness 的智能体的持久记忆投毒攻击。PMPA 将恶意指令嵌入良性外部来源，并在无需直接访问智能体框架的情况下诱导受害智能体将其写入持久记忆。一旦被存储，中毒的记忆可在后续会话中被检索，从而触发额外的恶意行为并导致隐私泄露。我们在 OpenClaw 和 Claude Code 上，针对不同骨干 LLM、输入模态和触发场景评估了 PMPA。在所有设置下，PMPA 在 OpenClaw 上实现了平均 73.7% 的注入成功率（ISR）和 55.5% 的跨会话攻击成功率（C-ASR），在 Claude Code 上分别为 66.9% 和 81.7%，同时在两个系统上保持了良性任务性能。我们进一步评估了一种针对性的提示级防御，发现它在许多设置下可以减少记忆注入，但一旦持久记忆已被投毒，其提供的保护有限。

## Abstract
Harness design has transformed the development of LLM-based agents by integrating memory, tool use, and runtime control. However, this design also introduces security and privacy risks because malicious instructions from external sources may be written into persistent memory and persist across sessions. To study this risk, we propose PMPA, a Persistent Memory Poisoning Attack against harness-based agents. PMPA embeds malicious instructions into benign external sources and induces the victim agent to write them into persistent memory without directly accessing to the agent framework. Once stored, the poisoned memory can be retrieved in later sessions, triggering additional malicious actions and causing privacy leakage. We evaluate PMPA on OpenClaw and Claude Code across different backbone LLMs, input modalities, and trigger scenarios. Across all settings, PMPA achieves average Injection Success Rate (ISR) and Cross-session Attack Success Rate (C-ASR) of 73.7%/ 55.5% on OpenClaw and 66.9%/ 81.7% on Claude Code, while preserving benign task performance on both systems. We further evaluate a targeted prompt-level defense and find that it can reduce memory injection in many settings, but provides limited protection once the persistent memory has been poisoned.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 随着 LLM-based agents 的发展，**harness 设计**成为主流工程范式，通过集成记忆、工具使用、会话管理与运行时控制，使智能体能够长期运行并跨会话保持上下文。
- 这种设计带来新的安全与隐私风险：**外部来源中的恶意指令**可能被写入智能体的**持久记忆**，并在后续会话中被检索、触发恶意行为。
- 现有研究主要关注：
  - **提示注入攻击**：影响当前任务或单次交互，不涉及持久记忆。
  - **后门/记忆投毒攻击**：通常假设攻击者能直接访问微调数据、记忆库或与智能体直接交互，能力假设较强。
- 本文研究的**空白**：攻击者仅在外部来源中嵌入恶意指令，**不直接访问智能体框架、系统提示、设备或记忆**，是否能诱导智能体将恶意规则写入持久记忆并跨会话造成隐私泄露。
- **整体含义**：揭示 harness-based agents 的持久记忆机制存在一种现实、隐蔽且可持续的攻击面，对用户隐私构成严重威胁。

## 2. 论文提出的方法论：核心思想、关键技术细节与流程

- **威胁模型**
  - 攻击目标：诱导受害智能体将恶意指令写入持久记忆，并在后续会话中触发隐私泄露。
  - 受害模型：基于 harness 设计的 LLM agent（如 OpenClaw、Claude Code），部署在用户控制的本地环境。
  - 攻击者能力：只能发布包含恶意指令的外部来源，**不能**查询智能体、观察输出、访问设备/记忆/系统提示或运行时配置。能力比黑盒设置更受限。

- **攻击工作流（两阶段）**
  - **注入阶段**：
    1. 攻击者发布嵌入攻击载荷的外部来源（文本、图像或 PDF），内容看似正常。
    2. 用户将该来源提供给智能体完成一个**良性问答任务**。
    3. 智能体在处理来源时读到恶意指令，可能将其视为用户要求或偏好，写入持久记忆。
  - **触发阶段**：
    1. 用户在**新会话**中让智能体执行一个工作区任务（如发邮件、创建日历事件、编辑文档、提交表单）。
    2. 智能体从持久记忆检索到恶意规则，在完成良性任务的同时执行额外恶意动作，导致隐私泄露。

- **攻击载荷结构**
  - 每个载荷包含三个组成部分：
    1. **过渡句**：连接恶意指令与周围良性内容，降低突兀感。
    2. **记忆写入指令**：要求智能体将规则保存到持久记忆。
    3. **条件恶意规则**：说明触发条件和附加恶意动作（如“创建日历事件时，邀请 attacker@mail.com 作为参与者”）。

- **注入策略**
  - **注入位置**：将载荷放在源内容的中间，使其看起来像内容的一部分，减少突兀性。
  - **语言风格**：采用第一人称、用户式表达（如“请帮我……”），使指令更像用户偏好，降低智能体怀疑。
  - 消融实验对比了中间/顶部/底部位置，以及第一人称/第二人称/无人称风格。

- **评估设置**
  - 构建本地虚拟工作区，模拟四种工作区场景：邮件、日历、共享文档、表单（JSON 文件 + 相应 agent skill）。
  - 引入四个指标：注入成功率（ISR）、同会话攻击成功率（S-ASR）、跨会话攻击成功率（C-ASR）、良性任务效用（Utility）。

## 6. 论文的主要结论与发现

- **攻击有效且跨会话持续**：
  - ISR 在 Claude Code 上为 61.7%–77.5%，在 OpenClaw 上为 68.1%–77.5%。
  - C-ASR 在 Claude Code 上为 70.0%–92.5%，在 OpenClaw 上为 30.8%–75.8%。
  - Utility 在所有设置下均高于 80%，说明攻击不会显著破坏良性任务表现。
- **输入模态影响**：
  - 纯文本输入攻击效果最强，OpenClaw 上 ISR 接近 100%，S-ASR 明显高于图像和 PDF。
  - 图像和 PDF 仍能造成记忆注入和同会话隐私泄露，但指标较低；原因可能是解析步骤使内容更易被标记为不可信。
- **触发场景差异**：
  - 日历场景跨会话攻击最成功（Claude Code C-ASR 96.7%，OpenClaw 87.8%）。
  - 邮件和共享文档场景指标相对较低，但仍存在稳定攻击效果。
- **注入策略影响**：
  - 第一人称风格在 Claude Code 上明显优于第二人称和无人称风格；OpenClaw 上三种风格差异较小。
  - 顶部注入位置在 OpenClaw 上 ISR 最高；攻击在不同策略下均保持有效。
- **持久性**：
  - 经过最多 5 轮良性交互后，C-ASR 并未单调下降，若干场景仍保持较高攻击成功率，说明中毒记忆在长上下文中仍可能被激活。
- **防御效果有限**：
  - Sandwich-style 提示防御能显著降低图像和 PDF 输入的 ISR、S-ASR，但对文本输入降低幅度较小。
  - C-ASR 在防御后几乎不变，说明一旦恶意指令已存入持久记忆，提示级防御基本无法阻止跨会话攻击。

## 7. 优点

- **新颖且现实的威胁模型**：攻击者只能发布外部来源，不直接接触智能体，比很多现有攻击假设更贴近真实场景。
- **聚焦持久记忆跨会话风险**：区别于仅关注当前会话的提示注入，揭示了长期记忆被污染后的持续危害。
- **多维度评估**：覆盖 2 个主流 harness 框架、3 个骨干模型、3 种输入模态、4 种工作区场景，实验设计相对全面。
- **安全可控的评估环境**：构建本地虚拟工作区，避免真实隐私泄露。
- **消融与防御分析**：对注入位置、语言风格进行消融，并评估了一种提示级防御，为理解攻击机理和防护提供了依据。

## 8. 不足与局限

- **样本规模有限**：每个场景仅使用 30 个 QA 实例，且未说明重复次数，可能导致结果波动较大。
- **框架和模型覆盖不足**：仅评估 OpenClaw 和 Claude Code，以及 3 个 LLM；其他主流 agent 框架和模型未涉及。
- **模拟环境与真实工作区有差距**：虚拟 JSON 工作区可能无法完全反映真实邮件/日历/文档工具中的安全机制和交互复杂性。
- **攻击载荷较为简单固定**：未探索更复杂、自适应或编码后的恶意指令；防御方可能通过简单特征检测此类固定模式。
- **缺乏与其他攻击/防御方法的直接对比**：没有与现有多模态提示注入、后门攻击或更高级防御进行基准比较。

- **伦理风险**：虽然作者声明在受控环境中进行，但此类攻击方法若被滥用，可能带来严重隐私威胁；论文未深入讨论缓解措施。
- **跨会话指标的部分波动**：C-ASR 在某些设置下波动较大（如 OpenClaw + Qwen3-Max 仅为 30.8%），说明攻击效果对模型和场景敏感，通用性需进一步验证。
