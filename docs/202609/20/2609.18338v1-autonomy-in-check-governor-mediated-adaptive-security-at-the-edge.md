## 摘要
网络边缘的自适应安全越来越依赖自动化规划器，包括基于规则的控制器、学习策略和 LLM 辅助代理，它们将观测转化为执行动作。一旦这样的规划器能够影响实时策略状态，仅语法有效是不够的。由不完整或被操纵的观测所产生的语义错误动作，可能会被无法判断任务上下文的执行基底忠实执行。我们将规划器输出与内核执行输入之间的边界视为主要安全对象来解决这一问题。我们提出一种分离控制架构，其中不可信的规划器发出类型化安全意图，确定性的治理器根据安全性、资源、时间稳定性和比例性不变量检查每个意图，只有被接纳的动作才会绑定到签名回执并编译到预安装的 eBPF 映射更新中。本文形式化了这一信任边界问题，定义了三种威胁类别，开发了治理器准入谓词，并报告了一个端到端原型。在连接到大学 5G 测试网络的 Raspberry Pi 5 测试平台上，针对基于规则和 LLM 辅助的规划器，治理器以微秒级成本接纳、拒绝和限制意图，且不破坏受保护流的规律性。这一贡献既是概念性的也是实证性的：自适应安全无需信任动作的作者，而是需要一个中介边界来决定该动作是否可接受。

## Abstract
Adaptive security at the network edge increasingly relies on automated planners, including rule-based controllers, learned policies, and LLM-assisted agents, that translate observations into enforcement actions. Once such a planner can influence live policy state, syntactic validity is not enough. A semantically wrong action, produced from incomplete or manipulated observations, can be faithfully executed by an enforcement substrate that cannot judge mission context. We address this problem by treating the boundary between planner output and kernel enforcement input as the primary security object. We propose a split-control architecture in which an untrusted planner emits typed security intents, a deterministic governor checks each intent against safety, resource, temporal-stability, and proportionality invariants, and only admitted actions are bound to signed receipts and compiled into pre-installed eBPF map updates. The paper formalizes this trust-boundary problem, defines three threat classes, develops the governor admission predicate, and reports an end-to-end prototype. Across rule-based and LLM-assisted planners on a Raspberry Pi 5 testbed connected to the university 5G Test Network, the governor admits, rejects, and bounds intents at microsecond cost without disrupting protected-flow regularity. The contribution is conceptual as much as empirical: adaptive security does not need to trust the author of an action. It needs a mediation boundary that decides whether the action is admissible.

## 1. 核心问题与整体含义

- **研究背景**：现代边缘系统越来越多地依赖自适应安全机制，由自动化规划器（规则控制器、学习策略、LLM辅助代理）将观测转化为执行动作（监控、限速、升级、隔离等）。这种转变在提升响应性的同时，也改变了安全问题本身——**适应过程本身成为攻击面的一部分**。
- **核心问题**：当前自适应安全系统通常只信任语法有效的规划器输出，但语义上不安全的行为可能源于被操纵的观测或不完美的推理。规划器在输入被对手塑造时，可能发出局部一致但对任务上下文不安全的动作，而执行基底会忠实执行这些动作。关键问题不再是“如何检测恶意行为”，而是**“当输入不可完全信任时，如何约束自适应控制器被允许做什么”**。
- **整体含义**：作者将**规划器输出与内核执行输入之间的边界**作为主要安全对象，提出“分离控制架构”，核心原则是：**自主性属于规划阶段，但执行必须被中介、有界且可审计**。自适应安全不需要信任动作的作者，而是需要一个中介边界来决定该动作是否可接受。

## 2. 方法论

### 2.1 整体架构：分离控制（Split-Control）

系统包含六个逻辑组件，形成单向执行管道：
- **观测平面**：内核驻留 eBPF 程序（附着在 tc/XDP 钩子）导出每个类别的包/字节速率、丢包计数、队列压力等遥测数据。
- **状态构建器**：用户态守护进程组装决策状态 $x_t = [o_t, c_t, r_t, q_t, h_t, m_t, u_t]$，其中 $u_t \in [0,1]$ 是来自测量新鲜度和跨源一致性的不确定性信号。
- **规划器**：接收 $x_t$ 并返回类型化意图，可以是基于规则、学习策略或 LLM 辅助代理，**在信任边界之外**。
- **治理器（Governor）**：确定性评估准入谓词 $\Gamma(a_t, x_t)$，只有在通过时发出签名回执 $\rho_t$。
- **编译器**：验证 HMAC 后，将批准的意图转换为有界 eBPF 映射更新，并追加审计日志。
- **执行器**：eBPF 基底，仅执行被批准的动作。

### 2.2 有界意图词汇表

限制规划器只能使用六种类型的意图，每种带有影响序数（impact ordinal）：

| 意图 | 序数 | 效果 |
|------|------|------|
| MONITOR | 0 | 被动观察，无流量影响 |
| REQAPPROVAL | 0 | 暂停直接执行，请求操作员审查 |
| ROLLBACK | 1 | 回退到上次治理器批准的稳定状态 |
| RATELIMIT | 2 | 受限速率控制，强制豁免 $F_{crit}$ 中的流 |
| ESCALATE | 3 | 请求更高级别的检测而不修改本地速率策略 |
| ISOLATE-NC | 4 | 仅隔离非关键流/设备 |

### 2.3 五种准入不变量（Admission Predicate $\Gamma = I_1 \wedge I_2 \wedge I_3 \wedge I_4 \wedge I_5$）

- **I1 – 语法有效性**：意图属于声明的词汇表，参数类型和值域有效。
- **I2 – 流安全性**：限制性动作不能影响 $F_{crit}$ 中的流，除非有明确的策略豁免（仅 REQAPPROVAL/ROLLBACK 可豁免）：
$$\text{scope}(a_t) \cap F_{crit} = \emptyset \lor \text{type}(a_t) \in \{\text{REQAPPROVAL}, \text{ROLLBACK}\}$$
- **I3 – 资源约束**：应用该意图后必须为受保护服务保留足够的带宽余量：
$$\text{headroom}(r_t, a_t) \geq r_{min}$$
- **I4 – 时间稳定性**：同一作用域上的上一次获批动作必须至少 $\Delta_{min}$ 个周期之前发生：
$$t - t_{\text{last}}\big(\text{scope}(a_t)\big) \geq \Delta_{min}$$
  这将对振荡攻击的速率限制在 $1/\Delta_{min}$ 以下。
- **I5 – 比例性**：动作的影响不能超过观察到的威胁严重程度与当前不确定性共同支持的范围：
$$\text{impact}(a_t) \leq \phi\big(\text{severity}(o_t), u_t\big)$$
  其中 $\phi$ 随 $u_t$ 单调递减，$u_t$ 越高，可执行的动作越受限。

### 2.4 完整性路径

被接纳的意图会生成签名批准记录：
$$\rho_t = \big(t, a_t, H(x_t), \text{HMAC}_k(t \parallel a_t \parallel H(x_t))\big)$$
其中 $k$ 仅由治理器进程持有。只有特权编译器服务（唯一持有 eBPF 映射文件描述符和 Linux 能力）验证 $\rho_t$ 后才能执行更新。治理器和执行基底属于可信计算基（TCB），规划器不在其中。

## 3. 实验设计

- **测试平台**：大学 5G 测试网络（5GTN，n78 频段 3.5 GHz），Raspberry Pi 5（4核 Cortex-A76，8 GB RAM，内核 6.12.79）作为执行节点和网关。wlan0 通过 WiFi 连接三个 ESP32-S3 端点，wwan0 提供 5G 连接到核心网。
- **流量类别**：受保护报警类（20字节 UDP，10 Hz，名义100 ms 到达周期）和常规类（1 kB 遥测突发，1 Hz）。
- **实验配置**：四种配置对比——Static（无自适应控制）、Rule（规则规划器+治理器）、Rule, no gov.（移除治理器的消融）、LLM（LLM 规划器+治理器）。
- **威胁模拟**：
  - **T1（上下文操纵）**：抑制三条 ESP32 报警源中的两条报告，使规划器对受保护流活动的视图与实际流量记录不一致。
  - **T2（策略振荡）**：以 $f_{adv} = 2/\Delta_{min}$ 注入意图，测试 I4 冷却期检查。
  - **T3（残余窗口利用）**：用 hping3 在治理器批准过渡后立即注入 UDP 突发，探测稳定窗口。
- **评测指标**：受保护流接收端节奏（receiver-side cadence）、攻击意图接纳率、治理器决策开销、意图处置分布。

## 6. 主要结论与发现

- **受保护流规律性保持良好**：四个 30 分钟基线运行中，p99 超额低于 7.3 ms，p99.9 低于 40.4 ms，所有配置下无序列间隙。
- **治理器开销极小**：p99 决策开销在 76.24–129.09 µs 之间，始终低于 1 ms，即使面对 LLM 随机性或对抗性输入。
- **振荡攻击被有效钳制**：在 $f_{adv} = 2/\Delta_{min}$ 下，I4 拒绝了 49.7% 的注入意图，符合预期的交替意图剪切模式。
- **LLM 规划器被有效约束**：名义 LLM 运行中，51 个结构化意图中有 38 个在强制执行前被拒绝（19 个 I1、5 个 I2、14 个 I5）；422 个非执行输出被转换为 do_nothing。
- **治理器不损害正常性能**：名义 p99 节奏超额在所有配置中均在一个 1.5 ms 带宽内，治理器在攻击下改变了可执行内容，却对正常受保护流无显著影响。
- **核心理念验证**：自适应安全无需信任决策组件，同样一个治理器可独立控制规则、学习或 LLM 生成的意图，为未来更强但更难预测的规划器提供了稳定安全边界。

## 7. 优点

- **将安全边界重新定位到规划器-执行器接口**：传统研究侧重检测恶意行为或提升执行效率，本文识别出“语义安全”这一被忽视的层面，用信任边界重新框定问题。
- **确定性、可推断的准入谓词**：五个不变量各自对应不同的失败模式，清晰、可验证、可部署，实现了安全分析的模块化。
- **规划器不可信任原则**：所有规划器类型（规则、学习、LLM）都经过同一中介边界，实现了架构层面与具体规划器实现解耦——新的规划器可随时引入而无需授予直接控制权限。
- **完整性保障链**：HMAC 签名收据 + 特权编译器 + 有界状态空间 + 仅追加审计日志，形成了从治理器到 eBPF 的完整不可否认链。
- **实证充分性**：非仅提出理论，还包括在真实 5G 测试网络上的端到端原型，并针对三类威胁逐一验证。
- **诚实的局限报告**：明确承认 T3 仅是部分遏制、I3 未被触发、实验规模有限，在同类论文中罕见且值得肯定。

## 8. 不足与局限

- **实验规模有限**：单个执行节点、三个端点，未覆盖多网关协调、大规模流量重放（数千源）、I3 饱和等场景。作者明确指出“更大规模的证据留给扩展版本”。
- **T3（残余窗口）仅部分遏制**：从治理器批准到内核稳定执行之间的过渡窗口（平均 2.616 ms）无法完全消除，对于更严格时序要求的应用仍是问题。
- **I3 资源约束未经试验证**：实测负载下未触发 I3，仅作为结构性防护；无法评价其在饱和条件下的实际效果。
- **参数敏感性未系统研究**：$\Delta_{min}$、$r_{min}$ 等关键参数的安全-敏捷权衡仅作定性讨论，缺乏系统性参数扫描或最优参数选取。
- **LLM 推理开销**：LLM 规划器在协同 GPU 节点上运行，推理延迟未在主要结果中表征；治理器开销虽微秒级，但整体闭环响应时间受 LLM 推理瓶颈影响，未被量化。
- **时钟漂移问题**：作者承认长运行暴露跨设备时钟漂移，导致原计划的一向延迟评测不可靠，转而使用接收端时间戳；这说明跨设备时间同步是实验的工程瓶颈。
- **攻击模型假设较简**：T2 直接注入治理器 Unix socket，为保守最坏情况但偏离了远程攻击者可能面临的额外传输延迟；T1 通过抑制报告实现，未探索更复杂的间接提示注入场景。
- **无跨域验证**：虽然声称适用于医疗、工业、车联网等领域，但仅在医疗报警场景（5GTN 测试台）上进行了实证验证，跨域通用性推断主要来自结构类比。
