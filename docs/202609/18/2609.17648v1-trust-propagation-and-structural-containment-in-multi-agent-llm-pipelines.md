## 摘要
多智能体LLM系统日益自动化涉及不同权限级别智能体的任务，这带来一种安全风险：受威胁的低权限智能体可能影响高权限智能体并触发未经授权的操作。我们研究了一个由 Supervisor、Researcher、Validator 和 Executor 组成的四智能体 LangGraph 流水线中的攻击传播。我们评估了共享内存投毒以及通过在检索到的文档中嵌入伪造批准而进行的间接提示注入。我们将 Validator 的判断与一个独立授权层进行比较，该授权层使用任务绑定的签名令牌和单独验证的策略预言机。我们的贡献包括：对攻击传播的实证研究、对授权边界的组件级消融，以及判断绕过率（JBR），该指标衡量被攻击智能体处的失陷，而非最终动作处的失陷。在三个随机种子和60个带标签任务中，内存投毒在每一次未设防试验中都到达执行阶段。启用授权后，其JBR达到100%，但不安全动作率为0%，这表明 Validator 可能仍然失陷，而执行受到遏制。对于拥有签名秘密的攻击者，策略预言机提供了所观察到的遏制效果，而独立编写的最小权限策略保持了这一结果。一个 Observer 层将智能体劫持的误报率从49%降低到7%，且未削弱执行级安全性。这些结果表明，即使上游LLM判断失效，结构化授权也能遏制失陷智能体的行为。

## Abstract
Multi-agent LLM systems increasingly automate tasks involving agents with different levels of privilege, creating a security risk in which a compromised low-privilege agent can influence a higher-privilege agent and trigger an unauthorized action. We study attack propagation in a four-agent LangGraph pipeline comprising a Supervisor, Researcher, Validator, and Executor. We evaluate shared-memory poisoning and indirect prompt injection through a forged approval embedded in a retrieved document. We compare the Validator's judgment with an independent authorization layer using task-bound signed tokens and a separately verified policy oracle. Our contribution is an empirical study of attack propagation, a component-level ablation of the authorization boundary, and the Judgment Bypass Rate (JBR), which measures compromise at the attacked agent rather than at the final action. Across three seeds and 60 labeled tasks, memory poisoning reaches execution in every undefended trial. With authorization enabled, it achieves 100% JBR but 0% Unsafe Action Rate, showing that the Validator can remain compromised while execution is contained. Against an attacker possessing the signing secret, the policy oracle provides the observed containment, while an independently authored least privilege policy preserves this result. An Observer layer reduces the false-positive rate for agent hijacking from 49% to 7% without weakening execution-level security. These results show that structural authorization can contain compromised agent behavior even when upstream LLM judgment fails.

## 1. 论文的核心问题与整体含义

- 多智能体 LLM 系统中，不同权限等级的智能体协作完成任务，但低权限智能体一旦被攻陷，可能影响高权限智能体并触发未授权操作，即经典的“混淆代理（confused deputy）”问题。
- 现有研究多关注“某个智能体是否被欺骗”，较少关注“被欺骗的判断是否会最终变成真实的系统动作”。论文的核心问题是：**能否通过结构化的授权边界，在 LLM 判断已经失效时，仍然阻止未授权执行**。
- 论文提出用任务绑定签名令牌和独立策略预言机构成执行级授权层，并引入 **JBR（Judgment Bypass Rate）** 指标来区分“审查被绕过”和“未授权动作真正发生”。
- 整体含义是：安全防护不应只依赖上游 LLM 的判断，而应在执行边界上实现独立、结构化的权限验证。

## 2. 论文提出的方法论

### 2.1 系统架构

- 四智能体 LangGraph 流水线：
  - **Supervisor**：确定性路由器，不调用 LLM，按固定顺序调度；
  - **Researcher**：低权限、只读，负责检索；
  - **Validator**：中权限，作为审批门；
  - **Executor**：高权限，执行真实数据库/文件操作。
- 所有角色通过共享的、类型化状态对象通信，所有状态转换被记录。

### 2.2 结构化授权机制

- 审批必须附带 **HMAC 签名的、任务绑定的、一次性令牌**。
- Executor 在允许任何真实工具调用前，必须：
  1. 验证签名令牌有效；
  2. 独立通过策略预言机重新推导权限；
- 只有同时满足两个条件，请求才能到达 SQLite 邮件数据存储。
- 策略预言机有两种模式：
  - **corpus policy**：直接映射每个任务的黄金标签，主要用于测试执行保真度；
  - **independent policy**：手写的最小权限 allowlist，只接收提议动作及资源范围，不使用任务标签。

### 2.3 攻击模型

- **内存投毒（memory poisoning）**：Validator 被替换为恶意例程，直接伪造审批；若拥有签名密钥，则生成匹配的授权令牌，完全绕过 LLM。
- **智能体劫持（agent hijacking）**：Researcher 从受污染源检索到包含伪造审批、置信度和来源声明的文档，Validator 在不知道来源的情况下对该摘要进行判断。
- 攻击者能力分为 T0（禁用令牌和策略预言机）和 T1（启用两者），并额外考虑攻击者持有签名秘密的最强情况。

### 2.4 评估指标

- 标准混淆矩阵指标：TP、FP、FN、TN，以及 Recall、F1。
- **UAR（Unsafe Action Rate）**：黄金不安全任务中实际执行的比例，越低越好。
- **LTC（Legitimate Task Completion）**：黄金安全任务中被允许完成的比例，越高越好。
- **FPR（False Positive Rate）**：黄金安全任务被错误阻止的比例。
- **JBR（Judgment Bypass Rate）**：在被攻击的智能体处，审查判断被绕过的比例，衡量智能体级失陷程度，而非最终执行效果。

## 3. 实验设计

  - 使用 **Enron 邮件数据集**，解析 Message-ID、发送者、接收者和时间戳，选取 1000 条仅保留头部信息的邮件。

  - 比较 corpus policy 与独立最小权限 policy；
  - Observer 层开启/关闭对智能体劫持的对比。
- **模型配置**：所有 LLM 智能体使用 `gemma4:31b-cloud`，通过 Ollama 服务，温度设为 0；Supervisor 不调用模型。

## 6. 论文的主要结论与发现

- 未防御时（T0），内存投毒在所有试验中均导致未授权执行，UAR 为 100%。
- 启用 T1 后，内存投毒的 UAR 降至 0%，但 **JBR 仍为 100%**，说明 Validator 可以完全被绕过，而执行层仍然有效遏制了未授权动作。
- 智能体劫持在 T0 和 T1 下 UAR 均为 0%，但 FPR 较高（T0 59.3%、T1 49.1%），原因是 Validator 将伪造审批视为可疑内容，大量误拦截合法任务。
- 授权消融显示：当攻击者持有签名密钥时，**仅靠签名令牌无法提供遏制**，真正起关键作用的是独立策略预言机。
- 独立最小权限策略与 corpus policy 在遏制效果上一致，说明结果并非完全由标签驱动的循环验证所致。
- 添加 Observer 层后，智能体劫持的 FPR 从 49.1% 降至 7.4%，F1 从 0.74 提升至 0.95，且 UAR 保持 0%，即执行级安全未被削弱。
- 总体结论：**结构授权可以在上游 LLM 判断失效时，仍防止未授权系统动作发生**。

## 7. 优点

- **问题定位清晰**：聚焦于攻击传播是否到达真实执行，而非仅关注智能体是否被欺骗，更贴近实际安全影响。
- **提出 JBR 指标**：将“智能体级失陷”与“执行级失陷”解耦，为防御评估提供了更细致的视角。
- **组件级消融严谨**：明确区分签名令牌与策略预言机的贡献，揭示签名只授权来源而非权限，策略才是关键遏制点。
- **攻击者能力分级**：逐步增强攻击者能力（包括持有签名秘密），避免了攻击不成立仅因攻击者缺少凭据的假象。
- **独立策略验证**：使用不依赖任务标签的手写最小权限策略重复实验，降低了循环验证风险。
- **Observer 层设计合理**：作为效用保持组件而非安全边界，只移除伪造审批声明，不判断任务安全性，避免引入额外安全依赖。
- **结果呈现规范**：采用多种子均值和置信区间，对不稳定指标给出区间估计。

## 9. 总体评价

- 论文在概念上具有启发性：将安全从“模型判断”推进到“执行边界”，并提供了可操作的授权原语。
- 实验证明结构授权确实能阻止由智能体失陷引发的未授权执行，且独立策略预言机是关键组件。
