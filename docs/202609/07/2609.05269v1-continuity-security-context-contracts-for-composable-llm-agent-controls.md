## 摘要
LLM 智能体系统越来越多地结合了来源追踪、授权、策略执行、协议适配器和执行控制。然而，单独正确的安全机制并不一定能组合成端到端安全的系统：当操作跨越组件边界时，安全关键上下文可能被丢弃、扩大、重新绑定或重新解释。我们将这种失效模式称为安全上下文不连续性，并引入 CONTINUITY，一个用于智能体安全控制可验证组合的框架。CONTINUITY 使用假设-保证契约为每个组件建模，并利用签名的根授权、来源承诺、角色绑定的转换回执、有界类型化发布、转换见证和效果绑定的执行许可，在转换过程中携带经过认证的安全上下文。我们对端到端后果完整性进行形式化，要求每一个已实现的外部效果都由有效且当前的授权见证支持，该见证将主体、任务、来源、委托、策略状态、规范动作和终局边界关联起来。我们实现了一个参考验证器和确定性的跨层故障注入测试套件，覆盖四个应用领域中的32种故障类别。在涵盖128个故障域类别的2560个参数化攻击实例中，完整的 CONTINUITY 配置未产生任何有害外部效果，同时完成了全部700个良性任务，并上报了全部200个模糊案例。这些结果表明，安全的智能体执行不仅需要健全的单独控制，还需要显式的契约，在从指令到效果的完整路径上保持其保证。

## Abstract
LLM agent systems increasingly combine provenance tracking, authorization, policy enforcement, protocol adapters, and execution controls. However, individually correct security mechanisms do not necessarily compose into an end-to-end secure system: security-critical context may be dropped, widened, rebound, or reinterpreted as actions cross component boundaries. We identify this failure mode as security-context discontinuity and introduce CONTINUITY, a framework for verifiable composition of agent security controls.   CONTINUITY models each component with an assume-guarantee contract and carries authenticated security context across transitions using signed root grants, provenance commitments, role-bound transition receipts, bounded typed releases, transformation witnesses, and effect-bound execution permits. We formalize end-to-end consequence integrity, requiring every realized external effect to be backed by a valid and current authorization witness linking the principal, task, provenance, delegation, policy state, canonical action, and finality boundary.   We implement a reference verifier and deterministic cross-layer fault-injection suite covering 32 fault classes across four application domains. In 2,560 parameterized attack instances spanning 128 fault-domain classes, the full CONTINUITY configuration commits no harmful external effect, while completing all 700 benign tasks and escalating all 200 ambiguous cases. These results show that secure agent execution requires not only sound individual controls, but explicit contracts that preserve their guarantees across the complete instruction-to-effect path.

## 1. 论文的核心问题与整体含义

- **研究问题**：LLM 智能体系统组合了来源追踪、任务范围授权、策略网关、协议适配器、效果绑定执行等多种安全控制，但这些控制通常被单独说明和测试。它们的组合可能仍然失败，例如边界丢弃来源标签、接受自声明的权威根、扩大委托、在缺少有效转换关系的情况下更改已批准字段、或执行过期/重放的许可。
- **安全上下文不连续性**：论文将这类失效归类为“安全上下文不连续性”（security-context discontinuity），即安全相关事实在控制组件之间被丢失、削弱、重新解释或重新绑定。
- **整体含义**：单独正确的安全机制不保证端到端安全；必须通过显式契约将安全保证从指令上下文连续地传递到最终外部效果。论文提出“端到端后果完整性”（ECI）作为目标性质。

## 2. 论文提出的方法论

- **核心思想**：使用**假设-保证合约**（assume-guarantee contract）对每个组件建模，并在组件之间传递签名的、可验证的安全上下文。
- **关键技术组件**：
  - **签名的根授权**（signed root grants）：由可信权威签署，绑定主体、任务、权限集合、工具/服务器/效果身份、字段约束、策略时代、来源/上下文承诺等。
  - **字段级来源证明**（field-resolved provenance）：使用 JSON Pointer 路径将来源声明绑定到具体字段值，并校验值摘要。
  - **有界类型化释放**（bounded typed releases）：将不可信外部值绑定到特定目标字段、源、值摘要、谓词、主体、任务、操作和工具，防止跨上下文重用。
  - **角色绑定的转换回执**（role-bound transition receipts）：每个组件签名收据，绑定输入/输出信封摘要、合同、变更字段集、转换见证等，并验证签名者与阶段/角色/合同匹配。
  - **转换见证**（transformation witnesses）：对合法语义转换（例如别名解析）要求独立可信验证者签署的见证，验证器独立评估关系谓词。
  - **效果绑定的执行许可与终局性**（effect-bound execution permits & finality）：许可绑定规范动作摘要、主体、受众、策略状态、一次性随机数、幂等键；终局性接收器在提交效果前重新检查主体、动作、策略、撤销、过期、随机数和幂等状态。
- **形式化模型**：定义信封 \(E\)、根授权 \(\Gamma\)、组件合同 \(C_i\)、转换回执 \(\rho_i\)、执行许可 \(\pi\)、效果见证 \(W_e\)。组合安全定理给出七个条件（C1–C7）：认证源头、合同兼容、上下文连续性、非放大、规范动作绑定、新鲜终局性、完全中介。
- **实现**：Python 3.11+ 参考实现，安全核心约 1,523 行（`core.py`），加上实验与故障注入代码共约 3,220 行。使用 SHA-256 摘要和 Ed25519 签名，确定性 JSON 编码。

## 3. 实验设计

## 6. 论文的主要结论与发现

- **完整 CONTINUITY 配置**：在 2,560 个攻击实例中实现**零有害外部效果**，包含全部 128 个故障-域类，同时完成 700 个良性任务并升级 200 个模糊案例，生命周期正确性 100%。
- **最强的不完整配置**（Gateway+Finality）仍有 **65.6% 的效果攻击成功率**，说明仅组合网关策略和最终动作绑定不足以保证端到端安全。
- **消融实验**：移除字段级来源验证、合同一致性检查或完全中介各重新打开 24 个故障-域类；移除根认证重新打开 16 个；移除释放验证 12 个；转换见证和重放保护各 8 个；单独的权限单调性移除在本基准中未重新打开任何类（由于防御纵深）。
- **核心结论**：安全的智能体执行需要显式、可验证的契约，将安全保证从指令上下文连续传递到最终效果；单独控制正确不等于组合正确。

## 8. 不足与局限

- **可信根是部署输入**：根授权、来源验证器、释放验证器、转换验证器等可信组件的配置和正确性不在系统保证之内；根或验证器被恶意配置或攻破会破坏相应保证。
- **完整性不等于语义正确性**：系统保证安全上下文的连续性，但不保证来源数据本身真实或验证器的结论正确；可信验证器可能产生错误的结构化结论。
- **上下文清单完整性依赖运行时**：原型不检测生产模型运行时是否真正覆盖了所有展示给模型的字节；不完整的上下文捕获会违反假设。
- **转换语言受限**：当前仅实现别名解析关系，生产环境需要更丰富的版本化关系语义（如货币转换、模式映射、聚合、去分类），这会带来新的可靠性和政策审查挑战。
- **未验证实现**：证明适用于抽象模型，Python 工件未经形式化验证、非恒定时间、未硬化；确定性 JSON 编码器应替换为符合标准的规范化器。
- **合成符合性基准**：测试套件由设计故障模板和确定性参数变化组成，非穷尽且非真实攻击分布采样；0/2,560 的结果不能解读为普适失败概率估计。
- **简化提供者语义**：终局性世界、随机数账本和幂等存储是内存中原子操作；真实分布式提供者存在并发、部分失败和最终一致性等问题。
- **不完整信息流覆盖**：不消除隐蔽信道，不阻止通过允许文本输出、时间、资源名称或聚合查询的泄露；完全中介是工程和治理义务。
- **人为和语义错误**：有效授权可能批准不明智的行为；用户可能批准误导性请求；CONTINUITY 不保证目标明智、合法或语义正确。
- **工件集成有限**：参考管线模拟了内存、策略、适配器和终局性边界，但未完成与生产 MCP、A2A、OWASP ACS、云 IAM 或区块链的集成。
