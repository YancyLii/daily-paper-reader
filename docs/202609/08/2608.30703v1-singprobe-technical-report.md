## 摘要
运行时护栏对于可靠的大语言模型（LLM）部署至关重要，然而现有方法通常依赖独立的外部模型，这会带来额外的推理成本、延迟的安全信号，以及与能力日益增强的基础模型之间的容量不匹配。为解决这些问题，我们提出 SingProbe，一种轻量级内在运行时护栏，它直接复用 LLM 推理过程中产生的隐藏状态，并与自回归解码同时运行。在统一框架内，SingProbe 在 token 级别持续预测查询意图、响应安全性和幻觉风险，额外的护栏推理开销几乎可以忽略不计，提供了一种“免费午餐”式方案。我们还引入 SingStreamBench，一个旨在评估流式护栏是否能在良性前缀上保持不激活、同时及时检测新出现的不安全内容的基准。大量实验表明，与规模大得多的独立护栏和专门的幻觉检测器相比，SingProbe 取得了有竞争力或更优的性能，仅需约 2M 参数和不到 0.5% 的额外开销。除被动检测外，我们还表明 SingProbe 分数能够预测未来生成风险并指导受约束的安全解码。我们进一步将这一范式扩展到医学生成，提出 SingProbe-Med，仅在出现临床相关风险时选择性地激活面向风险的解码干预。综上，这些结果证明内部模型表示为生成时的监测与控制提供了一个有效且高效的接口。

## Abstract
Runtime guardrails are essential for reliable large language model (LLM) deployment, yet existing approaches typically rely on independent, external models that introduce additional inference cost, delayed safety signals, and a capacity mismatch with increasingly capable base models. To address these issues, we introduce SingProbe, a lightweight intrinsic runtime guard that directly reuses hidden states produced during LLM inference and operates alongside autoregressive decoding. Within a unified framework, SingProbe continuously predicts query intent, response safety, and hallucination risk at the token level with negligible additional guardrail inference overhead, offering a "free-lunch" solution. We further introduce SingStreamBench, a benchmark designed to assess whether streaming guardrails remain inactive on benign prefixes while promptly detecting emerging unsafe content. Extensive experiments show that SingProbe achieves competitive or superior performance compared with substantially larger standalone guardrails and specialized hallucination detectors, with only $\approx$2M parameters and $<0.5\%$ extra overhead. Beyond passive detection, we also show that SingProbe scores can anticipate future generation risk and guide constrained safe decoding. We further extend this paradigm to medical generation through SingProbe-Med, which selectively activates risk-directed decoding interventions only when clinically relevant risks emerge. Together, these results demonstrate that internal model representations provide an effective and efficient interface for generation-time monitoring and control.

## 2. 论文提出的方法论

### 2.1 SingProbe 整体架构
- **输入**：从基座模型选定若干层（默认 3 层，浅、中、深各选一层）提取隐藏状态，拼接后送入轻量预测头。
- **预测头**：一个 query-residual 多头注意力（MHA）块 + 线性分类器，输出：
  - 查询意图分数：8 维（7 类风险 + Safe）；
  - 响应不安全分数：1 维；
  - 幻觉分数：1 维。
- **因果流式特性**：每个 token 位置的输出仅依赖当前前缀，因此可在生成过程中持续更新预测。

### 2.2 训练目标
- **查询意图损失**：对 7 类风险类别采用二元交叉熵（BCE），对 Safe 类别单独 BCE，并加入软互斥损失，惩罚 Safe 与最高风险类别同时高置信度。
- **响应安全与幻觉损失**：采用 token 级 BCE，但监督标签只有响应级。为此提出**自适应置信度加权**：
  - 根据当前预测的离散度（std）动态调整权重强度 β；
  - 当 token 预测不够分化时退化为均匀平均，避免早期噪声放大；
  - 当预测分化明显时，对高风险 token 分配更大权重。
- **多任务组合**：使用指数移动平均（EMA）动态调整各任务损失权重，使训练聚焦于当前更难的任务。

### 2.3 训练数据构建
- 合并公开安全/幻觉数据集的官方训练划分，统一到细粒度风险分类体系；
- 使用多个开源 LLM（如 Qwen3.5-397B-A17B、Kimi-K2.6）进行独立标注和交叉验证；
- 策略合成数据：使用红队模型生成有害提示和良性对照组，生成多样响应（有害响应、安全拒绝、安全替代），避免查询标签泄漏到响应安全；
- 质量控制：去重、平衡类别、保留高置信边界样本。

### 2.4 SingStreamBench 基准
- 旨在评估流式护栏能否在良性前缀保持静默，并在不安全内容出现时及时报警。
- 将响应分解为 `rsafe ⊕ rtarget`，重点评估安全前缀到不安全片段的过渡。
- 六级分层构造（Tier 0–5），逐步测试对查询恶意性、安全前缀、复杂上下文的误报鲁棒性。
- 核心版本 210 条人工验证样本，全量版本 2,428 条。

### 2.5 SingProbe-Med 医疗干预
- **四个信号**：干预资格 E、全局风险 G、未来风险 F、错误边界 B。
- **准入策略**：`E → G → (F/B)` 层级，只有资格满足且全局风险或短时风险信号触发时才激活干预。
- **干预方法 sGDS**：构建医疗风险 LoRA 分支，将其作为 anti-expert；在目标模型 top-k 候选集内，用 `(1+α)ℓ_tar − αℓ_risk` 对比融合 logits，抑制风险偏好。干预可限制在最多 W 个 token 的窗口内，之后返回原生解码。

## 6. 论文的主要结论与发现

- **有效性**：仅约 2M 参数的 SingProbe 在查询意图、响应安全、幻觉检测等任务上达到或超越规模大得多的独立护栏（如 Qwen3Guard系列、YuFeng-XGuard-Reason-8B）和专用幻觉检测器（DRIFT、HaMI、SAPLMA）。
- **效率**：额外推理开销低于 0.5%（ITL），TTFT 影响在 1–2% 以内，且不随并发显著增长。
- **流式能力**：在 SingStreamBench 上，SingProbe 的 token 级 AUC 显著优于 Qwen3Guard-Stream，能更好地定位安全前缀后的风险出现点。
- **预测未来风险**：SingProbe 在安全前缀上的分数与后续生成的不安全率呈单调正相关，证明隐含状态包含未来安全倾向信息。
- **可干预性**：利用 SingProbe 分数进行分支剪枝可以将不安全率降低约 30%（剪掉 50% 分支时），接近 oracle 效果。
- **医疗扩展**：SingProbe-Med 在可忽略额外监测成本下实现选择性干预，修正约 25% 的医疗错误生成，同时保持通用能力不下降。

## 7. 优点

- **轻量高效**：内在护栏复用已有隐藏状态，几乎不增加推理开销，避免独立模型部署。
- **统一多任务**：一个头同时输出查询意图、响应安全和幻觉风险，简化系统架构。
- **流式token级监控**：支持早期干预，突破传统事后分类的局限。
- **基准创新**：SingStreamBench 专门评估安全前缀到不安全内容的过渡，弥补现有基准缺乏时序标注的不足。
- **训练策略**：自适应置信度加权巧妙利用响应级标签进行 token 级监督，减少噪声。
- **工程可落地**：已集成到 SGLang 和 vLLM，提供实际服务部署路径。
- **拓展性强**：从被动检测到主动调控（约束解码、医疗干预），展示了内部表征的多用途价值。

## 8. 不足与局限

- **跨模型泛化**：实验主要集中在 Ling-3.0 系列基座模型上，对其他架构（如不同厂商、不同训练范式的模型）的适用性尚未充分验证。
- **训练数据依赖 LLM 标注**：数据构建大量依赖开源 LLM 进行标注和验证，可能引入系统性偏差；尽管有多模型交叉验证，但仍非人类专家标注。
- **在线评估的伪标签**：留一法多数投票产生的伪标签可能不够可靠，尤其在不平衡的在线场景中，F1 绝对数值难以直接解读。
- **误报率可能被高估**：良性数据集未完全审计，FPR 只能作为“表观”误报率。
- **医疗干预风险**：SingProbe-Med 仍存在约 1.84%–2.53% 的安全响应退化（safe regression），说明选择性干预并非完全无副作用。
- **算力信息缺失**：论文未报告训练和部署的具体 GPU 资源、训练时长、能耗等，影响可复现性评估。
- **SingStreamBench 规模有限**：人工验证的核心集仅 210 个样本，虽然全量版本较大，但精细评估的规模仍偏小。
- **缺乏与更先进流式护栏的对比**：虽然对比了 Qwen3Guard-Stream，但未覆盖所有最新的流式安全方案，可能使优势评估不够全面。
