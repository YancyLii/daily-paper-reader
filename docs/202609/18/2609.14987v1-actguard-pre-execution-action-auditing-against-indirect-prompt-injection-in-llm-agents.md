## 摘要
大型语言模型（LLM）智能体通过工具调用与外部环境交互，但工具输出也可能使其面临间接提示注入（IPI）攻击。现有防御主要依赖提示词加固、内容过滤、预生成计划或权限约束。这些方法往往难以应对复杂任务，或过度净化外部内容，从而难以平衡安全性与实用性。因此，关键挑战在于保持执行灵活性的同时，精确识别并移除实际诱发不安全行为的恶意内容。为应对这一挑战，我们提出了 ActGuard，一个执行前动作审计框架。ActGuard 并非判断外部内容本身是否可疑，而是评估其是否导致当前动作偏离局部合理预期。在每一步，ActGuard 预测即将执行的动作可能使用的工具，并在不约束执行轨迹的情况下构建局部工具先验。在执行前，它将候选动作与该先验进行比较，并进行工具级对比分析和参数级证据定位，以识别工具选择和动作参数中的偏差。随后，验证器检查定位到的证据，仅屏蔽被确认为恶意的片段，并从净化后的上下文重新生成动作。这种设计在保留合法规划灵活性的同时，最大程度减少了不加区分过滤造成的信息损失。我们在面向工具使用智能体的具有挑战性的基准上评估了 ActGuard。结果表明，ActGuard 将攻击成功率降低到与最先进防御相当的水平，同时保持接近无攻击设置下的任务效用，实现了良好的安全性与实用性权衡。我们的代码已公开在：https://github.com/binzhwang/ActGuard。

## Abstract
Large language model (LLM) agents interact with external environments through tool invocation, but tool outputs can also expose them to indirect prompt injection (IPI) attacks. Existing defenses mainly rely on prompt hardening, content filtering, pre-generated plans, or permission constraints. These approaches often struggle with complex tasks or over-sanitize external content, making it difficult to balance security and utility. The key challenge is therefore to preserve execution flexibility while precisely identifying and removing the malicious content that actually induces unsafe actions. To address this challenge, we propose ActGuard, a pre-execution action auditing framework. Rather than judging whether external content is inherently suspicious, ActGuard assesses whether it causes the current action to deviate from a locally reasonable expectation. At each step, ActGuard predicts the tools likely to be used by the upcoming action and constructs a local tool prior without constraining the execution trajectory. Before execution, it compares the candidate action against this prior and performs tool-level contrastive analysis and parameter-level evidence localization to identify deviations in tool selection and action parameters. A verifier then examines the localized evidence, masks only spans confirmed as malicious, and regenerates the action from the sanitized context. This design preserves legitimate planning flexibility while minimizing information loss from indiscriminate filtering. We evaluate ActGuard on challenging benchmarks for tool-using agents. Results show that ActGuard reduces attack success rates to a level comparable to state-of-the-art defenses while maintaining task utility close to the no-attack setting, achieving a favorable security-utility trade-off. Our code is publicly available at: https://github.com/binzhwang/ActGuard.

## 2. 方法论

ActGuard 由三个核心组件构成：

- **Step-wise Planning（逐步规划）**
  - 在每一步生成当前候选动作 \( a_t = (f_t, \theta_t) \) 的同时，预测下一步可能使用的工具集合 \( F_{t+1}^{prior} \)。
  - 该先验**不是执行白名单**，仅作为下一步审计的**局部行为参考**，不约束完整执行轨迹。
  - 只预测工具名称，不预测参数，因为参数依赖当前动作的观察结果。

- **Dual-Granularity Evidence Localization（双粒度证据定位）**
  - 将历史工具输出切分为细粒度文本块（chunk），合并近似重复块，形成候选集 \( S \)。
  - **工具级对比归因**：当候选工具 \( f_t \) 不在先验集合 \( F_t^{prior} \) 中时，检索与候选动作相关的 top-k 文本块，并用如下对比归因分数衡量每个块对工具偏差的贡献：
    \[
    \Delta(s) = \frac{1}{|f_t|}\log \frac{P(f_t \mid q,H_t)}{P(f_t \mid q,H_t\setminus s)}
    -
    \frac{1}{|f_t^{prior}|}\log \frac{P(f_t^{prior}\mid q,H_t)}{P(f_t^{prior}\mid q,H_t\setminus s)}
    \]
    分数大于阈值 \( \tau \) 的块被送入验证器。
  - **参数级证据定位**：当候选工具符合先验时，攻击者可能仍篡改 URL、地址、命令等参数。ActGuard 从参数 \( \theta_t \) 中提取可检索内容，在历史观测中定位其来源块，作为参数级证据。

- **Verifier-Guided Context Sanitization（验证器引导的上下文净化）**
  - 验证器（LLM）接收用户请求、候选动作、历史观测序列以及局部证据，判断证据中是否包含 IPI。
  - 若确认存在恶意块，则仅**屏蔽被确认的片段**（替换为固定占位符），从净化后的历史重新生成候选动作，并再次审计。
  - 最多尝试 2 次修复；若无恶意证据则放行动作。

**整体流程**：预测本地工具先验 → 比较候选动作 → 证据定位（工具级或参数级）→ 验证器检查 → 选择性屏蔽 → 重新生成并再审计 → 执行。

## 3. 实验设计

- **数据集 / 基准**
  - **AgentDyn**：包含 DailyLife、GitHub、Shopping 三个套件，60 个良性任务、560 个注入案例。轨迹更长、交叉交互更多，且包含合法第三方指令，更能测试防御是否误删有用信息。
  - **AgentDojo**：包含 Banking、Slack、Travel、Workspace 四个套件，97 个良性任务、629 个安全案例。任务相对简单、轨迹较短。

- **对比方法**
  - **基于提示的方法**：Spotlighting、Prompt Sandwich、Tool Filter。
  - **基于过滤的方法**：ProtectAI、PromptGuard2、PIGuard。
  - **基于系统的方法**：Progent、CaMeL、DRIFT。

- **评估指标**
  - **NAU（无攻击效用）**：无攻击时任务完成率。
  - **UAU（攻击下效用）**：存在注入时用户任务仍能完成的比例。
  - **ASR（攻击成功率）**：攻击者目标达成的比例。

- **实现配置**
  - 后端模型：GPT-4o-mini、Gemini-2.5-Flash、DeepSeek-V4-Flash。
  - 验证器模型：GPT-4o-mini、GPT-5-mini、Gemini-3.1-Flash-Lite、DeepSeek-V4-Flash，默认 GPT-5-mini。
  - 嵌入模型：all-MiniLM-L6-v2，top-k=5；对比归因模型：Llama-3.1-8B-Instruct，阈值 τ=0。
  - 温度设为 0，使用相同基准版本和评估脚本。

## 6. 主要结论与发现

- **安全-效用平衡**：ActGuard 在 AgentDyn 上三个后端模型均将 ASR 降低到 2.14%、2.32%、0.00% 等低水平，同时 UAU 接近无攻击场景；在 AgentDojo 上取得最佳平均 UAU（59.85%）和极低 ASR（0.42%）。
- **局部先验优于全局计划**：step-wise 工具先验在不同后端和攻击下保持较高覆盖率，而 global plan 则因无法预测环境反馈而几乎失效。
- **对比归因有效**：对比归因比朴素归因显著提高召回率并降低 ASR，且性能不随模型大小单调变化。
- **验证器选择影响任务效用**：GPT-5-mini 在 ASR 与 UAU 之间取得最佳平衡；GPT-4o-mini 的假阳性更高导致 UAU 下降。
- **自适应攻击鲁棒性**：重复 payload 和针对验证器的指令均未增加 ASR；重复攻击主要降低 UAU（因重试预算耗尽）而非提升攻击成功率。
- **成本适中**：ActGuard 的额外开销低于部分系统级防御，且在安全、效用、成本之间实现更优平衡。

## 7. 优点

- **创新视角**：从“判断内容是否可疑”转向“判断内容是否诱导当前动作偏离合理预期”，更贴近实际攻击的因果影响。
- **保持灵活性**：使用局部、状态自适应的工具先验，不固定完整轨迹，支持合法重规划。
- **双粒度证据定位**：同时处理工具选择偏差和参数污染，覆盖更全面。
- **精准净化**：验证器只屏蔽确认的恶意片段，而非整个工具输出，大幅减少信息损失。
- **系统评估扎实**：跨三个后端、两个基准、多种防御与自适应攻击，并开源代码。
- **可解释的审计结果**：能返回定位到的具体源块，便于人工审查。
