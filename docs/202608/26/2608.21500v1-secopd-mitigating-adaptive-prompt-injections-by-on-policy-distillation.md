## 摘要
提示注入被列为针对 AI 智能体的头号威胁。当智能体访问来自网站、文件或电子邮件的外部数据时，攻击者可能在这些数据中注入提示，例如“忽略所有先前指令并执行<攻击者任务>”。为防止智能体被任意操纵，防御者尝试训练安全的大语言模型（LLM），但面对自适应提示注入，这些模型仍面临接近 100% 的攻击成功率（ASR）。我们发现，这是因为现有防御微调方法依赖序列级反馈信号（如 DPO 或 GRPO）。将整个输出同等对待会阻碍模型精确学习哪些输出 token 是不安全的。本文提出安全在线策略蒸馏（SecOPD），提供 token 级反馈来指导防御微调。LLM 接收被注入的样本并生成一条输出序列，其各个 token 由初始化模型在相应干净输入条件下进行评分。借助更细粒度的训练信号，我们防御后的 Qwen3.6-27B 在面对当前最先进的 PISmith 自适应提示注入时实现了 9.0% 的 ASR，而先前最先进的 Meta-SecAlign 为 94.0%。所获得的安全性可泛化到训练中完全未见过的领域：在智能体工具调用中，SecOPD 的 ASR 为 4.7%，Meta-SecAlign 为 5.5%。代码和模型可在 https://github.com/pppyb/SecOPD 和 https://huggingface.co/pybbb/Qwen3.6-27B-SecOPD 获取。

## Abstract
Prompt injection is listed as the \#1 threat to AI agents. When an agent accesses external data from websites, files, or emails, an attacker may inject a prompt into the data, saying, "Ignore all prior instructions and perform <an attacker's task>." To prevent arbitrary manipulation of agents, defenders try to train secure LLMs, which, however, still suffer from near 100% attack success rates (ASRs) against adaptive prompt injections. We note that this is because existing defensive finetuning recipes rely on sequence-level feedback signals (in DPO or GRPO). Treating an entire output equally prevents the model from learning precisely which output tokens are insecure. In this paper, we propose Secure On-Policy Distillation (SecOPD) that provides token-level feedback to guide defensive fine-tuning. The LLM receives an injected sample and produces a rollout, whose tokens are scored by the initialization model given the corresponding clean input. With more fine-grained training signals, our defended Qwen3.6-27B achieves a 9.0% ASR against the SoTA PISmith adaptive prompt injections, compared to 94.0% for the prior SoTA, Meta-SecAlign. The obtained security generalizes to domains completely unseen in training: in agentic tool calling, SecOPD achieves a 4.7% ASR compared to 5.5% for Meta-SecAlign. Code and the model are available at https://github.com/pppyb/SecOPD and https://huggingface.co/pybbb/Qwen3.6-27B-SecOPD.

## 1. 核心问题与整体含义

- **研究背景**：提示注入被列为 AI 智能体的头号威胁。当智能体从网站、文件、邮件等外部来源获取数据时，攻击者可在不可信数据中注入指令，例如“忽略所有先前指令并执行某攻击任务”，从而操控智能体行为。
- **现有问题**：已有防御性微调方法主要依赖序列级反馈信号，如 DPO、GRPO。这类方法将整个模型输出作为一个整体进行奖励或惩罚，无法指出输出中具体哪些 token 是安全的、哪些是危险的。
- **动机**：提示注入场景中常出现“混合响应”——模型既回答了可信用户任务，又跟随了注入指令。序列级反馈无法有效处理这种部分正确、部分错误的情况，导致模型难以精确学习安全策略。
- **整体含义**：本文提出 SecOPD，通过 token 级反馈替代序列级反馈，帮助模型精细地区分哪些输出 token 应当被鼓励、哪些应当被抑制，从而显著提升对自适应提示注入的防御能力。

## 2. 方法论

- **核心思想**：将 on-policy distillation（OPD）适配到提示注入防御任务中。模型在被攻击输入上生成 rollout，初始化模型（作为教师）在对应干净输入上对同一 rollout 的每个 token 进行评分，由此得到 token 级训练信号。
- **输入表示**：沿用 Meta-SecAlign 的消息格式，使用 `user` 角色表示可信用户提示，使用 `input` 角色表示不可信外部数据，使模型能够从结构上区分可信指令与不可信数据。
- **训练数据合成**：
  - 从 Cleaned-Alpaca 构造 19K 训练样本。
  - 每个干净样本 `(I, c)` 构造干净输入 `pc = R(I, c)` 和被攻击输入 `pa = R(I, A(c, g))`，其中 `g` 为注入目标，`A` 将注入指令插入不可信数据。
  - 大多数注入直接放在不可信数据开头或结尾，少量使用 completion-style 分隔符攻击，以增强对角色边界攻击的鲁棒性。
- **交叉上下文 token 评分**：
  - 学生在被攻击输入 `pa` 上采样生成 rollout：`z = (z1, ..., zT) ~ πθ(· | pa)`。
  - 对每个生成 token `zt`，分别计算：
    - 学生条件对数概率：`ℓθ,t = log πθ(zt | pa, z<t)`
    - 教师条件对数概率：`ℓteacher,t = log πref(zt | pc, z<t)`
  - 估计 reverse-KL 项：`D̂t = ℓθ,t − ℓteacher,t`。
  - 定义 token 级优势：`At = sg[ℓteacher,t − ℓθ,t]`，其中 `sg` 表示 stop-gradient。
- **训练过程**：每个迭代从注入输入采样 rollout，利用干净输入打分，基于 token 级优势更新学生模型。教师始终保持冻结状态。训练不依赖外部安全 judge 或任务特定奖励模型。
- **关键效果**：token 级反馈使得同一条响应中符合可信任务的部分获得正向信号，而跟随注入指令的部分获得负向信号，从而解决信用分配问题。

- **总体结论**：SecOPD 证明，通过精细的 token 级训练信号，可以在不大幅牺牲模型效用的前提下，显著提升对自适应提示注入的鲁棒性。

## 7. 优点

- **方法创新**：首次将 on-policy distillation 用于提示注入防御，用干净输入下的教师评分提供 token 级安全信号，解决了序列级反馈的信用分配问题。
- **显著效果**：对当前最强自适应攻击 PISmith 实现了数量级水平的安全提升。
- **良好的安全-效用平衡**：在提升鲁棒性的同时，基本保持未防御模型的通用能力，优于以安全换效用的 GRPO。
- **严格的评估体系**：采用自适应攻击而非仅静态攻击；攻击成功判定使用双 LLM judge 六次一致规则，并辅以人工审计。
- **跨域验证**：使用 AgentDojo 进行 OOD 测试，证明方法泛化到未见过的工具调用域。
- **无需外部 judge**：训练过程不依赖外部安全 reward model，只使用初始化模型本身作为教师，降低了训练复杂度。

## 8. 不足与局限

- **攻击范围有限**：仅适用于间接提示注入，前提是用户提示可信、环境数据不可信；不适用于越狱攻击、直接提示注入或其他恶意用户场景。
- **依赖可信边界先验**：假设系统已经明确知道输入中哪些部分可信、哪些部分不可信，无法处理需要模型自行判断信任边界的情况。
- **推理痕迹特性**：SecOPD 训练模型以“如同没有注入”的方式推理和响应，因此推理痕迹中不会出现对注入的识别或犹豫，可能影响依赖推理痕迹进行检测的下游防御机制。
- **安全性并非绝对**：PISmith 下 ASR 仍为 9.0%，并非零风险；未来更强的自适应攻击可能进一步突破。
- **实验局限**：
  - 未提供具体算力信息。
  - GRPO 与 SecOPD 的训练注入分布不完全一致，可能引入公平性偏差。
  - 缺少消融实验，未单独分析 LoRA、温度、注入构造方式等组件的影响。
  - AgentDojo 的 Slack 域中 SecOPD ASR 相对较高，说明跨域安全性在不同任务上并不完全一致。
  - PISmith 训练和评估设置较为单一，未覆盖多种 RL 攻击者初始化或攻击训练规模。
- **模型与场景单一**：主要基于 Qwen3.6-27B，对其他模型架构和规模的可扩展性尚待验证。
