## 摘要
部署在车辆中的大语言模型（LLM）智能体必须在每一轮交互中满足书面运行策略：一个幻觉出的标识符、遗漏的强制副作用或过早的完成声明都会导致任务失败。我们提出 AgentGuardUtil，这是我们参加 CAR-bench Track 1 的方案，它将 AI 规划器（LLM）视为在有依据的“验证—修订”循环中的一个易出错提议者。其核心创新是一个运行时策略编译器：随每次对话提供的自然语言策略会被编译为类型化、机器可检查的规则，每个策略仅编译一次，其中一部分规则还会获得可执行形式。一个确定性义务引擎根据实时工具结果以及草稿本身的模拟写入后状态来解释这些规则，并发出带有计算参数的确切补救调用，而非自然语言提醒。在该引擎周围，25 个确定性门（标识符来源、模式和枚举有效性、先收集后行动、确认与未来时间协议）以及一个 LLM 批评器产生分级发现，驱动一个有界修订循环，并针对 pass@k 指标进行了调优。

## Abstract
Large Language Models (LLMs) agents deployed in vehicles must satisfy a written operating policy on every turn: a single hallucinated identifier, omitted mandatory side-effect, or premature completion claim fails the task. We present AgentGuardUtil, our entry to CAR-bench Track~1, which treats the AI planer (LLM) as a fallible proposer inside a grounded verify-and-revise loop. Its core novelty is a runtime policy compiler: the natural-language policy shipped with each conversation is compiled, once per policy, into typed machine-checkable rules, a subset of which receive an executable form. A deterministic obligation engine interprets these rules against live tool results and the simulated post-write state of the draft itself, emitting the exact remedial calls with computed arguments rather than natural-language reminders. Around this engine, 25 deterministic gates (identifier provenance, schema and enum validity, gather-before-act, confirmation and future-time protocols) and an LLM critic produce tiered findings that drive a bounded revision loop tuned for the pass k metric.

## 1. 论文的核心问题与整体含义

- **研究背景与动机**：车载 LLM 智能体需要在每一轮交互中严格遵循书面运行策略（如安全规则、副作用要求、确认协议等）。一个幻觉标识符、遗漏强制副作用或过早声称完成都可能导致任务失败，甚至引发安全事件。  
- **核心问题**：如何将自然语言策略可靠地转化为可执行的约束，并对 LLM 提议的动作进行确定性验证，从而提高车载 LLM 智能体的可靠性与策略合规性。  
- **整体含义**：论文提出 AgentGuardUtil，将 LLM 规划器视为“易出错的提议者”，嵌入一个**有依据的验证—修订循环**中，由确定性“教师”来裁决每个草稿动作，从而在动作执行前拦截错误。

## 2. 论文提出的方法论

### 2.1 总体架构
- 系统采用**学生—教师分解**：LLM 学生只负责提议动作；确定性验证框架（教师）负责审查每个草稿，返回具体发现，并在动作到达模拟驾驶员前进行修订和再验证。  
- 设计遵循**假设—保证**思想：教师仅假设学生“有能力但易错”，并将策略合规性、数据基础等保证通过确定性检查来承担，不依赖学生行为。

### 2.2 运行时策略编译
- 在对话首轮，将自然语言策略 `Π` 编译为类型化、机器可检查的规则集 `R`，并按策略哈希缓存。  
- 每条规则 `r = ⟨id, κ, Tr, ρ⟩` 包含类型 κ（前置条件、自动动作、确认、禁止、披露、约束、选择等）、触发工具 `Tr` 和命令式要求 `ρ`。  
- 复合条款被拆分为原子规则（一个条件、一个补救措施）。  
- 第二遍将状态条件规则转化为**可执行形式**：`er = g, φ, ◁, v, ω`，其中 `g` 是读取工具，`φ` 是字段名模式（含一个通配符），`◁` 是比较运算符，`v` 是阈值，`ω(x)` 是将匹配项 `x` 绑定到工具 `u` 参数的义务模板。

### 2.3 确定性义务引擎
- 对每个草稿动作，引擎回答：基于已观察到的环境和当前提议的动作，策略还要求哪些进一步动作？  
- **步骤 1**：估计动作后环境状态。将历史观察与草稿中提出的动作按顺序模拟，得到投影状态 `ˆσ`；可预测效果的动作直接设置状态变量，不可预测或失败的动作将相关变量标记为未知。  
- **步骤 2**：计算缺失动作。规则 `r` 处于活跃状态当且仅当其触发工具已使用或出现在草稿中。对每个违反规则条件的实体 `x`，填充动作模板 `ω(x)`，并移除已执行或已在草稿中的动作，得到仍需执行的集合 `Ω`。  
- **步骤 3**：匹配期望粒度。若所有实体都违反条件且工具支持 `ALL` 参数，则将逐实体动作合并为一个集合动作；同时检查多余动作。

### 2.4 分层验证与方差控制
- 围绕义务引擎有 **25 个确定性门**，每个门检查草稿必须遵守的协议，并从对话历史、工具模式和先前观察中可判定。  
- 重要门包括：**标识符来源**（标识符必须来自先前观察，否则阻止调用）、**模式有效性**（参数必须符合工具声明的类型与枚举值）、**先收集后行动**（规则条件依赖的观察必须已进行）、**确认协议**（需用户同意的动作必须找到肯定确认）、**完成声明**（声称已完成的动作必须确实执行或出现在草稿中）、**拒绝读取**（在声称无法执行前必须先调用读取工具）、**未来条件**（对未来的查询必须使用未来时刻的未过滤数据）。  
- 每个门返回**硬发现**（直接触发修订）或**咨询候选**（由 LLM 批评器确认或丢弃，但批评器不能添加新发现或推翻硬发现）。  
- 存在**振荡阀**：若发现要求重新执行学生已修订掉的动作集，则丢弃该发现并放宽收集门，防止无限循环。  
- 修订循环有界，最多 `R` 轮；若修订后仍有硬发现，则执行一次安全网修订；最后进行清理（去除无法朗读的标记）。

## 6. 论文的主要结论与发现

- AgentGuardUtil 在 CAR-bench Track 1 上**全面优于基线**：Pass 3 为 **53.3%**（基线 50.0%），Pass@3 为 **80.0%**（基线 66.7%），Pass 1 为 **66.7%**（基线 60.0%）。  
- **Pass@3 增益较大（+13.3 点）**，而 Pass 3 增益较小（+3.3 点），说明系统能**让较好的尝试更好**，但无法让多次尝试更一致。  
- 分类别表现：  
  - **幻觉类最佳**：Pass@3 达 100.0%，因为标识符来源和模式检查是简单、确定的事实核查。  
  - **基础策略类**：Pass@3 为 60.0%，Pass 3 为 60.0%。  
  - **歧义消解类最差**：Pass@3 为 80.0%，Pass 3 为 50.0%，Pass 1 为 40.0%；代码无法判断“是否应该提问”，这一任务依赖 LLM 批评器，而批评器并非总是正确。  
- 主要损失来自 **Pass@3 与 Pass 3 的差距**：8 个任务在部分尝试中成功但未能在全部三次中成功，原因在于学生的稳定性不足，且当没有编译规则覆盖任务时，检查静默。  
- 系统**较慢且昂贵**：token 和耗时约为基线的 4.4 倍和 6 倍，但全领域 token 消耗与得分相关性不强（r=0.435）。

## 7. 优点

- **确定性优先**：将关键检查从 LLM 中移出，放入代码中，避免模型幻觉绕过验证；硬发现不可被 LLM 批评器推翻，保证系统行为可预测。  
- **运行时策略编译**：将自然语言策略一次性编译为可执行规则，支持基于实时工具结果的精确补救调用（带计算参数），而非模糊提醒。  
- **投影状态模拟**：在评估规则时考虑草稿自身写入后的状态，能发现草稿动作本身会制造的违规。  
- **分层发现机制**：硬发现与咨询候选分离，LLM 批评器仅能过滤咨询候选，不能添加或覆盖，降低模型方差影响。  
- **有界修订与振荡阀**：防止无限循环，并在多门冲突时通过振荡阀避免来回拉锯。

## 8. 不足与局限

- **实验覆盖有限**：仅在一个 benchmark（CAR-bench）上评估，且未进行跨领域或真实车载环境验证。  
- **缺乏消融研究**：无法确定各模块（义务引擎、25 个门、批评器、模态投票等）的具体贡献。  
- **依赖 LLM 进行策略编译和批评**：策略编译可能出错或遗漏，批评器在歧义消解等任务上表现不稳定。  
- **高成本与延迟**：单轮 19.2 秒、362k tokens 的开销对于实时车载交互可能不可接受。  
- **Pass 3 提升有限**：系统只能修正确定性错误，无法提升学生模型在多次尝试间的一致性；当策略未被编译为可执行规则时，检查静默。  
- **可扩展性存疑**：25 个确定性门和编译步骤针对特定领域（车载）设计，迁移到其他领域需要重新定义门和规则类型，且未展示对策略变更的鲁棒性。
