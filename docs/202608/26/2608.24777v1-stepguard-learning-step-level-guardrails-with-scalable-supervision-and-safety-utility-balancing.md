## 摘要
基于大语言模型的智能体能够通过工具调用与外部环境交互，但这一能力也引入了文件修改、信息泄露和未授权操作等安全风险。现有护栏通常评估已完成的轨迹，对步骤级动作执行前的监控尚未充分探索。我们提出 StepGuard，一种步骤级护栏模型，能够审计已完成的智能体轨迹，并在工具动作执行前对其进行检查。为训练 StepGuard，我们引入 StepGen，一个自动数据引擎，可在风险步骤处生成上下文相同但动作不同的安全与不安全轨迹。为进一步减少过度防御和防御不足，我们提出 Balance-GRPO，根据观察到的准确率动态平衡安全与不安全动作之间的学习。实验表明，StepGuard 在开放权重护栏模型中取得了最高的平均准确率，性能与 GPT-5.4 相当。在 AgentDojo 和 AgentDyn 上用于防护智能体时，StepGuard 相较于无护栏设置将平均攻击成功率降低了 77.3%，而平均效用仅下降 2.8 个百分点。

## Abstract
LLM-based agents can interact with external environments through tool invocation, but this capability also introduces security risks such as file modification, information leakage, and unauthorized actions. Existing guardrails often evaluate completed trajectories, leaving pre-execution monitoring of step-level actions underexplored. We propose StepGuard, a step-level guard model that can audit completed agent trajectories and check tool actions before they are executed. To train StepGuard, we introduce StepGen, an automatic data engine that generates safe and unsafe trajectories with the same context but different actions at the risky step. To further reduce over-defense and under-defense, we propose Balance-GRPO, which dynamically balances learning between safe and unsafe actions based on their observed accuracy. Experiments show that StepGuard achieves the highest average accuracy among open-weight guard models, with performance comparable to GPT-5.4. When used to guard agents on AgentDojo and AgentDyn, StepGuard reduces mean attack success rate by 77.3% relative to the no-guard setting, while mean utility drops by only 2.8 percentage points.

## 2. 方法论

### 2.1 任务建模

- 智能体在多步“推理—行动”循环中执行用户请求。每个时间步有动作 \(a_{i,t}\)，执行后得到观察 \(o_{i,t}\)。
- 护栏模型 \(G_\theta\) 对执行上下文 \(X\) 输出结构化诊断：
  - 安全判断：safe / unsafe；
  - 风险源是否存在；
  - 风险源类型；
  - 可选的定位到不安全步骤。
- 输入 \(X\) 可以是完整轨迹，也可以是当前前缀 + 候选动作，用于执行前检查。

### 2.2 StepGen：前缀对齐数据引擎

StepGen 用于自动生成具有步骤级监督的安全/不安全对比轨迹，主要流程如下：

1. **风险锚定规划**：
   - 采样风险源 \(r\)、失败模式 \(f\)、危害类型 \(h\)，以及工具子集 \(T\)。
   - 规划器生成一个包含不安全锚点 \(i^*\) 的执行计划。
   - 只有存在唯一不安全锚点的计划才会保留，否则重采样。

2. **轨迹 roll-out**：
   - 按照计划逐步生成 agent 思考、工具调用和模拟环境反馈。
   - 对基于响应的风险（如间接提示注入、损坏工具反馈等），在锚点步骤注入风险扰动，确保 \(i^*\) 对应第一个不安全决策。

3. **前缀对齐对比分支**：
   - 在风险锚点之前的前缀保持不变，仅重新生成锚点之后的后缀。
   - 生成两种安全分支：
     - **Refuse**：拒绝危险动作；
     - **Aware**：识别风险后通过安全替代方案继续完成任务。
   - 同时生成独立的 **benign tool-reuse trajectory**：在无对抗场景下复用相同工具子集，防止模型仅凭工具身份就判断不安全。

4. **步骤级标注与质量控制**：
   - 每个动作标注 Safe/Unsafe 标签和结构化解释。
   - 使用机械验证器 \(\phi_{\text{mech}}\) 检查轨迹结构、工具调用格式、参数溯源等。
   - 使用 LLM 审计器 \(\phi_{\text{qual}}\) 评估语义一致性、锚点正确性、场景合理性等，得分超过阈值 \(\eta\) 才保留。

### 2.3 冷启动 SFT

- 以 **Qwen3-4B-Instruct** 为基座，使用 StepGen 生成的 3K 示例进行监督微调。
- 输入为完整轨迹或候选动作上下文；输出包括安全标签和风险类别，不安全时还定位不安全步骤并解释原因。
- 使用 **GPT-5.4** 根据 StepGen 标注生成目标回答，丢弃与标注不一致的样本。
- 使用 token 级交叉熵损失训练。

### 2.4 Balance-GRPO

- **动机**：SFT 检查点存在明显过度防御，safe 类准确率显著低于 unsafe 类。
- **结构化奖励**：
  \[
  r_{i,j}=0.5 \cdot \mathbb{I}[\hat Y_{i,j}=Y_i] + 0.5 \cdot \mathbb{I}[\hat Y_{i,j}=Y_i]\cdot \mathbb{I}[\hat R_{i,j}=R_i]
  \]
  即安全判断正确得一半分，风险类别也正确再得一半分。
- 在 GRPO 标准化优势 \(A_{i,j}\) 的基础上进行重加权：
  - **类计数修正** \(c_i\)：根据批次中安全/不安全样本数量进行加权，弥补类别不平衡。
  - **准确率差距权重** \(\omega_i\)：
    - 计算 \(\Delta_{\text{cls}}=\text{Acc}_{\text{safe}}-\text{Acc}_{\text{unsafe}}\)；
    - 若 safe 类更差，则提高 safe 样本权重；若 unsafe 类更差，则提高 unsafe 样本权重。
  - 最终平衡优势：
    \[
    A'_{i,j}=c_i\omega_i A_{i,j}
    \]
- 训练目标为标准 clipped GRPO 加 KL 正则项。关键超参：\(\lambda=2.0\)，死区 0.02，有效权重范围 \([0.75,1.5]\)。
