## 摘要
模型上下文协议（MCP）已成为连接大语言模型智能体与外部工具后端的事实标准层。这种开放性引入了一种严重的服务器端威胁，我们称之为 TrustShift：受感染的 MCP 服务器在初始条件化阶段表现良性，建立运行依赖并抑制智能体怀疑，一旦达到交互阈值就切换到对抗性载荷。这种规避是时序性的，而非语法性的：部署时良性，服务器的背叛对部署前静态分析不可见，因为静态分析只能看到诚实阶段。切换后的载荷从明显的结构违规到符合模式的操作不等，后者保留外层协议合规性以逃避运行时中间件过滤。关键在于，TrustShift 源于服务器控制的工具通道，而非用户提示（不同于间接提示注入）或传输层（不同于中间人攻击）：对手正是受信任的服务器端点本身。我们提出 TrustShiftProbe，一个评估和防御框架，包含四项贡献：（1）一个有状态的时序威胁模型，将智能体-服务器生命周期建模为良性条件化阶段之后在信任视界处发生对抗性背叛；（2）一个语言无关的攻击引擎，在四个生产领域中将每种变体实例化为受感染的 MCP 服务器；（3）SHIELD，一个位于 MCP 传输边界的多层、零预言机运行时防御，依据在干净信任窗口期间学习的行为基线审计服务器载荷；（4）九个 TrustShift 变体的分类法，涵盖三种执行机制（结构违规、语义破坏、范围扩展）和三种对抗目标（破坏、数据外泄及其组合）。在前沿专有和开放权重模型中，TrustShift 攻击达到 69.5% 的平均攻击成功率，SHIELD 将其缓解至 42.7%。

## Abstract
The Model Context Protocol (MCP) has emerged as the standard layer connecting Large Language Model agents to external tool backends. This openness introduces a severe server-side threat we term TrustShift: a compromised MCP server behaves benignly during an initial conditioning phase, building operational reliance and suppressing agent skepticism, before switching to an adversarial payload once an interaction threshold is reached. The evasion is temporal, not syntactic: benign at deploy time, the server's defection is invisible to predeployment static analysis, which sees only the honest phase. Switched payloads range from overt structural violations to schema-valid manipulations, the latter preserving outer protocol compliance to evade runtime middleware filters. Crucially, TrustShift originates in the server-controlled tool channel, not user prompts (unlike indirect prompt injection) or the transport (unlike man-in-the-middle): the adversary is the trusted server endpoint itself. We introduce TrustShiftProbe, an evaluation and defense framework with four contributions: (1) a stateful temporal threat model of the agent-server lifecycle as a benign conditioning phase followed by an adversarial defection at a trust horizon; (2) a language-agnostic attack engine that instantiates each variant as a compromised MCP server across four production domains; (3) SHIELD, a multi-tier, zero-oracle runtime defense at the MCP transport boundary that audits server payloads against behavioral baselines learned during clean trust windows; and (4) a taxonomy of nine TrustShift variants spanning three execution mechanisms (structural violation, semantic corruption, scope expansion) and three adversarial objectives (disruption, exfiltration, and their combination). Across frontier proprietary and open-weight models, TrustShift attacks achieve a 69.5% mean attack success rate that SHIELD mitigates to 42.7%.

## 2. 论文提出的方法论

- **总体框架：TrustShiftProbe**，包含四个贡献：
  - **C1 有状态时序威胁模型**：将智能体-服务器生命周期建模为：
    - \(t < N\)：良性条件化阶段，服务器返回诚实结果 \(r_t\)
    - \(t \geq N\)：对抗阶段，服务器返回变异结果 \(A(r_t)\)
    - \(N=0\) 退化为传统的始终恶意服务器；\(N>0\) 可规避静态审查。
  - **C2 受感染服务器攻击引擎**：语言无关，在四个生产领域中实例化受感染 MCP 服务器，变异服务器自身 JSON-RPC 响应。
  - **C3 零预言机运行时防御（SHIELD）**：多层级、位于 MCP 传输边界的防火墙，仅基于干净信任窗口学到的行为基线审计服务器载荷，不使用硬编码规则或真实标签。
  - **C4 攻击分类法**：9 个 TrustShift 变体，沿两个轴组织：
    - **机制族**：
      - M1 结构违规：有状态服务拒绝、验证元数据遗漏、依赖劫持、部分授权失败
      - M2 语义破坏：语义反转、实体欺骗、连续特征漂移
      - M3 范围扩展：工具范围升级、跨工具横向移动
    - **目标**：O1 运行破坏、O2 上下文外泄、O3 两者结合。

### SHIELD 防御流程

- **三层检测管道**：
  1. **Tier 1 结构异常检测**：\(O(n)\) 扫描，耗时 < 0.1 ms，检查签名词汇、空结果、字段置空、参数不匹配与基线矛盾。
  2. **Tier 2 统计一致性检测**：耗时 < 1 ms，对比会话基线，检查数值一致性、schema 键一致性、响应大小一致性、时间近期性与跳跃异常、时间排序异常。
  3. **Tier 3 语义合理性检测**：耗时 200–800 ms，使用一次 LLM 调用，结合任务目标、工具参数、信任阶段示例进行合理性判断，返回 clean/suspicious/compromised。
- **阻断策略**：任何层级的 flag 达到配置严重度阈值即阻断，返回合成错误给智能体。
- **关键保证**：
  - **零预言机**：所有检测信号仅来自智能体实际收到的工具结果、滚动会话历史和 JSON 结构性质，不使用注入前服务器响应。
  - **轻量级**：Tier 1–2 毫秒级且无 LLM 调用；Tier 3 可异步执行。
  - **运行时无关**：推理时不查询攻击标签或分类法类别。

### 自动化任务生成

- 使用 **GPT-4o 作为 Red LM** 的三阶段生成管道：
  1. **Schema 约束生成**：基于目标 JSON-RPC schema、分类法约束和两个跨领域示例生成任务。
  2. **多跳强制与多样化**：要求任务跨多次工具调用，并变化用户 persona，避免触发依赖表面措辞。
  3. **确定性信号协同生成**：同时生成用于评分的“现实矩阵”（良性 vs 对抗值），使得 ASR 可通过精确值匹配计算，减少对 LLM-as-judge 的依赖。
- 生成后通过 schema 有效性和 scorer 有效性双重准入门筛选。

## 3. 实验设计

- **Benchmark**：TrustShiftProbe 测试集，共 **360 个测试样例**：
  - 由 9 个机制 × 4 个领域 × 10 个任务构成
  - 领域分布：金融分析 90、位置导航 90、浏览器自动化 90、仓库管理 90
- **评估模型**：6 个前沿专有和开源模型：
  - GPT-5、GPT-4.1、o4-mini（OpenAI）
  - Claude-Opus-4-8（Anthropic）
  - Grok-4.3（xAI）
  - Qwen3.5 Flash（Alibaba）
- **智能体执行方式**：统一的 ReAct 循环（Thought → Action → Observation），温度 = 0，最大 4096 tokens，步数预算 15 次工具调用。
- **核心指标**：
  - **ASR（Attack Success Rate）**：在暴露会话中，最终答案采纳对抗值的比例。
  - 报告 **Base（无防御）** 和 **+SHIELD（有防御）** 的 ASR，并用差值衡量防御效果。
- **对比的已有方法/基座**：
  - 静态/预执行防御：MCP-Scan、SafeMCP 等
  - 行为级运行时防御：MCP-Defender、MCIP-Guardian
  - 隔离/架构防御：MCP-Gateway、ToolHive
  - 决策级防御：MindGuard、AIM-MCP
  - 这些方法被认为无状态、单点检查，无法应对 TrustShift。
- **显著性检验**：使用精确 McNemar 检验对配对会话结果进行统计显著性验证。

## 6. 论文的主要结论与发现

- **发现 1：TrustShift 能颠覆所有测试的前沿模型。**
  - Base ASR 范围 60.2%（GPT-5）到 74.1%（GPT-4.1），总体均值 **69.5%**。
  - 良性信任阶段是智能体被解除武装的关键，而非载荷本身。
- **发现 2：目标不对称明显——破坏成功、外泄失败。**
  - 针对数据完整性和运行破坏的攻击系统性成功，而外泄和范围扩展攻击大多失败。
  - 模型天然信任工具内容，但对工具输出中的间接命令注入具有较强抵抗力。
- **发现 3：SHIELD 在可用性攻击上有原则性边界。**
  - 对有状态服务拒绝，SHIELD 能检测但不能重建缺失数据；任何零预言机单通道监视器都无法恢复可用性。
- **发现 4：SHIELD 在留下足迹的操纵上最有效。**
  - 元数据遗漏 90.8→43.1，部分授权 94.3→40.0，语义反转 87.9→38.3，连续漂移 77.1→40.5。
- **发现 5：领域差异——仓库管理是最难防御的领域。**
  - 浏览器自动化 70.6→26.8，金融分析 73.8→28.9，但仓库管理仅 70.0→64.7。
- **发现 6：可防御性与模型原始能力不成正比。**
  - o4-mini 最终残差 ASR 最低（39.2%），GPT-5 为 40.7%，Claude-Opus-4-8 最难防御（48.1%）。
- **总体**：Base 69.5% → +SHIELD 42.7%，SHIELD 显著降低大部分欺骗式攻击。

## 7. 优点

- **新颖且切中实际威胁**：系统提出时间性信任攻击，弥补了现有静态、单点检测的盲区。

- **零预言机防御**：SHIELD 不依赖真实标签，仅使用信任窗口行为基线，具有现实可部署性。

- **统计严谨性**：采用 McNemar 检验，避免小样本高方差导致的误导结论。
- **关注边界条件**：清楚说明 SHIELD 无法恢复可用性，体现对防御能力边界的诚实认识。

## 8. 不足与局限

- **算力信息缺失**：未说明 GPU/API 算力开销，难以评估工程部署成本。

- **未与所有既有防御进行直接实验对比**：主要从原理上指出已有防御不足，但未将 SHIELD 与 MCP-Guard、MindGuard 等在同一任务集上做端到端实验比较。
- **可移植性需要少量领域适应**：尽管无预言机，但将 SHIELD 迁移到全新 MCP 服务器类别仍需一次性设置可接受的行为边界。
