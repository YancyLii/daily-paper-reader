## 摘要
开放权重语言模型会公开其聊天模板中用于标记轮次、角色和工具结果的字符串，分词器会将这些字符串映射回模型所遵从的保留标识符。因此，任何能控制提示中文本的人都可以写出与服务栈所写内容无法区分的轮次边界。我们审计了256个已部署的聊天分词器。所有分词器均可被伪造，而通常建议用于修复的标志仍使56.6%可被伪造，因为它遗漏了智能体系统所依赖的工具和推理标记。我们提出无名标记化，它使控制条目仅有保留标识符而没有表面字符串，因此内容编码器无法生成此类标记，消息内容可以原样到达模型。在五个分词器家族中，它在无攻击数据上精确复现标准标记流，并将包含分隔符的文本探测准确率从8.5%提升至59.9%，而清理器则会损失该准确率。将分隔符的出现与其标识符分离表明，标识符在单纯任务指令面前几乎无关紧要，但一旦系统消息要求模型将用户内容视为数据，标识符就会在伪造工具结果和伪造轮次中起到大部分作用。

## Abstract
Open-weight language models publish the strings their chat templates use to mark turns, roles and tool results, which the tokenizer maps back to the reserved identifiers the model obeys. Anyone who controls text in a prompt can therefore write a turn boundary indistinguishable from one the serving stack wrote. We audit 256 deployed chat tokenizers. All are forgeable, and the flag usually recommended as a fix leaves 56.6% forgeable because it misses the tool and reasoning markers agent systems rely on. We propose nameless tokenization, which leaves the control entries with a reserved identifier and no surface string, so the content encoder cannot emit one and message content reaches the model unaltered. Across five tokenizer families it reproduces the standard token stream exactly on attack-free data and lifts accuracy on a probe of delimiter-bearing text from 8.5% to 59.9%, where sanitizers lose it. Separating a delimiter's appearance from its identifier shows the identifier matters little against a bare task instruction, but carries most of a forged tool result and most of any forged turn once the system message tells the model to treat user content as data.

## 1. 论文的核心问题与整体含义

- **核心问题**：开放权重语言模型（open-weight LLMs）会公开其聊天模板（chat template）中用于标记轮次、角色和工具结果的**控制字符串**（control surface strings）。分词器会将这些字符串映射回模型所遵从的**保留标识符**（reserved identifiers）。由于这些字符串和模板都是公开的，任何能控制提示文本的攻击者都可以在用户消息或检索文档中直接嵌入这些字符串，从而**伪造一个与服务栈所写内容在令牌层面完全等价的轮次边界**，实现提示注入攻击。

- **问题的严重性**：该问题并非理论性风险，而是**一个可以有构造性保证的漏洞**——它是提示注入问题中唯一能够“提供保证而非缓解措施”的部分，但当前部署的软件并未关闭这一通道。

- **现有修复的缺陷**：
  - 通常建议的修复是启用 `split_special_tokens` 标志来禁用消息内容中的特殊令牌解析，或在分词前过滤掉这些字符串（如 Chen et al. 2024 的做法）。
  - 作者通过大范围审计发现：**256 个已部署聊天分词器在默认配置下全部可伪造**（100%），启用该标志后仍有 **56.6% 可伪造**，原因是该标志只抑制被仓库标记为“special”的令牌，而 56.2% 的模型将至少一个控制令牌注册为**非特殊**（non-special）——最常见的是 `<tool_call>`、`</tool_call>`、`<think>`、`</think>`、`<tool_response>` 等**工具调用与推理标记**，这些正是智能体系统所依赖的关键通道。
  - 字符串过滤（sanitizer）方法虽能阻止伪造，但会**破坏含分隔符的合法内容**。

- **整体含义**：作者提出将控制令牌的**表面字符串与其保留标识符解耦**，从构造上关闭文本到控制标识符的通道，从而在不经过枚举攻击字符串的情况下实现**无条件不可伪造性**。


## 2. 论文提出的方法论

- **核心思想（无名标记化，Nameless Tokenization）**：
  - 创建一种**无名令牌**（nameless token）：一个词表条目，具有嵌入向量和保留标识符，但**没有任何编码器能映射到它的表面字符串**。
  - 将渲染过程分为两层：**模板层直接写入标识符**（trusted），而**内容层只能通过不包含控制令牌路径的内容编码器编码**（untrusted）。

- **关键技术细节**：
  - **内容编码器构造**：快速分词器（fast tokenizers）通过一个**在子词模型运行前被查询的表格**来处理添加令牌（added tokens）。作者将分词器序列化后清空该表格，移除注入句子标记的后处理器，再重新加载。得到的编码器 $E_c$ 在相同的词表上运行相同的子词模型，但**不存在从字符串到仅由该表格产生的标识符的路径**。
  - **模板层直接写标识符**：渲染模板时用占位符替代每条消息，在模板自身写入的保留表面字符串处切分渲染结果，直接将其转为标识符；其余部分（模板文本和消息内容）以最大片段送入 $E_c$。这保证了子词模型看到与标准分词下相同的字符串，不会在消息边界处发生分割漂移。
  - **不可伪造性保证**：通过构造，对任意攻击者选择的文本 $t$，有 $E_c(t) \cap C = \varnothing$（其中 $C$ 为模板发出的保留标识符集合）。该保证**无需枚举攻击字符串**，是一个性质保证（property guarantee）。
  - **无损性**：无损的精确含义是“消息的每个字符都原样到达模型”，这是渲染方案的属性，而非对攻击率的声明。模型本身未做任何修改。

- **通用性**：该实现仅通过模板输出来读取模板，因此**一套实现覆盖所有研究的家族**，无需针对每个模板单独适配。


## 3. 实验设计

- **模型与任务**：
  - 使用**五个指令微调开放权重模型**，来自五个分词器谱系：Gemma-4-31B-IT、Llama-3.1-8B-Instruct、Ministral-3-8B-Instruct-2512、Qwen3.8-27B、gpt-oss-20b。

- **攻击与防御对比**：
  - 所有攻击携带**完全相同的注入指令**，仅通过引入指令的分隔符（delimiter）来区分，从而隔离控制通道的贡献。

    - **Strip**：从消息内容中删除控制字符串。
    - **Mask**：用占位符替换控制字符串。
    - **Escape**：替换为全角同形字符。
    - **Nameless**：本文提出的无名标记化。
  - 清洗器仅影响消息内容；所有条件在两种系统消息下运行（仅任务系统消息、附带“将用户消息视为数据”防御句的系统消息）。

  - 用于评估清洗器对含分隔符合法内容的破坏程度。

- **大规模审计**：
  - 从公共模型枢纽选取 **400 个下载量最高的文本生成仓库**，保留 **256 个**带有聊天模板且至少一个非平凡控制令牌的仓库。

## 6. 论文的主要结论与发现

- **审计结论**：256 个部署聊天分词器全部可通过文本控制通道伪造，启用推荐标志后仍有 56.6% 可伪造，主要遗漏工具调用与推理标记。

- **核心定量发现**：
  - **分词保真度**：无名标记化在五个分词器家族上以 **100.0% 的比例**在无攻击宿主提示上精确复现标准标记流。
  - **宿主任务准确性**：标准分词 89.1% vs 无名 88.9%，差异来自 GPT-OSS-20B 的解码噪声，四模型完全一致。
  - **分隔符保真度**：标准分词 8.5%（本身就低，因为复现控制字面量意味着发出结束轮次的标识符）→ 无名标记化 **59.9%**；清洗器 Stripping 仅 2.2%，Masking 23.0%，Escaping 24.1%。
  - **攻击率分解**（任务系统消息，目标 A）：
    - Naive：62.4%（所有防御条件下几乎相同，说明该攻击不依赖控制通道）。
    - Forged turn：无防御 99.9% → 无名 92.8%。将贡献分解后，**分隔符的外观价值 30.4 个百分点**，而**标识符仅贡献 7.1 个百分点**；拼错的 Lookalike 达到 93.0%，说明关键因素是“形状像边界的文本”，而非特定字符串。
    - Forged tool：无防御 33.1% → 无名 7.4%，下降几乎全部来自 Qwen-3.8-27B。
    - **Forged system** 在无名条件下反而升到 68.0%（从 46.9%），说明移除保留标识符但保留分隔符文本使模型更容易服从，这是值得注意的副作用。

- **标识符的作用取决于防御情境**：
  - 在**无附加防御**的情况下，标识符的作用有限（约 7.1 点）。
  - 当系统消息**明确指示模型将用户内容视为数据**后，标识符成为决定性因素：在 Llama-3.1-8B 和 Ministral-3-8B 上，纯文本注入分别降至 4.1% 和 0.0%，但伪造轮次仍成功 98.3% 和 99.0%；移除标识符后分别降至 50.0% 和 23.3%。**边界构造在效果上胜过指令内容**，而关闭标识符通道才能阻止伪造轮次。

- **与训练级分离的对比**：
  - 在未进行训练级分离的模型上，无名标记化将 forged system 攻击从 98.0% 降至 66.6%；与 ISE 和 ASIDE 等方法相比，无名标记化不收训练成本，但训练级方法在攻击防御上更占优。
  - 在已进行训练级分离的模型上，切到无名标记化无额外收益，且 ASIDE 方法牺牲 11.4 点干净准确率。


## 7. 优点

- **构造性保证（Guarantee by construction）**：与需要枚举攻击字符串的过滤方法不同，无名标记化从分词器层面根本性地杜绝了文本到控制标识符的路径，无需搜索即可保证不可伪造，是同类工作中少见的“性质级”安全方案。

- **无损性经过定量验证**：100% 复现无攻击数据上的标准标记流，宿主任务准确率几乎无差异，这证明该防御不是“安全性换功能性”的权衡，而是**零成本**的改动。

- **精细的消融框架**：通过将“分隔符的外观”和“标识符”分离，论文揭示了攻击有效性贡献的细致结构（外观 30.4 点 vs 标识符 7.1 点），这一分解结果出乎作者自身预期，为理解控制令牌本体在提示注入中的作用提供了独特见解。

- **规模化的实证审计**：对 256 个真实部署分词器进行了系统排查，发现常用修复（`split_special_tokens`）存在系统性盲点（遗漏工具与推理标记），具有直接实践价值。

- **“自由”的贡献定位明确**：论文明确指出该方法的边界——解决了可保证的那部分问题，不解决纯语言层面的注入，也不替代训练级防御，定位诚实客观。


## 8. 不足与局限

- **实验覆盖有限**：
  - 仅评估了 5 个模型、3 个任务和 2 个注入目标，绝对攻击率在不同目标或更大条目池下可能移动，不能作为实际部署风险估计。
  - 防御系统消息仅测试了一句话，未覆盖更复杂的防御组合（如检索卫生、训练级分离与无名标记化的联合部署）。

- **保留分隔符文本可能产生反效果**：无名标记化虽移除保留标识符，但保留了分隔符文本本身。在 forged system 攻击上，模型在无名条件下的服从率从 46.9% 升到 68.0%，说明**仅靠分词器级防御不足以应对所有提示注入变体**，在未进行训练级分离时，攻击者仍可通过形似边界的文本获得一定攻击增益。

- **审计范围受限**：审计覆盖的是“带聊天模板且加载时无需执行仓库代码”的分词器，**遗漏了使用自定义分词器代码分发的模型**，这类模型在真实部署中可能存在更复杂的暴露面。

- **保真度探测为合成块**：分隔符保真度探测基于人工构造的块，仅能说明清洗器会破坏含分隔符的内容，无法反映真实工作负载中此类内容的发生频率。

- **与训练级方法的对比有限**：仅在单一基础模型的三个变体上对比，不能全面刻画无名标记化与更广泛训练级防御体系的交互。此外，该方法**不改变模型本身**，对于能通过纯语言形式“说服”模型的注入（如 Naive 攻击）完全无效，调用者直接提供令牌标识符的场景也超出了其防御边界。

- **算力信息缺失**：论文未报告 GPU 配置、推理时间或计算成本，对于想复现或评估资源需求的研究者不够透明。
