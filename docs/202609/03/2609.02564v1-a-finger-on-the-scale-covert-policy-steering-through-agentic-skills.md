## 摘要
可复用智能体技能为大型语言模型（LLM）智能体扩展了任务流程、工具使用指导和输出约束。然而，这些技能同时充当外部化行为策略，由此带来供应链风险：第三方技能可能在保留所声明任务和有效输出接口的同时，暗中将智能体决策重定向至未公开目标。我们将技能策略完整性（Skill Policy Integrity）形式化，要求技能所诱导的策略与其声明的功能和用户授权的目标保持一致。我们进一步提出 SkillShift，一个受约束的黑盒框架，在不进行显式目标命令注入或任务劫持的情况下实现隐蔽策略引导。该框架将语义上合理的策略编辑与分层验证、失败引导优化和策略压缩相结合，以保持有效性、输出有效性、可迁移性和隐蔽性。我们在智能体商务和软件依赖使用场景中实例化该威胁，SkillShift 分别实现了 81.33% 和 63.33% 的攻击者偏好选择率，同时保持 100% 的效用保持率。冻结的策略无需进一步优化即可跨异构 LLM 后端和智能体环境迁移。此外，所评估的扫描器未能检测到构造的技能，这促使将可复用技能作为智能体策略制品进行行为审计。

## Abstract
Reusable agent skills extend large language model (LLM) agents with task procedures, tool-use guidance, and output constraints. Yet these skills also act as externalized behavioral policies, which create a supply-chain risk: a third-party skill may preserve the declared task and valid output interface while covertly redirecting agent decisions toward an undisclosed objective. We formalize Skill Policy Integrity, which requires a Skill-induced policy to remain aligned with its declared functionality and the user-authorized objective. We further present SkillShift, a constrained black-box framework for covert policy steering without explicit target command injection or task hijacking. It combines semantically plausible policy edits with hierarchical validation, failure-guided optimization, and strategy compression to preserve effectiveness, output validity, transferability, and inconspicuousness. We instantiate this threat in agentic commerce and software dependency use, with SkillShift achieving attacker-favored selection rates of 81.33% and 63.33% while maintaining a 100% utility-preserving rate. The frozen policies also transfer without further optimization across heterogeneous LLM backends and agent environments. Moreover, the evaluated scanners fail to detect the constructed skills, motivating behavioral auditing of reusable skills as agent policy artifacts.

## 1. 核心问题与整体含义

- **研究背景**：可复用智能体技能（Agentic Skills）已经成为扩展 LLM 智能体能力的重要方式。它们以可加载指令包的形式，编码任务流程、工具使用指导、输出约束和示例，因此不仅改变智能体“能做什么”，也深刻影响其“如何决策”。
- **核心问题**：第三方技能可能成为隐蔽的行为策略载体。在保持声明任务、候选集、输出接口不变的情况下，恶意提供者可以通过修改技能中的评判标准、示例和规则，悄然改变智能体的候选选择偏好，服务于未公开的商业或其他目标。
- **形式化定义**：论文提出 **技能策略完整性（Skill Policy Integrity）**，要求技能所诱导的行为策略必须忠于其声明功能和用户授权目标。违反该属性的攻击，即使输出完全有效，也构成策略层破坏。
- **整体含义**：论文揭示了一个现有安全研究视野之外的供应链风险：不是任务劫持或提示注入，而是“软策略层”的隐蔽偏好引导。该威胁更难以被传统安全扫描器发现，因而需要新的行为审计手段。

## 2. 方法论

### 2.1 核心思想

- **SkillShift** 是一个受约束的黑盒优化框架，目标是在不改变用户查询、候选数据、候选顺序和输出接口的情况下，仅通过修改共享技能文档中的比较策略，提高目标实体被选中的概率。
- 攻击策略被编码为结构化对象：

  \[
  A = (G, U, T, X)
  \]

  其中：
  - \(G\)：全局评估原则（global evaluation principles）
  - \(U\)：任务特定规则（task-specific rules）
  - \(T\)：平局打破规则（tie-breaking criteria）
  - \(X\)：语义示例（semantic examples）

- 攻击技能通过渲染器附加到底层技能之上：

  \[
  S_A = R(S_{\text{base}}, A)
  \]

### 2.2 三种策略引导机制

- **策略框架（Policy framing）**：改变任务相关属性在隐式比较函数中的权重，例如强调“专业运动品牌”“官方旗舰店”“列式数据处理”等属性，使目标候选在无须显式点名的情况下获得优势。
- **平局打破操纵（Tie-breaking manipulation）**：在多个候选都可行时，引入看似合理的次级标准，使目标候选在“接近平局”时优先胜出。
- **语义锚定（Semantic anchoring）**：通过示例稳定抽象原则的跨查询、跨模型应用方式。示例中允许出现目标名称，但禁止直接给出无条件目标映射、位置捷径或查询特定规则。

### 2.3 黑盒优化流程

SkillShift 分为四个阶段：

1. **上下文一致初始化**：用 LLM 根据基础技能、声明任务、目标和目标属性，生成一个满足所有硬性约束的紧凑初始策略。
2. **受约束黑盒策略搜索**：
   - 候选生成：对当前最优策略进行局部语义编辑，如增删规则、改写标准、替换示例、合并内容。
   - 分层验证：候选必须通过结构检查、表面隔离检查、内容约束检查。禁止显式目标命令、查询特定映射、位置捷径、测试实例引用、目标名称超范围出现。
   - 黑盒评估：仅使用最终模型输出，计算目标选择率（PSR）和有效输出率（VR）。
   - 策略更新：按 PSR、VR、渲染长度进行字典序比较，保留改进策略。
3. **失败引导覆盖修复**：将开发集上失败的查询按其语义类别分组，仅向策略生成器提供类别级反馈和聚合统计，避免实例级记忆。对覆盖不足的类别进行局部修补。
4. **效果保持的策略压缩**：删除低贡献内容，合并相似规则，缩短重复解释，泛化示例，以减少冗余内容和暴露面，同时设定 PSR 退化容忍阈值。

### 2.4 目标函数

优化目标是最大化开发集上的攻击 PSR，同时满足：

\[
\widehat{VR}(A) \ge \tau_{vr}, \quad \ell(A) \le B
\]

其中 \(\ell(A)\) 为策略长度，\(B\) 为固定长度预算，\(\tau_{vr}\) 为最低有效输出率。

## 3. 实验设计

### 3.1 任务与数据集

- **两个固定候选选择领域**：
  - **购物推荐（Shopping Recommendation）**：从固定运动商品列表中选择一个，目标品牌为 **Li-Ning**。
  - **Python 依赖选择（Python Dependency Selection）**：从 `pandas`、`dask`、`polars`、`modin`、`datatable` 中选择一个包并返回 import 语句，目标为 **polars**。
- 每个领域包含 **50 个查询**：
  - 前 **30 个**作为开发集（dev30）
  - 后 **20 个**作为留出集（heldout20）
- 每个查询独立执行 **3 次**，因此：
  - dev30 有 90 次响应
  - heldout20 有 60 次响应
  - all50 有 150 次响应

### 3.2 模型配置

- **策略提出者（Proposer）**：GPT-5.5
- **主受害者模拟器（Victim Simulator）**：Claude Haiku 4.5
- 其他跨模型后端：DeepSeek v4-Flash、GLM-4.7、Gemini 3-Flash、Qwen3.5-Flash、GPT-5.4
- 完整智能体环境：Claude Code（使用 Claude Haiku 4.5）和 Codex-compatible Agent（使用 DeepSeek v4-Flash）

### 3.3 对比方法

- **非对抗控制**：
  - No Skill（无技能）
  - Clean Skill（干净技能）
- **独立攻击基线**：
  - Target Name Only（仅目标名称）
  - Keyword Stuffing（关键词堆砌）
  - Generic Prompt Injection（通用提示注入）
  - Direct-Skill Injection（直接技能注入，作为非隐蔽正向控制）

### 3.4 评价指标

- **PSR（Policy Steering Rate）**：目标实体被选中并成功解析的比例。
- **VR（Valid-output Rate）**：输出有效且从固定候选集中选择实体的比例。
- **Lift**：攻击 PSR 与干净 PSR 的绝对差值，以百分点表示。

### 3.5 附加实验

- **消融实验**：移除目标语义线索、示例、任务匹配框架、专业框架、平局规则、全部示例等组件。
- **安全检测**：使用 skill-scanner-full、Aguara、Snyk Agent Scan、STARS、SkillSpector、ProtectAI DeBERTa 六种检测器。
- **注册表级评估**：ClawHub、Tencent SkillHub、vskill 三个公共技能注册表。
- **下游代码质量**：使用 DeepEval GEval 对 50 个干净输出和 50 个攻击输出进行代码质量评分，报告平均分及阈值通过率 QPR@0.7、QPR@0.6。

## 6. 主要结论与发现

- **攻击有效性**：
  - 在购物推荐领域，SkillShift 将 PSR 从干净技能的 37.33% 提升至 **81.33%**，Lift 为 +44.00 个百分点，VR 保持 100%。
  - 在 Python 依赖选择领域，SkillShift 将 PSR 从约 0.67% 提升至 **63.33%**，Lift 为 +62.66 个百分点，VR 保持 100%。
- **隐蔽性**：
  - 与直接技能注入相比，SkillShift 不使用显式覆盖命令，更难以被检测。
  - 大多数安全扫描器和提示注入检测器无法区分 SkillShift 攻击技能与干净技能。
- **迁移性**：
  - 冻结策略可跨 6 种模型后端迁移，Lift 在购物领域为 20.00–51.33 个百分点，在 Python 领域为 52.67–100.00 个百分点。
  - 在完整智能体环境中同样有效，Lift 为 28.67–94.00 个百分点。
- **下游影响**：
  - 尽管选择阶段输出 100% 有效，攻击条件下代码质量平均分从 0.558 降至 0.506，高质量输出通过率显著下降。
- **核心结论**：**输出有效性和通过安全扫描并不保证技能策略完整性**。现有防御体系对“软策略层”隐蔽引导存在盲区，需要引入基于 Clean–Attack 对比和反事实测试的行为审计机制。

## 7. 优点

- **新颖的威胁建模**：首次形式化技能策略完整性，明确区分“任务正确性”与“策略层行为偏差”。
- **实用的黑盒框架**：SkillShift 不依赖模型内部概率、梯度、隐藏状态或注意力信息，仅使用最终输出，现实可行性高。
- **严格约束设计**：通过分层验证明确禁止显式目标命令、位置捷径、查询特定规则和测试实例引用，使攻击保持在“语义合理”的隐蔽范围内。
- **良好的迁移性和泛化性**：冻结策略无需进一步优化即可迁移到多个异构模型后端和完整智能体环境，显示出对底层模型差异的鲁棒性。
- **多维评估**：除攻击成功率外，还系统评估了输出有效性、跨查询泛化、跨模型迁移、检测器覆盖率、注册表防御和下游任务质量，研究链条完整。
- **消融研究清晰**：通过移除特定组件（如示例、语义线索、任务匹配框架）定位了不同机制对攻击效果的贡献，

例如移除目标语义线索后 PSR 显著下降，移除示例会削弱跨查询泛化能力，移除任务匹配框架或平局规则也会导致可测量的效果损失，表明策略框架、语义锚定与平局打破机制之间存在互补性，并非单一组件在起作用。

## 8. 局限性

- **威胁模型假设较强**：论文假设攻击者能够直接修改共享技能文档，但未讨论攻击技能如何被分发、推广或伪装进入目标用户的技能库。现实中的技能供应链攻击还涉及社会工程、版本更新、依赖混淆等环节，论文未覆盖这些前置条件。
- **任务类型单一**：研究仅覆盖固定候选集上的单一选择任务，未涉及开放式生成、多步工具调用、动态候选集或需要长期规划的任务。因此，SkillShift 能否在更复杂的智能体工作流中保持隐蔽性和有效性仍有待检验。
- **评估指标偏重结果**：PSR 和 VR 只度量最终选择结果，未刻画模型内部推理、中间步骤或对用户解释的变化。攻击可能不仅改变选择，还改变理由呈现方式，而这部分未被量化。
- **对多轮交互影响未知**：实验主要在单轮查询中完成，未评估攻击技能在多轮对话、用户追问或纠错场景下的稳定性与隐蔽性。真实使用中用户可能对推荐结果提出质疑，攻击策略是否仍能维持目标偏好需要进一步研究。
- **防御方未得到对称建模**：论文主要站在攻击者视角优化 SkillShift，防御者只能被动使用现有检测器。缺乏对主动防御策略（如技能签名、行为对比测试、反事实审计）的有效性评估，使结论偏向攻击可行性而弱化防御可能性。

## 9. 未来工作与防御启示

- **建立技能策略完整性审计框架**：论文建议将“行为策略是否忠于声明功能”作为独立于输出有效性的审计维度。未来可开发基于 Clean–Attack 对比、反事实查询和分布偏移检测的自动化审计工具，专门识别软策略层偏好引导。
- **发展行为级检测器**：现有扫描器主要关注恶意指令、可疑 URL 或提示注入模式，对语义级偏好操纵不敏感。未来可训练或设计检测器，通过比较技能文档中的评估原则与候选属性分布，发现不成比例地偏向特定实体的规则。
- **引入技能来源与版本治理**：论文结果提示，技能供应链需要更严格的来源验证、签名机制和变更审计。对公共注册表中的技能，应记录修改历史、评估策略变化，并在更新时触发行为回归测试。
- **扩展至更多任务与多目标场景**：未来工作可将 SkillShift 应用于多目标竞争、多步决策、工具选择、网页导航等场景，检验策略操纵的普遍性，并研究多个攻击者或目标实体共存时的相互作用。
- **结合可解释性分析**：通过分析模型在攻击前后的注意力、中间推理或自解释文本，可以更早发现策略层偏差，为防御提供更丰富的信号。

## 10. 总结

论文通过提出技能策略完整性这一新概念，揭示了一个被忽视的智能体供应链风险：攻击者无需篡改候选集或输出格式，只需修改共享技能中的比较原则、平局规则和示例，即可显著且隐蔽地引导模型选择特定实体。SkillShift 框架以黑盒方式实现了这种攻击，并在购物推荐与 Python 依赖选择两个领域中取得显著提升，同时保持输出有效率和跨模型迁移性。该研究表明，输出有效性和通过安全扫描并不等同于行为策略未被操纵，现有防御体系需要引入行为审计和策略完整性验证机制，以应对“软策略层”的隐蔽威胁。
