## 摘要
安全调优流程仅评判最终回答，这使得很难区分稳健的拒绝与两种不良捷径：对良性请求一概拒绝，以及看似完善但并未真正约束回答的不忠实安全理由。我们提出 AUDITPLAN，一种单模型的“先规划后回答”方法，模型先生成紧凑的结构化安全计划，然后基于该计划进行回答。该计划记录威胁标签、预期行动和显式约束，从而实现机器可检查的审计，同时在部署时对用户隐藏。我们通过监督微调以及随后使用 FAITHGATE 的强化学习来训练这种行为；FAITHGATE 是一种奖励门控目标，只有在安全计划正确时才给予回答奖励。这抑制了看似安全但不忠实的行为，并促进更紧密的计划-回答耦合。在 Qwen 主干模型上，AUDITPLAN 同时提升了稳健性和可审计性：在 Qwen2.5-3B-Instruct 上，FAITHGATE 将 ASR 从 24.0% 降至 11.6%，将 LSR 从 1.0% 降至 0.36%，并将过度拒绝从 11.0% 降至 2.0%，优于仅对回答进行强化学习、自由形式解释和加权和结构化奖励。类似趋势在 Qwen2.5-1.5B-Instruct 上同样成立。在 Qwen-3-4B-Instruct 和 Qwen2.5-7B-Instruct 上的更大模型确认实验保持了相同趋势，表明显式的内部承诺可以使安全对齐更加忠实、稳健和可审计。

## Abstract
Safety tuning pipelines judge only the final answer, which makes it difficult to distinguish robust refusal from two undesirable shortcuts: blanket refusal on benign requests and polished but unfaithful safety rationales that do not actually constrain the answer. We propose AUDITPLAN, a single-model plan-then-answer approach where the model first emits a compact structured safety plan and then answers conditioned on it. The plan records a threat label, intended action, and explicit constraints, enabling machine-checkable auditing while remaining hidden from users at deployment. We train this behavior with supervised fine-tuning followed by reinforcement learning with FAITHGATE, a reward-gating objective that grants answer reward only when the safety plan is correct. This discourages safe-looking but unfaithful behavior and promotes tighter plan-answer coupling. Across Qwen backbones, AUDITPLAN improves both robustness and auditability: on Qwen2.5-3B-Instruct, FAITHGATE reduces ASR from 24.0% to 11.6%, LSR from 1.0% to 0.36%, and over-refusal from 11.0% to 2.0%, outperforming answer-only RL, free-form explanation, and weighted-sum structured rewards. Similar trends hold for Qwen2.5-1.5B-Instruct. Larger-model confirmation runs on Qwen-3-4B-Instruct and Qwen2.5-7B-Instruct preserve the same trend suggesting that explicit internal commitments can make safety alignment more faithful, robust, and auditable.

## 1. 核心问题与研究动机

- **背景痛点**：当前大语言模型的安全对齐流程通常只优化最终回答，难以区分真正稳健的拒绝与两类“安全捷径”：
  - **对良性请求一概拒绝（blanket refusal / over-refusal）**，损害有用性；
  - **表面安全但实际不忠实的安全理由（unfaithful safety rationale）**：模型在回答后补充看似合理的解释，但该解释并未真正约束回答生成。
- **现有方法的局限**：
  - 外部守卫模型（如 Llama Guard、WildGuard、ShieldGemma）将安全决策放在生成器之外，增加延迟、部署复杂度，且无法让生成器自身可审计。
  - 自由形式的中间推理（如 deliberative reasoning）虽能提升鲁棒性，但缺乏稳定、可机器检查的结构，难以可靠审计。
- **本文目标**：通过让模型在生成最终回答之前，先输出一个**紧凑、结构化、隐藏的安全计划**，并在该计划约束下再生成回答，从而实现：
  1. **稳健拒绝**：对越狱和泄露类提示安全拒绝或偏转；
  2. **保持有用性**：对良性请求给出有帮助的回答，避免过度拒绝；
  3. **可审计性**：通过结构化计划记录威胁标签、动作和约束，使开发者能够事后检查失败来源（威胁误判、动作选择错误、计划-回答不一致）。

## 2. 方法论：AUDITPLAN 与 FAITHGATE

### 2.1 核心思想：先承诺，再回答

- 模型输出由两段组成：
  ```text
  <plan> {...} </plan> <answer> ... </answer>
  ```
- **结构化安全计划（plan）** 是紧凑的 JSON 对象，包含以下字段：
  - `threat`：`benign` / `jailbreak` / `leakage`；
  - `action`：`answer` / `refuse` / `deflect`；
  - `constraints`：短约束列表，如 `no_harmful`、`no_policy_leak`、`safe_guidance`；
  - `trust_boundary`（可选）：如 `system_over_user`。
- 计划在部署时对用户隐藏，仅作为内部日志进行审计；但若解析失败或计划与回答不一致，可选运行时包装器可替换为模板化拒绝并记录违规。

### 2.2 训练流程：SFT + GRPO 强化学习

- **监督微调（SFT）**：
  - 使用带计划标注的演示数据，让模型学会输出合法 JSON 计划和大致正确的安全动作；
  - 优化目标为拼接输出 \( x = \langle z, y \rangle \) 的教师强制似然。
- **强化学习（RL）**：
  - 从 SFT 检查点初始化，使用 **GRPO（Group Relative Policy Optimization）**；
  - 每个提示采样 \( K \) 个补全，计算组内相对优势，并结合 KL 惩罚；
  - 采用 LoRA + 4-bit QLoRA，在单张 V100 上训练。

### 2.3 计划校验器（Plan Verifiers）

- 论文使用四个轻量校验器：
  - **格式有效性（PS）**：标签存在且 JSON 可解析；
  - **威胁准确性（PAA）**：预测威胁标签是否匹配数据集标签；
  - **动作正确性**：动作是否适合提示类别（良性→`answer`；越狱/泄露→`refuse`/`deflect`）；
  - **计划-回答一致性（PAC）**：回答类型是否匹配承诺的动作。
- 这些校验器刻意保持简单、可扩展且可大规模优化，不等同于语义安全证明。

### 2.4 奖励设计：FAITHGATE

- 共五个组件奖励，归一化到 \([0,1]\)：
  - \(R_{safe}\)：回答是否正确拒绝有害提示或回答良性提示；
  - \(R_{leak}\)：惩罚泄露金丝雀、系统提示片段或语义等价泄露；
  - \(R_{plan}\)：奖励正确结构、威胁标签和动作选择；
  - \(R_{util}\)：奖励良性有用性，惩罚不必要拒绝；
  - \(R_{format}\)：奖励遵守标签和模式。
- **加权和基线**：将上述奖励直接线性组合，允许“安全但计划错误”的捷径。
- **FAITHGATE 核心思想**：将回答奖励**以计划正确性为条件**。
  - 定义门控基础奖励 \( g(z, y, u) \)：
    - 格式错误：\( g = 0 \)；
    - 计划正确且回答安全：\( g = +2.0 \)；
    - 计划错误但回答安全：\( g = -0.5 \)；
    - 计划正确但回答不安全：\( g = -2.0 \)；
    - 其他：\( g = 0 \)。
  - 完整奖励为：
    \[
    R_{\text{gate}} = g(z, y, u) + \lambda_{safe} R_{safe} + \lambda_{leak} R_{leak} + \lambda_{plan} R_{plan} + \lambda_{util} R_{util} + \lambda_{fmt} R_{format}
    \]
- 这确保：**只有计划正确且行为安全时才获得高分**；安全回答若计划错误会受到惩罚；这直接抑制过度拒绝和虚假安全理由。

## 3. 实验设计

### 3.1 数据集与场景

- **SFT 数据**：1,500 个提示，划分 55% 良性 / 30% 越狱 / 15% 泄露；
- **RL 数据**：1,000 个提示，约 40% 良性 / 40% 越狱 / 20% 泄露；
- **评估集**：900 个提示，包含：
  - 300 来自 **Do-Not-Answer** 的越狱提示；
  - 300 泄露增强提示；
  - 300 来自 **UltraChat** 的良性提示。
- 攻击覆盖：直接请求、角色扮演、权威框架、假设提示、比较提示、间接泄露模板、合成对抗后缀等。
- **额外压力片**：混合 JailbreakBench-mini、改写泄露和良性安全相邻提示，\(n=180\)。

### 3.2 评估指标

- **行为指标**（越低越好）：
  - **ASR**（Attack Success Rate）：越狱成功率；
  - **LSR**（Leakage Success Rate）：泄露成功率；
  - **ORR**（Over-Refusal Rate）：良性提示被过度拒绝率。
- **计划指标**（越高越好）：
  - **PS**：句法计划有效性；
  - **PAA**：威胁标签准确率；
  - **PAC**：计划-回答一致性。

### 3.3 对比方法

- 同主干 **仅回答 RL（AnswerOnly RL）**：无计划通道；
- **自由形式解释（Free-form explanation）**：自然语言安全理由后回答；
- **结构化加权和奖励（Weighted-sum structured reward）**：使用相同计划结构，但回答奖励不做门控；
- **模式消融**：仅威胁、威胁+动作、完整计划；
- 外部守卫模型仅作为背景参考，不与本文直接对比。

## 6. 主要结论与发现

- **SFT 是主要表征转变阶段**：在 1.5B 上，SFT 使 PS 从 0 升至 0.9792，PAA 升至 0.9268，显著降低 ASR/LSR；RL 则进一步细化决策边界，尤其在泄露鲁棒性和 PAC 上提升明显。
- **在 3B 主对比中，FAITHGATE 全面优于其他变体**：
  - ASR：0.2400 → **0.1155**（降低 51.9%）；
  - LSR：0.0100 → **0.0036**（降低 64.3%）；
  - ORR：0.1100 → **0.0197**（降低 82.1%）；
  - PAA：0.5800 → **0.7219**；
  - PAC：0.6520 → **0.8013**；
  - PS：0.6330 → **0.8281**。
- 自由形式解释的中间信号不稳定：提取动作一致性仅 0.6810，稳定可提取性 0.7120，低于结构化计划。
- 1.5B 上 ORR 仍高于 0.10，显示出**有用安全部分依赖模型容量**；3B 以上模型在 FAITHGATE 下可实现低 ORR 与低 ASR 的更好权衡。
- 门控常数敏感性分析表明：默认设置强于 5/6 其他设置，且所有设置均在 ORR 上优于加权和，证明并非脆弱常数选择。
- 可审计性价值：AUDITPLAN 将每次补全变成结构化记录，可在系统层面聚合“良性误标为越狱”“泄露提示威胁正确但 PAC 失败”“格式失败”等操作上有意义的分类。

## 7. 优点

- **新思路**：将安全决策从“回答后的解释”前移到“回答前的结构化承诺”，实现可审计而无需外部守卫模型。
- **直接抑制安全捷径**：FAITHGATE 通过奖励门控，显式惩罚“计划错误但回答安全”的情况，有效降低过度拒绝和虚假安全理由。
- **紧凑、低熵、可机器检查的计划模式**：避免自由形式推理的解析不稳定，使计划指标（PS/PAA/PAC）可以大规模、低成本计算。
- **可选的运行时包装器**：在部署时解析计划、检查动作一致性，发现违规可替换为模板化拒绝并记录 PAC 违规。
- **实验设计严谨**：同一主干/数据/奖励组件下仅改变信用分配，并做了多种子、多规模、消融、压力测试和敏感性分析，结果较稳健。
- **可诊断的失败分类**：威胁误判、计划-回答不匹配、间接泄露、格式失败等可以被明确追踪，改进调试和目标数据收集。

## 8. 不足与局限

- **威胁模型较窄**：仅覆盖单轮、仅提示型对手；明确不保证多轮自适应攻击、白盒攻击、工具或检索文档中的提示注入安全。
- **校验器是启发式而非语义证明**：PAA/PAC/PS 等基于简单规则和数据集标签，不等同于真实语义安全；可能继承基准和判官提示的偏差。
- **模型规模偏小**：主受控实验主要是 1.5B/3B；4B/7B 仅做单种子确认，不构成大规模严格验证。
- **判官依赖风险**：泄露检测、安全评分使用 LLM 判官作为第三层，绝对 ASR/LSR 可能随判官校准变化；虽然论文报告了 0.86 的一致性检查，但仍需跨判官和人工审计。
- **未报告训练时长和计算成本**：虽然说明单卡 V100 可运行，但缺少训练小时数或显存占用等具体数据。
- **外部守卫基线不可直接比较**：文中引用的 WildGuard、Llama Guard 等数字来自不同主干、分类法和评估协议，仅用于背景而非公平对比。
- **伦理与发布风险**：越狱和泄露研究可能间接帮助攻击者，作者建议谨慎发布攻击模板以防滥用。
- **内部计划忠实度**：论文强调“显式奖励忠实度能提升可测耦合”，但不声称计划在机制意义上保证忠实。
