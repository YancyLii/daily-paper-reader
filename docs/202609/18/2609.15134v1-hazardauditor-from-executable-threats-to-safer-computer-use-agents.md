## 摘要
计算机使用智能体越来越多地与浏览器、终端、文件系统和外部服务交互，由此带来的安全风险主要源于运行时行为，而不仅仅是生成内容。现有防护模型针对静态提示和响应，难以适应智能体的执行过程；现有可执行安全平台只产生评估判定，而无法提供防护模型在异构智能体框架之间学习所需的规范化监督信号。我们提出 HazardAuditor，一个以执行过程为基础的框架，弥合上述两个差距。其基础设施在受控环境中运行异构智能体（Claude Code、Codex、Hermes 和 OpenClaw），并将它们的交互规范化为统一的事件表示，以支持跨框架监督。我们进一步观察到，token 级后训练目标会给生成式防护模型带来结构性错配，导致较长的推理过程主导梯度更新。Guard Policy Optimization（GuardPO）通过将确定性的安全结果转换为序列级优势，并对推理区域和判定区域进行归一化，使安全决策成为优化的有效单元，从而解决这一问题。在多个基准和异构计算机使用系统上，HazardAuditor 相较此前最强的防护模型将准确率最多提高 16.5 个百分点。代码、模型和评估工件将在 https://yunhao-feng.github.io/HazardAuditor/ 提供。

## Abstract
Computer-use agents increasingly interact with browsers, terminals, file systems, and external services, introducing safety risks that emerge through runtime behavior rather than generated content alone. Existing guard models target static prompts and responses and are poorly suited to agent execution; existing executable safety platforms produce evaluation verdicts rather than the normalized supervision a guard model needs to learn across heterogeneous agent frameworks. We introduce HazardAuditor, an execution-grounded framework that closes both gaps. Its infrastructure runs heterogeneous agents (Claude Code, Codex, Hermes, and OpenClaw) in controlled environments and normalizes their interactions into a canonical event representation for cross-framework supervision. We further observe that token-level post-training objectives create a structural mismatch for generative guards, causing longer rationales to dominate gradient updates. Guard Policy Optimization (GuardPO) addresses this by converting deterministic safety outcomes into sequence-level advantages and normalizing rationale and verdict regions, making the safety decision the effective unit of optimization. Across multiple benchmarks and heterogeneous computer-use systems, HazardAuditor improves accuracy by up to 16.5 percentage points over the strongest prior guard. Code, models, and evaluation artifacts will be available at https://yunhao-feng.github.io/HazardAuditor/.

### 2.3 Guard Policy Optimization（GuardPO）

- **问题**：标准 token 平均损失会使长推理响应获得更大的梯度权重，但每个响应其实只对应一个安全决策。
- **决策级奖励**：对每个生成响应 `zi`，解析出二元判定 `byi ∈ {0,1,⊥}`，与真实标签 `yi` 比较：
  - 正确：`+1`；
  - 错误：`−1`；
  - 格式错误：`−γ`，其中 `γ=1.25`。

- **裁剪 token 更新**：采用类似 CISPO 的裁剪重要性权重：
  - 重要性比 `ρ_{i,t}` 被裁剪到 `[1−ε, 1+ε]`，`ε=0.1`；
  - token 损失：`ℓ_{i,t} = − sg(clipped ρ_{i,t}) · Â_i · log πθ(z_{i,t}|x_i,z_{i,<t})`。
- **决策归一化目标**：
  - 将响应拆分为推理区域 `R_i` 和最后 `Kver=12` 个判定 token 区域 `V_i`；
  - 分别对两个区域内的 token 损失取平均，再聚合：
    \[
    L_{\text{GuardPO}} = \frac{1}{N}\sum_{i\in B} \left[ M_i(R_i) + \lambda_{\text{ver}} M_i(V_i) \right]

    其中 `λ_ver = 2`。
- **长度不变性（Proposition 1）**：若将某响应的推理 token 复制 q 次，其在 GuardPO 损失中的贡献不变；而在标准 token 平均目标下，该响应的批次权重会随长度增加。GuardPO 因此使安全决策而非推理 token 数量成为优化的有效单元。

## 6. 主要结论与发现

- HazardAuditor 在 CUA-EXEC 四个框架上均取得最优结果，相较最强先前智能体导向防护模型 BraveGuard，准确率分别提升 12.5、4.0、9.5、16.5 个百分点。
- GuardPO 相较 SFT 初始化在所有四个平衡子集上均有提升，例如 Claude Code 上准确率从 82.0 提升到 94.0，OpenClaw 上从 74.0 提升到 87.5。
- 执行接地训练可以迁移到基础设施分布之外：在 AgentHazard 的四个不同后端上，HazardAuditor 多数情况下达到最高准确率或 F1，且在全部后端上比 SFT 初始化 F1 更高。
- 在 ATBench、ASSE-Safety、R-Judge 上，HazardAuditor 具有最高的最差基准 F1（88.3%），显示跨基准稳定性。
- 改进并非靠更激进地预测“不安全”获得，而是在安全与不安全之间学到了更好的决策边界。
- 快速分类头虽能将平均延迟降低约 10 倍（至约 304 ms），但宏 F1 从 88.12% 降至约 69.63%，只适合作为预筛器。

## 7. 优点

- **执行接地**：从真实工具调用、环境观察和推理轨迹中学习，贴合计算机使用智能体实际风险。
- **跨框架统一表示**：通过规范化事件模式适配四种异构智能体，使单一防护模型具备跨框架泛化能力。
- **行为-内容区分清晰**：明确指出观察风险内容不等于执行危险行为，防止误判。
- **GuardPO 方法创新**：
  - 面向安全决策的序列级优化；
  - 分别归一化推理和判定区域，理论上保证对推理长度的不变性；
  - 不依赖外部奖励模型或在线 LLM 法官。
- **评估设计较全面**：涵盖自建执行集、多个外部基准、多个后端、消融和效率分析。
- **可审计性**：输出包含分析文本和确定性二元判定，便于下游控制器干预和人工审查。

## 8. 不足与局限

- **个别基准上仍有劣势**：在 AgentHazard 的 GPT-5.5 后端上，BraveGuard 的召回率和 F1 高于 HazardAuditor；在 R-Judge 上，SFT 初始化略优于 GuardPO 版本，说明 GuardPO 并非在所有分布上都带来单调提升。
- **固定测试子集规模有限**：CUA-Exec 固定子集仅 228 条轨迹，每个框架样本量较少，框架级结果可能不稳定。
- **训练成本与时长未透明**：虽然报告了 8×A100 硬件，但未给出完整训练时间，难以评估复现成本。
- **推理延迟较高**：生成式模型平均延迟约 3.1 秒，不适合对低延迟要求严格的在线安全控制；快速分类头性能下降明显。
- **框架覆盖有限**：仅涵盖 Claude Code、Codex、Hermes、OpenClaw，真实世界还有大量其他计算机使用智能体和工具协议，跨框架泛化边界仍需进一步检验。
- **基准覆盖不完全**：部分外部基准如 R-Judge、ASSE-Safety、ATBench 的风险分布与真实部署场景可能仍有差距；NSFA 查询集上的敏感信息和资源滥用类召回较低（69.22%、42.95%）。
- **依赖确定性解析器**：GuardPO 的奖励依赖输出格式是否可解析，格式错误会得到负奖励，

## 9. 总体评价与未来方向
