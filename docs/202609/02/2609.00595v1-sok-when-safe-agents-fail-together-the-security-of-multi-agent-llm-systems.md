## 摘要
安全智能体也可能一起失败。多智能体大语言模型（LLM）系统（MAS）跨越主体边界传递信息、状态、决策和权限，从而产生局部检查可能无法发现的故障。若缺乏执行层面的视角，多智能体场景很容易被误认为是真正多智能体安全效应的证据。因此，我们通过对197项工作进行以执行过程为中心的分析，系统化梳理MAS安全，涵盖六类交互接口、四种对手位置、七类系统级风险以及八条反复出现的攻击路径。我们提出A-I-R框架，按对手位置、交互接口和最终系统级风险来组织攻击，将MAS中原本零散的攻击机制统一起来。我们通过五部分契约来组织防御，涵盖路径目标、观察、干预、信任边界和恢复，并指出路径闭合与恢复是关键挑战。我们审计了44项评估与基准工作，识别出在隔离交互效应、设计可比较且具有诊断性的指标、支持跨MAS设计复用以及评估开放系统运行方面的开放挑战。总之，这些发现促使我们以交互感知的视角看待MAS安全：端到端追踪攻击，检验防御是否闭合这些路径，并用适当的反事实来评估系统级效应。

## Abstract
Safe agents can fail together. Multi-agent LLM systems (MAS) move information, state, decisions, and authority across principal boundaries, creating failures that local checks may miss. Without an execution-level view, a multi-agent setting can easily be mistaken for evidence of a genuinely multi-agent security effect. We thus systematize MAS security through an execution-centered analysis of 197 works, covering six interaction interfaces, four adversary positions, seven system-level risks, and eight recurring attack paths. We introduce an A-I-R framework that organizes attacks by adversary position, interaction interface, and resulting system-level risk, unifying otherwise fragmented attack mechanisms across MAS. We organize defenses through a five-part contract covering path target, observation, intervention, trust boundary, and recovery, and identify path closure and recovery as key challenges. We audit 44 evaluation and benchmark works and identify open challenges in isolating interaction effects, designing comparable and diagnostic metrics, supporting reuse across MAS designs, and evaluating open-system operation. Together, these findings motivate an interaction-aware view of MAS security: trace attacks end to end, test whether defenses close those paths, and evaluate system-level effects with appropriate counterfactuals.

## 1. 论文的核心问题与整体含义

- **核心问题**：多智能体大语言模型系统（MAS）中，原本单独使用时安全的智能体，在组合后可能产生系统级安全故障。信息、状态、决策和权限跨主体边界移动，局部安全检查往往无法发现这些故障。
- **研究动机**：现有综述多按组件、攻击名称或治理关注点组织安全知识，缺少“攻击如何在多智能体系统中端到端传播”的执行视角。一个在多智能体场景中观察到的失败，容易被误认为是由多智能体交互引起的，但实际上可能只是单智能体漏洞的继承或简单重现。
- **整体含义**：论文主张以**端到端执行过程**作为分析单元，建立统一的 MAS 安全描述、防御比较与评估审计框架，推动“交互感知”的安全研究范式。

## 2. 论文提出的方法论

### 2.1 核心思想

- 将 MAS 安全定义为围绕**跨主体执行路径**的问题：对抗性影响从哪里进入、经过哪些交互接口、最终造成什么系统级安全后果。
- 提出 **A → I → R 框架**：
  - **A（Adversary position）**：对手位置，包括外部对手、用户级对手、成员对手、基础设施对手。
  - **I（Interaction interface）**：交互接口，共 6 类。
  - **R（System-level risk）**：系统级风险，共 7 类。
- 用 **配置维度 C1–C8** 描述执行发生的条件：通信拓扑、协议语义、主体组成、协调机制、状态架构、成员与信任、权限放置、监督架构。
- 用 **交互接口 I1–I6** 描述安全相关转移：准入、消息传递、状态传播、权限转移与行动、集体承诺、检测与干预。
- 用 **系统级风险 R1–R7** 描述最终安全后果：遏制失败、独立性丧失、集体决策完整性失败、轨迹与目标完整性失败、跨主体机密性泄露、传递性授权失败、可用性与资源隔离失败。
- 进一步归纳出 **8 条反复出现的攻击路径 P1–P8**：准入/组合注入、传播/持久化、路由/角色操纵、协调/集体操纵、同伴/状态引导、跨主体泄露、委托/权限升级、共享资源/控制平面干扰。

### 2.2 防御组织：五部分契约

- 每个防御按五个维度比较：
  - **路径目标**：要中断哪条攻击路径或风险。
  - **观察**：防御者能看到执行过程的哪些部分。
  - **干预**：可以改变什么、何时改变。
  - **信任边界**：必须可信的主体、组件和系统条件。
  - **恢复**：预防或遏制失败后，还能否撤回、回滚或修复。
- 将防御控制原语分为四类 **D1–D4**：
  - 身份、策略与权限执行。
  - 信任与交互结构控制。
  - 检测、归因与遏制。
  - 状态、溯源与信息流治理。
  - 另将“自适应防御分配”视为跨切面策略。

### 2.3 交互对安全结果的作用分类

- **继承效应**：移除交互后结果基本不变。
- **交互放大效应**：交互改变可能性、传播范围、持久性、特权或影响。
- **组合诱导效应**：只有组合多个主体或步骤时才出现。
- **结构型多智能体效应**：安全属性本身由主体间关系定义，如共谋、联盟或法定人数操纵。
- 这种分类为设计反事实比较提供了依据。

### 2.4 文献语料

- 最终语料包含 **197 篇工作**：
  - Set 1：115 篇同行评审或至少 10 次引用的工作，用于主综合。
  - Set 2：82 篇新兴机制工作，用于扩展性证据。

## 3. 实验设计

- 本文是 **SoK 系统化文献分析与基准审计**，并非传统模型训练实验。

- 每个工作按以下维度编码：
  - 对手位置 A1–A4。
  - 配置维度 C1–C8。
  - 交互接口 I1–I6。
  - 攻击路径 P1–P8。
  - 系统级风险 R1–R7。
- 同时记录：
  - 观察深度：最终输出、回合结果、主体/消息事件、完整执行轨迹。
  - 比较设计：攻击/组件对照、防御对照、匹配单主体对照、关系聚焦 MAS 对照或无对照。
  - 成员设置：固定成员或允许运行时生成。
  - artifact 可用性：是否提供可恢复 URL、仅声明、仅上游 URL 或无 artifact。
- 覆盖场景：
  - 44 个工作全部报告或变化主体组成 C3。
  - 39 个覆盖协调机制 C4。
  - 38 个覆盖通信拓扑 C1。
  - 42 个使用固定成员，2 个允许有限运行时生成。
- 评估深度统计：
  - 20 个使用完整执行轨迹。
  - 20 个使用主体级消息或动作。
  - 2 个使用回合结果。

## 6. 论文的主要结论与发现

- **关系本身是攻击面**：路由、角色放置、聚合和委托即使不改变消息内容，也可以改变安全结果。
- **安全效应可以超越交互生命周期**：共享状态、衍生代理和继承权限能够在原始攻击源消失后继续维持妥协。
- **保护对象远超最终输出**：即使最终答案看似正确，独立性、拓扑、私有上下文和委托权限仍可能已经失败。
- **观察攻击路径不等于归因**：执行轨迹只能显示影响去向，因果判断需要额外的反事实比较。
- **防御方面**：
  - 局部保护不能保证路径闭合。
  - 有效性取决于干预位置、观察范围和信任假设。
  - 遏制不等于恢复；已写入状态、凭证、权限或派生代理的影响难以消除。
- **评估方面**：
  - 需要交互特定的比较设计。
  - 需要可比较且有诊断能力的指标，如限定 ASR 的评估单位。
  - 需要可配置、可扩展的基准组件和文档化接口。
  - 开放系统、动态成员和跨域信任评估仍几乎是空白。

## 7. 优点

- **统一的分析视角**：以端到端执行为中心，将配置、接口、风险、攻击路径、防御和评估连接起来。
- **A → I → R 框架清晰**：将原本分散的攻击机制统一为一个可追踪路径，便于跨研究比较和归因。
- **防御契约可操作**：五部分契约使防御假设、干预点和恢复能力显式化，有助于发现路径闭合与恢复缺口。
- **对评估实践的直接诊断**：指出 ASR 定义不一致、缺少因果溯源图、缺少单主体对照等问题，并提出具体改进建议。
- **交互效应四分类**：继承、放大、组合诱导、结构型多智能体，为设计反事实实验提供了清晰标准。
- **大规模系统审计**：对 44 个基准的多维编码提供了量化证据，而非仅凭定性判断。
