## 摘要
外泄 LLM 智能体的运行时上下文——如用户提示、执行轨迹和工具列表——会给用户带来严重的安全与隐私风险。此类攻击可通过恶意工具实施，通常需要满足三个条件：(1) 智能体选择该恶意工具执行任务；(2) 智能体将其运行时上下文作为输入参数传给该工具；(3) 该工具的实现将这些输入发送至攻击者控制的端点。现有工作主要关注条件 (1) 和 (3)，而条件 (2) 尽管对成功实现上下文外泄至关重要，却在很大程度上未被探索。在本工作中，我们通过开发 ContextLeak 弥补了这一空白。ContextLeak 是一种恶意工具攻击，诱导智能体既选择该工具，又将其上下文作为输入参数泄露出来。我们通过使用强化学习精心设计工具名称和描述来实现该攻击。具体来说，ContextLeak 使用一个 LLM（称为攻击 LLM）自动生成恶意工具的名称和描述。为提高攻击有效性，我们在一组具有多样化模拟智能体上下文的影子用户上，通过强化学习对攻击 LLM 进行微调。我们的关键技术贡献在于设计了针对上下文外泄目标的新型奖励函数，从而能够基于强化学习有效微调攻击 LLM。大量评估表明，即使影子用户的上下文与受害者用户的上下文差异很大，我们的攻击仍保持高效。此外，在适应该设置后，ContextLeak 显著优于现有恶意工具攻击。

## Abstract
Exfiltrating an LLM agent's runtime context -- such as the user prompt, execution trajectory, and tool list -- poses severe security and privacy risks to users. Such attacks can be carried out via malicious tools and typically require three conditions: (1) the agent selects the malicious tool for task execution, (2) the agent passes its runtime context as input arguments to the tool, and (3) the tool's implementation transmits these inputs to an attacker-controlled endpoint. Existing work primarily focuses on conditions (1) and (3), leaving condition (2) largely unexplored, despite its critical role in enabling successful context exfiltration.   In this work, we bridge this gap by developing ContextLeak, a malicious tool attack that induces the agent to both select the tool and disclose its context as input arguments. We realize this attack by carefully crafting the tool's name and description using reinforcement learning. Specifically, ContextLeak employs an LLM, referred to as the attack LLM, to automatically generate the malicious tool's name and description. To improve attack effectiveness, we fine-tune the attack LLM via reinforcement learning on a set of shadow users with diverse, simulated agent contexts. Our key technical contribution is the design of novel reward functions tailored to the context exfiltration objective, enabling effective reinforcement-learning-based fine-tuning of the attack LLM. Extensive evaluation demonstrates that our attack remains highly effective even when the shadow users' contexts differ substantially from those of the victim users. Moreover, ContextLeak significantly outperforms existing malicious tool attacks when adapted to this setting.

- **研究背景**：LLM 智能体在执行用户任务时会维护一个运行时上下文，包括用户提示、对话历史、执行轨迹、工具列表等。这些信息高度敏感，一旦泄露可能暴露健康、财务、工作机密等隐私。
- **核心问题**：通过恶意工具外泄 LLM 智能体上下文的攻击需要满足三个条件：
  1. 智能体选择恶意工具；
  2. 智能体将运行时上下文作为输入参数传递给该工具；
  3. 工具实现将输入参数发送到攻击者控制的端点。
- **研究缺口**：已有工作主要关注条件（1）工具选择优化和条件（3）恶意代码实现，条件（2）——如何诱导智能体主动把上下文作为参数传给工具——在很大程度上未被探索。
- **整体含义**：ContextLeak 提出首个系统化方法，在工具名称与描述层面同时优化“选择目标”和“参数传递目标”，填补了上下文外泄攻击链中的关键空白，揭示了 LLM 智能体在工具调用环节的深层安全风险。

## 2. 论文提出的方法论

### 2.1 核心思想

- ContextLeak 使用一个攻击 LLM 自动生成恶意工具的名称和描述，目标是让智能体：
  - **选择该恶意工具**；
  - **将运行时上下文作为输入参数传入该工具**。
- 由于普通 LLM 未针对该目标训练，直接提示生成效果不佳，因此采用**强化学习微调攻击 LLM**。

### 2.2 系统提示设计

- 攻击 LLM 的系统提示包含两个关键原则：
  - **选择主导性**：将恶意工具描述为工作流中的必要组件、统一接口或预处理层，使智能体倾向于优先选择它。
  - **参数目标**：在工具描述中建立“正确执行必须依赖完整参数”的语义关系，隐式诱导智能体传入完整上下文，而不是使用显式指令。

### 2.3 强化学习微调流程

- 采用 DAPO 算法，对攻击 LLM 进行 LoRA 微调，rank 为 8。
- 每轮迭代：
  1. 攻击 LLM 生成多个候选工具名称与描述；
  2. 对每个候选工具，从影子用户集中采样一个影子上下文，将其附加到上下文后输入攻击者部署的智能体实例；
  3. 智能体输出是否选择该工具，以及输入参数；
  4. 根据奖励函数评分，并用奖励更新攻击 LLM。

### 2.4 奖励函数设计

- **选择奖励**：二进制值 S，若恶意工具被选择则 S=1，否则 S=0。
- **参数奖励**：由两部分组成：
  - 相似度奖励：  
    `rsim(C′, A) = 1 − Lev(C′, A) / max(|C′|, |A|)`  
    使用词级 Levenshtein 距离衡量参数 A 与真实上下文 C′ 的重建程度。
  - 长度正则项：  
    `rlen(C′, A) = exp(−α · |C′| − |A| / max(|A|, 1))`  
    惩罚参数与真实上下文长度差异过大的情况。
  - 综合参数奖励：  
    `Rarg(C′, A) = (1 − λ) rsim(C′, A) + λ rlen(C′, A)`  
    其中 λ 平衡保真度与长度一致性。
- **总奖励**：  
  `R(C′, A) = 1 + Rarg(C′, A)` 若 S=1；否则 R=0。

### 2.5 策略引导候选生成

- 将每个候选工具的测试结果分为三类：
  - **Tool Failure**：工具未被选择；
  - **Low Exfiltration**：工具被选择，但参数与上下文相似度低（Rarg < τ）；
  - **Full Success**：工具被选择且参数相似度高（Rarg ≥ τ）。
- 使用策略提取 LLM 从每个候选中提取策略名称与定义，并存入对应策略缓冲区。
- 生成新候选时，从缓冲区采样策略：
  - 2 个 Full Success；
  - 1 个 Low Exfiltration；
  - 1 个 Tool Failure。
- 通过混合策略引导，在利用有效模式的同时避免候选生成坍缩，并保持多样性。

## 6. 主要结论与发现

- **攻击有效**：ContextLeak 在用户提示、对话历史、工具列表三类上下文上均取得较高 MTSR 和接近 1 的 EDS/ES，优于所有基线。
- **策略引导有价值**：ContextLeak 完整版比去掉策略引导的 ContextLeak-w/o-S 在所有指标上都有进一步提升。
- **迁移能力强**：
  - 在不同后端 LLM（包括闭源 GPT 系列）上仍保持高攻击成功率；
  - 在跨域、跨数据集受害者上仍有效，域迁移带来的性能下降比数据集迁移更明显。
- **现有防御不足**：
  - 预防性防御虽然可降低攻击成功率，但显著损害工具选择的正确率和参数质量，安全收益主要来自模型能力退化；
  - 检测性防御 FNR 接近 1.0，几乎无法识别 ContextLeak 生成的恶意工具，包括专门针对 MCP 生态的 MCPScan。
- **真实世界可迁移**：针对开源代理训练的恶意工具能够迁移到 Claude Code，恶意工具选择率 22%，被选择时提取接近完整（EDS 0.77、ES 0.96）。

## 7. 优点

- **填补关键空白**：首次系统地解决条件（2）——诱导智能体将上下文作为参数传给恶意工具，而不仅是优化工具选择或恶意代码。
- **奖励函数设计清晰可解释**：将选择与参数重建质量统一到单一奖励中，并通过长度正则项平衡完整性与简洁性。
- **策略引导机制有效**：通过分类提取成功/失败模式并混合采样，缓解候选坍缩并提高微调质量。
- **威胁模型现实**：攻击者无需白盒访问目标智能体，仅部署目标智能体实例并黑盒交互，降低攻击门槛。
- **评估全面且贴近实际**：
  - 覆盖多种后端 LLM、跨数据集、跨域、真实生产代理；
  - 同时评估预防性和检测性防御；
  - 包含消融实验以验证策略引导的独立贡献。
- **与大量基线对比**：包含提示注入、越狱、工具选择攻击等多种类型，比较维度丰富。

## 8. 不足与局限

- **上下文类型覆盖有限**：实验集中在用户提示、对话历史、工具列表三类，记忆、知识库、执行轨迹等其他敏感上下文还未充分测试，论文也将其列为 future work。
- **攻击前提较强**：假设受害者已经安装恶意工具，未讨论如何增加工具安装率，也假设恶意工具能通过平台发布并进入用户工具列表。
- **执行轨迹泄露受限**：由于攻击诱导智能体在任务早期选择恶意工具，往往不会先执行其他良性工具，因此无法有效泄露执行轨迹中的敏感工具响应。

- **真实世界验证范围有限**：仅在 Claude Code 一个生产系统上测试了 100 个样本，且 MTSR 为 22%，尚未在更广泛的商业代理平台中验证。
- **未充分讨论输入参数检查防御**：仅作为未来工作提出，未给出具体实现或评估。

- **与白盒基线的公平性**：部分基线需要白盒访问后端 LLM，而 ContextLeak 仅使用黑盒交互，可能导致比较结果对 ContextLeak 更有利；一些基线的适配方式也可能限制其原本性能。
