## 摘要
LLM 智能体越来越多地读取不可信内容、调用外部工具、访问私有数据，并将工作委托给其他智能体。危害往往并非源于单个不安全操作，而是敏感数据在一系列看似合理的步骤中跨步骤流动。我们提出 AgentFlow，一种以流为中心的策略语言和运行时执行模型，用于规定数据在智能体系统中可以流向何处。策略定义在带标签的运行时边上，并约束哪些工具可以接收敏感字段、哪些汇聚点可以接收已释放数据，以及何种权限可以跨越委托边界。该语言支持流规则和路径规则、任务范围能力、受控释放以及有状态污点语义。运行时引用监视器中介智能体操作，一个有界的基于 SMT 的验证器检查结构化策略片段的安全属性。我们在多个智能体基准上评估 AgentFlow。在我们的原型中，七个安全属性每个验证时间均低于 0.5 秒，验证器捕获了研究中所有植入的不安全策略变体。在四个套件共 949 个 AgentDojo 注入案例中，AgentFlow 将确认的攻陷率从 33.0% 降至 0.0%，同时将总体效用从 46.7% 提升至 63.3%。在 200 个案例的 AgentDyn Dailylife 基准上，它将确认的攻陷率从 73.5% 降至 0.0%，同时保持接近基线的效用（44.5% 降至 43.5%）。跨 ASB、InjecAgent、BIPIA、AgentHarm 和 MCPTox 回放的广度检查表明，所配置的策略阻止了基准指定的策略可见攻击者流；在 ASB 的直接提示注入测试环境中，攻击成功率为 0/1,200。这些结果是初步的，并且仅限于建模的策略可见智能体行为和所评估的基准。

## Abstract
LLM agents increasingly read untrusted content, invoke external tools, access private data, and delegate work to other agents. Harm often arises not from a single unsafe action but from the flow of sensitive data across a sequence of otherwise plausible steps. We present AgentFlow, a flow-centric policy language and runtime enforcement model for specifying where data may travel in agent systems. Policies are defined over labeled runtime edges and constrain which tools may receive sensitive fields, which sinks may receive released data, and what authority may cross delegation boundaries. The language supports flow and path rules, task-scoped capabilities, controlled release, and stateful taint semantics. A runtime reference monitor mediates agent actions, and a bounded SMT-based verifier checks safety properties for a structured policy fragment.   We evaluate AgentFlow on multiple agent benchmarks. In our prototype, seven safety properties verify in under 0.5 seconds each, and the verifier catches all seeded unsafe policy variants in our study. On 949 AgentDojo injected cases across four suites, AgentFlow reduces confirmed compromise from 33.0\% to 0.0\% while improving aggregate utility from 46.7\% to 63.3\%. On a 200-case AgentDyn Dailylife benchmark, it reduces confirmed compromise from 73.5\% to 0.0\% while preserving near-baseline utility (44.5\% to 43.5\%). Breadth checks across ASB, InjecAgent, BIPIA, AgentHarm, and MCPTox replays suggest that the configured policies block the benchmark-specified policy-visible attacker flows; in ASB's direct-prompt-injection harness, attack success is 0/1{,}200. These results are preliminary and scoped to the modeled policy-visible agent behaviors and evaluated benchmarks.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：LLM 智能体系统经常读取不可信内容、调用外部工具、访问私有数据、委托子代理。危害往往不是来自单个明显危险的工具调用，而是敏感数据在一系列看似合理的步骤中跨步骤流动。例如：一条机密记录被 LLM 摘要后通过外发邮件发送，可能违反策略，尽管每一步单独看都合法。  
- **现有局限**：请求级授权语言（如 Cedar）擅长判断“谁能否对资源执行动作”，但缺乏端到端的数据流状态记忆，无法回答“数据从哪里来、如何被变换、可以影响哪些后续动作”。架构绑定的防御（如 Progent、FIDES、CaMeL、FORGE）提供了部分保护，但没有形成**独立、可复用、面向带标签运行时边和历史的策略层**。  
- **整体含义**：AgentFlow 试图将信息流控制、污点跟踪、路径约束和引用监视器思想，转化为现代智能体部署中可用的显式策略层；它面向**策略可见的受中介行为**，不试图解决所有不安全 LLM 行为（如越狱、幻觉、隐蔽信道）。

## 2. 论文提出的方法论

### 核心思想
- 提出 **AgentFlow**：一种以流为中心的策略语言与框架，将安全策略写成**带标签的运行时边上的声明式规则**，对工具调用、响应汇聚点、委托边界进行中介。
- 策略由两类规则组成：**流规则（flow rules）** 约束单步数据流；**路径规则（path rules）** 约束多步历史/谱系中的时序模式。
- 运行时使用引用监视器执行策略；预部署使用有界 SMT 验证器检查结构化策略片段的安全属性。

### 关键技术细节
- **多维度标签格**：每个数据节点标注三元组 \(L = \langle s, C, t\rangle\)
  - 敏感性 \(s\)：`Public ≤ Internal ≤ Confidential ≤ Restricted ≤ TopSecret`
  - 类别 \(C\)：层次化标签，如 `Personal.Identity.SSN`，支持祖先匹配
  - 信任 \(t\)：布尔值，区分可信与不可信来源
- **流图模型**：节点（源/内部/汇）、边（传播语义 \(\rho\)）
  - \(\triangleleft from\)：继承源标签
  - \(\rightsquigarrow(r)\)：应用变换规则（类别移除、降级、设置）
  - \(\bot\)：不透明传播，保守近似
  - \(\equiv s\)：常值标签替换
- **智能体与任务范围**：智能体定义最大敏感度、允许边、可委托对象；任务范围提供临时最小权限限制。
- **路径表达式**：支持顺序、`→*`（最终跟随）、`→!`（紧邻非匹配）、选择题、有界重复 `{m,n}`；评估范围可选 `lineage`（谱系）或 `session`（会话全迹）。
- **运行时状态**：污点映射 \(M\)、执行迹 \(\tau\)、谱系映射 \(Lin\)、活动任务范围、已批准需求、能力集合。
- **形式语义**：给出标签传播、输入标签解析、候选步骤构建、路径匹配、策略评估、运行时转换的小步操作语义；证明运行时保持良构性并强制五条安全目标（流策略执行、委托安全、信任保持、外部披露控制、路径安全）。
- **SMT 验证器**：将策略与有界抽象执行编码为 Z3 约束，检查非泄漏、凭证逃逸、权限提升、第三方敏感数据流、凭证外泄序列、信任洗白、污点单调性等七类属性；SAT 时生成反例迹，UNSAT 表示有界无违规。

## 7. 优点

- **策略层定位清晰**：将跨步骤数据流、路径约束、委托边界、释放上下文作为一等公民，弥补请求级授权不足。  
- **多维度标签格区分敏感/类别/信任**：可表达“公开但不可信的网页文本”与“可信但机密的客户数据”之间的微妙差异。  
- **形式化扎实**：提供操作语义和多个安全定理（运行时保持、策略执行健全、委托安全、信任保持、外部披露控制、路径安全），并附证明。  
- **静态 + 动态双阶段**：SMT 预部署检查策略错误，运行时引用监视器强制策略，兼顾早期发现和实时防护。  
- **与框架解耦**：通过中间件包装工具调用，适配 LangChain、AgentDojo、AgentDyn 等，具有实用性。  
- **诚实界定范围**：明确列出非目标（越狱、幻觉、隐蔽信道等），避免过度宣称。  
- **实验设计较全面**：多基准、消融、性能、种子 bug、回放、相关防御对比，并报告效用与安全双重指标，避免“一刀切拒绝”带来虚假安全。

## 8. 不足与局限

- **过度污染 / 过阻**：当 LLM 处理污点结果时，无法恢复精确 token 级依赖，保守传播导致效用下降；AgentDyn 首版策略因缺少动态任务族的范围能力，产生大量终端拒绝。  
- **策略依赖人工编写**：需要应用所有者显式定义释放上下文、敏感源/汇点和能力；论文本身不是策略自动生成研究。  
- **保证范围有限**：仅覆盖策略可见、受中介的工具调用、委托和数据释放；不涉及越狱、幻觉、错误建议、隐蔽信道、不可信组件漏洞、绕过监视器路径。  
- **SMT 验证有界**：只保证有界抽象中的安全属性，不能覆盖任意无界 LLM 行为或超出建模接口的路径。  
- **广度检查非端到端**：大部分回放为确定性策略门检查，不能代表最终回答安全性或真实任务效用。  
- **指标分类主观性**：四分类结果由论文作者后处理，虽然提供了脚本，但其他研究复现可能产生偏差。  
- **未见真实部署评估**：原型在基准和重放中验证，缺少与工业级多智能体系统的集成/用户研究。  
- **未披露具体 LLM 模型和算力**：降低了可复现性，也可能影响结论的外部效度。
