## 摘要
智能体技能通过可复用的指令包扩展 LLM 智能体，这些指令包还可能包含脚本、资源和服务配置。这为恶意行为提供了直接的传播渠道，然而现有的恶意技能数据集在来源、工件格式、证据机制和良性覆盖方面较为分散；重复且在结构上相关的内容进一步使直接聚合与评估变得复杂。我们提出了 MaliciousSkillBench，一个用于恶意智能体技能检测的综合基准。我们整合了 13 个公开来源，其中 11 个贡献了核心恶意工件，并将 8,414 条原始恶意记录归纳为 4,588 个可运行结构家族中的 7,539 个归一化唯一标识。在保守地排除交叉标签冲突后，主基准包含 9,740 项技能：7,505 项恶意和 2,235 项良性。为了刻画其覆盖范围，我们为 4,983 个恶意标识统一了 11 个攻击类别，并提供有支持的来源原生映射，发现不同来源之间的威胁构成存在显著差异。随后我们评估了三种学习型文本检测器和三种现成的技能扫描器。学习型检测器在随机划分下取得 0.882-0.932 的宏 F1，但在来源分离评估下仅有 0.653-0.665；最强的词 TF-IDF SVM 在随机划分/结构分离/来源分离上分别取得 0.932/0.916/0.665，同时保持 95.6% 的恶意召回率，但在留出来源上产生 62.4% 的良性误报率。现成扫描器处于不同但同样不理想的工作区间，其降低误报的代价是恶意召回率急剧下降。总体而言，这些结果表明，可靠的恶意技能检测既需要更广泛的跨来源基准覆盖，也需要能够同时衡量攻击检测与良性误报的评估方法。

## Abstract
Agent Skills extend LLM agents with reusable instruction packages that may also include scripts, resources, and service configuration. This creates a direct distribution channel for malicious behavior, yet existing malicious-Skill datasets are fragmented across sources, artifact formats, evidence regimes, and benign coverage; duplicated and structurally related content further complicates direct aggregation and evaluation. We present MaliciousSkillBench, a comprehensive benchmark for malicious Agent Skill detection. We consolidate 13 public sources, 11 of which contribute Core malicious artifacts, and reduce 8,414 raw malicious records to 7,539 normalized-unique identities in 4,588 operational structural families. After conservative cross-label conflict exclusion, the primary benchmark contains 9,740 Skills: 7,505 malicious and 2,235 benign. To characterize its coverage, we harmonize 11 attack categories for 4,983 malicious identities with supported source-native mappings and find substantial differences in threat composition across sources. We then evaluate three learned text detectors and three off-the-shelf Skill scanners. Learned detectors achieve 0.882-0.932 Random Macro-F1 but only 0.653-0.665 under Source-Disjoint evaluation; the strongest word TF-IDF SVM scores 0.932/0.916/0.665 on Random/structural-disjoint/Source-Disjoint while retaining 95.6% malicious recall but producing 62.4% benign FPR on held-out sources. Off-the-shelf scanners occupy different but also unsatisfactory operating regimes, reducing false positives only at the cost of sharply lower malicious recall. Together, these results show that reliable malicious-Skill detection requires both broader cross-source benchmark coverage and evaluation that jointly measures attack detection and benign over-flagging.

## 2. 论文提出的方法论

### 2.1 数据整合与规范化
- **来源收集**：冻结 13 个公开恶意 Skill 数据集/安全语料，保留 11 个满足严格 Core 恶意工件规则的来源。
- **Core 恶意工件规则**：只有可恢复为实际 Skill 工件（`skill.md` 或 `skill package`）、保留来源原生恶意声明与支持性证据、保持工件惰性（不执行）、且可追溯到冻结来源修订的记录才进入 Core 恶意池。
- **证据保留式规范化**：每条记录获得稳定 canonic ID，同时保留来源 ID、来源标签、来源修订、工件类型、provenance、标签强度、证据类型、哈希及 lineage 元数据。来源标签保守映射，`vulnerable`、`suspicious`、`dual-use`、`scanner-flagged` 不被升级为恶意真值。
- **处理原则**：所有潜在恶意工件作为惰性静态数据处理，不执行任何脚本、payload、URL、安装器或嵌入指令。

### 2.2 去重与结构复用控制
- **三层关系区分**：
  - **精确身份**：SHA-256 哈希。
  - **归一化身份**：确定性保守文本归一化（UTF-8 解码、BOM 移除、行尾统一、尾部空白去除、多余空行折叠等），保留实质文本。
  - **结构复用**：独立于身份与威胁语义，对每个归一化恶意身份取一个代表性工件，使用冻结静态相似度管线在阈值 0.68 下得到 4,588 个操作性结构家族。
- **数据缩减**：8,414 条原始 Core 恶意记录 → 7,562 精确唯一 → 7,539 归一化唯一恶意身份。

### 2.3 良性池与标签冲突过滤
- **良性池**：48,217 条良性候选分为 Main 与 Auxiliary。Main 良性要求实际 Skill 工件 + 强/中等良性证据；弱负样本（marketplace-unflagged、scanner-clean 等）留在 Auxiliary。
- **冲突排除**：比较恶意/良性侧精确与归一化身份，34 个归一化身份出现交叉标签冲突，全部排除出主评估。
- **最终基准**：9,740 归一化唯一 Skills = 7,505 恶意 + 2,235 良性。

### 2.4 威胁刻画
- 仅使用文档化的来源原生标签和确定性强语义映射，将 11 个攻击类别 harmonize 到 4,983 个恶意身份（66.4%）。
- 攻击类别包括：执行/代码投递、指令/目标/记忆操纵、特权/工具滥用、数据外泄、资源/可用性滥用、凭据访问、持久化/控制、供应链滥用、完整性/输出操纵、防御逃避、发现。
- 该 11 类别为多标签，来源间威胁构成显著不同。

### 2.5 评估协议
- **随机划分**：标签分层 70/10/20。
- **Source-Balanced Random**：来源×标签队列内分配，控制来源构成漂移。
- **Malicious-Structural-Disjoint**：4,588 个恶意结构家族原子跨 train/val/test。
- **Source-Disjoint**：完全留出 SRC009、SRC011、SRC012（移除 8 个跨边界身份），测试集 839 恶意 + 545 良性。
- **对比方法**：
  - 学习型文本检测器：词 TF-IDF + 逻辑回归、词 TF-IDF + 线性 SVM、字符 TF-IDF + 线性 SVM。
  - 现成扫描器：Cisco-local-behavioral（HIGH/CRITICAL gate）、SkillFortify-offline（MEDIUM+）、SkillSpector-static（LLM 禁用，block gate）。

## 3. 实验设计

- **数据集/场景**：归一化主基准 9,740 Skills；恶意侧来自 11 个 Core 来源，良性侧来自 5 个来源（SRC006、SRC008、SRC010、SRC011、SRC012）。
- **检测器输入**：仅使用惰性主 Skill 指令文本，排除来源 ID、路径、provenance、结构家族 ID 等元数据。
- **协议对比**：随机、Source-Balanced Random、Malicious-Structural-Disjoint、Source-Disjoint。
- **消融/鲁棒性控制**：
  - 类别平衡子集（每分区恶意多数类下采样到与良性 1:1）。
  - 审计脚手架清洗（移除 7 类固定构造包装器，保留攻击语义）。
  - 格式-only 基线（5 个标量特征：字符长度、行数、Markdown 标题数、代码块数、URL 数）。
  - Leave-one-source-out（LOSO）诊断。
- **攻击分层分析**：将扫描器判决与 harmonized 攻击映射关联，报告类别级召回。
- **扫描器评估**：同一主静态工件上运行三个固定配置扫描器；覆盖度/技术弃权单独报告。

## 4. 资源与算力

- **论文中未明确报告 GPU 型号、GPU 数量或训练时长**。
- 主动说明所用模型：
  - 主要学习型基线为 **TF-IDF + 线性模型（逻辑回归/LinearSVC）**，无需 GPU。
  - 辅助 MiniLM embedding 基线使用本地缓存的 `sentence-transformers/paraphrase-MiniLM-L6-v2`，384 维 embedding，无微调；未报告该基线推理所需具体 GPU 显存或时间。
- 静态文本处理、特征提取、扫描器集成均在本地静态环境执行，不涉及恶意 payload 执行。
- 实验资产规模：
  - 29,220 个 scanner-item 作业（9,740 × 3）。
  - 序列化 seed-42 估计器、MiniLM embedding 矩阵等被冻结发布。
- 结论：**算力细节不完整，未提供可复现的硬件/运行时消耗信息**，但对所述轻量实验而言算力需求较低。

## 5. 实验数量与充分性

- **实验组数量较多**，覆盖以下维度：
  - 4 个主协议 × 3 个学习型检测器（主结果 + 完整混淆矩阵 + 类别指标）。
  - 3 个固定扫描器在 4 个协议上的结果，以及 3 个技术弃权与 bootstrap 置信区间。

  - LOSO 转移诊断（4 个来源）。
  - Source-Disjoint 词 SVM 的按来源错误分解。
  - 线性特征审计 / marker 审计。
- **充分性评价**：

  - 消融与鲁棒性控制已预设，结论有支撑。
  - 对扫描器无法训练、固定配置的特点，报告了覆盖/技术弃权/源重叠敏感性，较严谨。

## 6. 论文的主要结论与发现

- **源覆盖与威胁多样性**：
  - 11 个 Core 来源贡献的威胁类别分布差异显著，不同数据集侧重不同攻击切片。
  - 最常见的 harmonized 攻击是执行/代码投递（3,320 身份）、指令/目标操纵（1,671）、特权/工具滥用（1,013）。
  - 没有任何单一来源能够代表完整恶意 Skill 威胁空间。

- **检测器随机评估高估鲁棒性**：
  - 随机宏 F1 为 0.882–0.932，Source-Disjoint 降至 0.653–0.665。
  - 最强词 TF-IDF SVM：随机 0.932 / 恶意结构分离 0.916 / 源分离 0.665。

- **跨源主要失败在良性误报**：
  - Source-Disjoint 下学习型检测器恶意召回保持 94.4–95.7%，但良性 FPR 达 62.0–64.4%。
  - 词 SVM 在源分离中只漏掉 37/839 个恶意，却误报 340/545 个良性；SRC011 贡献 293 个误报。

- **现成扫描器同样存在权衡**：
  - Cisco 与 SkillSpector 良性 FPR 极低（1.1%、0.55%），但恶意召回只有 2.5% 和 0%。
  - SkillFortify 恶意召回 25.3% 但良性 FPR 49.9%。
  - 没有评估方法同时实现高恶意召回和低良性 FPR。

- **鲁棒性控制**：
  - 类别平衡使词 SVM Source-Disjoint F1 从 0.665 提高到 0.710、FPR 从 62.4% 降至 43.3%，但源条件差距仍存在。
  - 脚手架清洗无法消除源分离退化（清洗后源分离 F1 0.643–0.662）。
  - 表明跨源退化不能仅归因于类不平衡或已审计的构造包装器。

## 7. 优点

- **综合性与可追溯性**：整合 13 个来源，冻结修订，保留来源 ID、provenance、证据强度、lineage 等，使数据集构建透明且可审计。
- **严格身份与冲突控制**：区分精确哈希、归一化哈希、结构家族三层复用；保守排除 34 个跨标签冲突身份，避免错误真值。
- **威胁刻画有边界**：只使用来源原生标签和确定性映射，不从小文本推断攻击，明确攻击映射覆盖 66.4%，防止过度泛化。
- **评估协议设计合理**：随机、结构分离、源分离三种视角，Source-Disjoint 揭示源条件退化，凸显良性误报与恶意召回的 trade-off。
- **两类检测器对比**：学习型与固定扫描器在同一惰性工件上比较，操作点敏感性、源重叠、技术弃权均有报告。
- **伦理与安全措施**：静态处理，不执行恶意内容；对 5 个敏感凭据恶意身份提供脱敏表示；发布/维护契约分层清晰。

---

## 8. 不足与局限

- **来源覆盖有限**：综合仅针对 13 个冻结公开来源，不涵盖全新或未来的恶意技能生态；Source-Disjoint 仅留出 3 个来源，不能外推为普遍泛化。
- **良性池较窄、来源不平衡**：Main benign 仅来自 5 个来源，且 SRC010/SRC011 占主导；良性覆盖明显窄于恶意侧，类别平衡控制不能完全解决源耦合。
- **Source-Disjoint 归因困难**：留出来源与标签混合、构造程序、文档风格、provenance 等多因素耦合，无法分离因果效应。
- **检测器范围有限**：学习型基线只使用主 Skill 指令文本，未使用包级脚本、运行时行为、代码语义或多模态资源；扫描器为固定外部配置，不构成模型能力对照。
- **结构家族解释受限**：4,588 结构家族基于静态相似度阈值，不包含攻击机制或阵营语义，聚类可能存在过链/漏链。
- **攻击映射与影响覆盖不完整**：攻击映射仅覆盖 66.4% 恶意身份；派生影响仅覆盖 28.4%，且 subset 存在来源浓度。
- **算力/硬件报告不足**：未提供 GPU/训练时长等消耗数据，虽对轻量方法可不关键，但不利于完全复现。
- **扫描器源重叠敏感**：SkillFortify 受 SRC012 重叠影响，排除后性能显著下降，表明扫描器结果解释需谨慎。
- **LR/SVM 未在验证集调阈值**：结果基于固定决策分数，可能存在阈值选择不优的问题。
