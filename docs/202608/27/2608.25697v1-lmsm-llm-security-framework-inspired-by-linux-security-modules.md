## 摘要
大型语言模型（LLM）越来越多地采用分层防御进行部署，但恶意提示仍可能绕过这些防御。可解释性方法能够暴露生成路径上的模型内部信号，这些信号可为执行策略提供依据，但其本身并非安全控制。将其用于安全目的的部署通常把每个信号与其各自的校准、策略逻辑和干预代码耦合，因此每新增一个工件都会带来集成工作，而不是强化共享防御。我们提出语言模型安全模块（LMSM），这是一个将 Linux 安全模块（LSM）背后的分离思想适配到 LLM 服务的安全框架。在 LMSM 中，选定的安全后端暴露经过校准的证据，带版本的策略根据可信的逐请求上下文评估活动规则，独立的门控授权缓冲输出的释放。该设计将中介正确性与策略有效性分离，并允许后端、规则或调度变更，而无需重建请求处理或执行逻辑。我们的原型展示了这种分离在实际中的效果：借助 Hugging Face Transformers 和连续批处理的 vLLM，同一基础平台承载了由工件支持的稀疏自编码器（SAE）与转码器部署以及面向任务拟合的稠密探针，在调度器波动下保持逐请求决策，并有选择地对每个请求执行和组合多条规则。在 Qwen3-4B 上，LMSM-Checkpoint 将 HarmBench 攻击成功率从 39.20% 降至 3.32%，XSTest 误拒率从 2.40% 升至 4.40%，同时在 32 条活跃序列下保留了不执行任何监控工作的匹配服务路径 98.14% 的吞吐量。LMSM 为可解释性和模型内部分析的进展提供了一条通向运行时执行的通用路径。

## Abstract
Large language models (LLMs) are increasingly deployed with layered defenses, yet malicious prompts can still bypass them. Interpretability methods can expose model-internal signals along the generation path that could inform enforcement, but these signals are not security controls by themselves. Deployments that adapt them for safety typically couple each signal to its own calibration, policy logic, and intervention code, so each new artifact creates integration work instead of strengthening a shared defense. We present Language Model Security Modules (LMSM), a security framework that adapts the separation behind Linux Security Modules (LSM) to LLM serving. In LMSM, a selected security backend exposes calibrated evidence, a versioned policy evaluates active rules over trusted per-request context, and a separate gate authorizes buffered output release. This design separates mediation correctness from policy effectiveness, and it allows backend, rule, or schedule changes without rebuilding request handling or enforcement. Our prototype shows the separation working in practice: with Hugging Face Transformers and continuously batched vLLM, the same substrate hosts artifact-backed sparse autoencoder (SAE) and transcoder deployments and task-fitted dense probes, preserves request-specific decisions under scheduler churn, and selectively enforces and composes multiple rules per request. On Qwen3-4B, LMSM-Checkpoint reduces HarmBench attack success rate from 39.20% to 3.32%, with XSTest false refusals rising from 2.40% to 4.40%, while retaining 98.14% of the throughput of a matched serving path that performs no monitoring work at 32 active sequences. LMSM gives advances in interpretability and model-internal analysis a common path to runtime enforcement.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 部署中虽然已有多层防御（对齐、提示控制、外部 guard），但恶意提示仍可能绕过这些防御。
- **核心问题**：可解释性方法（如稀疏自编码器、转码器、探针）能暴露模型内部信号，可用于安全判断，但这些信号本身不是安全控制；现有做法往往将每个信号与各自的校准、策略逻辑和干预代码绑定，导致每新增一个工件就要重建一套 guard 堆栈，缺乏共享的运行时执法机制。
- **整体含义**：论文提出 LMSM（Language Model Security Modules），借鉴 Linux 安全模块（LSM）的设计哲学，将模型内部证据的暴露、策略评估、输出授权三者分离，为 LLM 服务提供一个可重用的运行时执法基板，使可解释性研究成果无需修改服务架构就能用于安全执行。

## 2. 论文提出的方法论

- **核心思想**：将 LSM 的“内核提供中介点、模块提供策略、内核执行结果”分工迁移到 LLM 服务：
  - **安全后端**：暴露经过校准的模型内部证据；
  - **版本化策略**：基于可信的逐请求上下文评估活动规则；
  - **独立门控**：授权缓冲输出的释放。
- **系统模型**：
  - 部署操作员（operator）安装三类配置：后端绑定、版本化规则库、一个活动策略束。
  - 受保护的转换是 `LMSM runner/wrapper` 向外部释放响应。
- **核心对象与形式化**：
  - **后端契约**：给定激活矩阵 \(H_t \in \mathbb{R}^{N_t \times d}\)，后端观察映射 \(E_t = \text{Observe}_\beta(H_t) \in \mathbb{R}^{N_t \times K}\)，为每个活跃请求提供 \(K\) 个证据通道 \(E_{r,t,k}\)。
  - **原子规则**：\(\rho_i = (g_i, K_i, c_i, a_i, v_i)\)，其中 \(g_i\) 是目标，\(K_i\) 是证据通道子集，\(c_i\) 是校准条件，\(a_i\) 是候选动作，\(v_i\) 是规则版本。
  - **策略束**：\(P = (I_P, \{\rho_i\}_{i \in I_P}, \text{sched}_P, \prec_P, \text{resolve}_P, v_P)\)，记录活动规则集、时间调度、规则优先级顺序、动作映射和版本。
  - **两阶段评估**：状态更新 \(x_{r,t} = U_P(x_{r,t-1}, E_{r,t})\)；规则评估 \(\text{EvalRule}(\rho_i, x_{r,t})\) 返回候选动作或 \(\bot\)；固定 OR 组合：若多个规则同时触发，按声明顺序选择第一个。
  - **决策类型**：`allow`、`terminate`、`refuse`。
- **关键设计**：
  - **请求键控状态**：策略状态按主机提供的稳定请求 ID 存储，而非瞬态 batch 行索引。
  - **选择性执法**：只停止/拒绝选中的请求，不影响批次中其他请求。
  - **审计记录**：同步创建干预记录，包含请求 ID、目标、规则、分数/阈值、步骤、版本、token 视图等。
  - **后端供应方式**：artifact-backed（绑定已发布工件如 SAE / transcoder）与 task-fitted（针对部署目标学习/适配稠密探针等）两种路径。

## 6. 论文的主要结论与发现

- LMSM 能够在连续批处理下保持逐请求决策隔离：所有 32 对重复请求在调度抖动下保持动作、类别、干预步骤和完整阈值穿越向量一致。
- 后端替换无需更改请求处理、评估器接口或执法路径；稠密探针与 transcoder 绑定均能通过共同契约运行。
- **策略有效性**：在 Qwen3-4B 上，LMSM-Checkpoint 将 HarmBench ASR 从 39.20% 降至 3.32%，WildJailbreak ASR 从 41.90% 降至 7.35%；LMSM-Anytime 分别降至 6.81% 和 6.00%。相对 Matched Disabled 降低 82.5%–91.5%。
- **误拒绝代价**：XSTest FRR 从 2.40% 升至 Checkpoint 的 4.40% 和 Anytime 的 5.60%，数值上低于多数外部训练时防御方法（除 SafeKey 外）。
- **服务开销**：宽度 32 时 Checkpoint 保留 98.14% 吞吐量，15 条规则时保留 96.89%；Anytime 保留 83.91%，因其每步更新 running-prefix 证据。
- **时间权衡**：Checkpoint 以固定低开销决策，Anytime 以更高监控成本换取更早干预（中位首次干预步骤 15 vs 64）。

## 7. 优点

- **架构分离清晰**：将后端证据、策略评估、执法门控解耦，遵循参考监视器原则，便于局部演进。
- **实用性强**：支持 artifact-backed 和 task-fitted 两种后端供应方式；与 Hugging Face Transformers 和 vLLM 集成，保持高吞吐（98% 以上）。
- **评估严谨**：使用匹配的 disabled 和 empty extension baseline 分离策略行动与监控成本；用外部评判器；提供详细的调度抖动隔离验证。
- **开源可复现**：提供了实现和复现 artifact，包含四个部署配置和记录参数。
- **对可解释性领域的贡献**：为 SAE、transcoder、稠密探针等模型内部分析方法提供了统一的运行时执行路径。

## 8. 不足与局限

- **执行环境限制**：仅在单 GPU H100、eager vLLM 上测试，未覆盖多 GPU、编译执行或 CUDA graph 等生产环境。
- **单一活跃后端绑定**：每个部署策略只支持一个后端绑定和一个激活位点，尚未支持多后端或多激活位点的证据组合。
- **动作种类有限**：仅支持 allow、terminate、refuse；未实现 redaction、受控重生成、二次复核路由等动作。
- **对抗鲁棒性**：论文承认可解释性监视可能被自适应混淆攻击绕过；未测试对抗性输入下的表现。
- **策略拟合与校准未完全公开重建**：复现工作流跳过数据标注、探针拟合和阈值选择；外部训练时方法未在同一路径重跑。
