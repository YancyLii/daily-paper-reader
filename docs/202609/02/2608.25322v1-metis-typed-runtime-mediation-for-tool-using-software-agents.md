## 摘要
软件代理将概率模型输出连接到改变代码仓库、进程、网络和图形应用程序的操作。我们提出了 Metis，一个多提供商运行时，它在获准调用触及外部副作用之前将提供者流转换为类型化事件。其执行路径使权限决策、干扰类别、终端结果和生命周期转换明确且可检查。我们在冻结的源代码工件上评估这些机制。在30个匹配的真实 I/O 对中，四类中介将中位耗时从强制串行化下的25.958毫秒降低到14.146毫秒。平均配对差异为-12.295毫秒（95%自助置信区间[-12.968, -11.694]），且在所有配对中中介更快。一个包含十个案例的故障矩阵暴露了重复标识符和回滚限制。在子边界消融中，完整的门控加注册表条件阻止了所声明的未授权效果，并隐藏了所有五个逃逸工具。移除这两项保护后，两个观察结果均被逆转。仅决策的权限预言机在五个调用路径上匹配了全部十个声明案例。五个模型条件也在固定Read-marker协议中各自完成了3/3次试验。这些结果支持关于调度、权限路由、子权限和提供者验证的踪迹闭包的有界声明。它们并未确立模型能力、语义安全、回滚或相对于其他运行时的优越性。

## Abstract
Software agents connect probabilistic model output to operations that change repositories, processes, networks, and graphical applications. We present Metis, a multi-provider runtime that converts provider streams into typed events before admitted calls reach external effects. Its execution path makes permission decisions, interference classes, terminal results, and lifecycle transitions explicit and inspectable. We evaluate these mechanisms on frozen source artifacts. Across 30 matched real-I/O pairs, four-class mediation reduced median elapsed time from 25.958 ms under forced serialization to 14.146 ms. The mean paired difference was -12.295 ms (95% bootstrap interval [-12.968, -11.694]), with mediation faster in all pairs. A ten-case fault matrix exposed duplicate-identifier and rollback limits. In a child-boundary ablation, the full gate-plus-registry condition blocked the declared unauthorized effect and hid all five escape tools. Removing both protections reversed both observations. A decision-only permission oracle matched all ten declared cases across five invocation routes. Five model conditions also completed a fixed Read-marker protocol in 3/3 trials each. These results support bounded claims about dispatch, permission routing, child authority, and provider-valid trace closure. They do not establish model competence, semantic safety, rollback, or superiority over another runtime.

## 1. 论文的核心问题与整体含义

- **研究背景**：软件工程代理不仅给出代码建议，还能修改仓库、调用构建/测试进程、访问远程服务、控制图形界面。模型的 token 输出通常可忽略，但一条被执行的命令或指针操作可能已经改变外部状态。
- **核心问题**：在模型提出工具调用之后，**谁负责准入、排序、记录终端结果，并在中断或上下文压缩后保持提供者有效历史？** 现有研究多聚焦于策略（ReAct、Toolformer）或任务环境（SWE-agent、OpenHands），缺少一个位于模型与环境之间的运行时中介层。
- **整体含义**：Metis 将“运行时”本身作为软件工程对象，通过类型化事件和可检查的执行轨迹，在外部效果发生前显式处理权限、调度、结果与生命周期，从而回答下游系统问题，同时避免声称模型能力、语义安全或跨运行时优越性。

- **关键机制**：
  - **权限门控**：函数 `d(u, σ) ∈ {allow, ask, deny}`，采用五模式（default、acceptEdits、bypassPermissions、plan、dontAsk），按公式 `d(u, σ)` 的优先顺序解析：plan 边界 → bypass-immune 检查 → 规则匹配 → 路径范围 → 模式回退。**批量预检**要求所有 ask 决策在首个 admitted 效果开始前完成（公式 7）。
  - **四类调度**：`κ(u) ∈ {Safe, Queue, Exclusive, Background}`。Safe 并发；Queue 单 FIFO 串行但可与 Safe 重叠；Exclusive 等待前一波并串行；Background 返回握手、分离执行。理想关键路径公式 `T*` 考虑了各集合的服务/握手时间与 Exclusive 序列。

- **评估对象**：冻结的运行时源码工件、companion 实现和权限路由闭包变体，基于私有证据清单（公开存档为未来工作）。

## 6. 论文的主要结论与发现

- 四类调度在 30 对中全部快于强制串行：中位耗时 14.146 ms vs 25.958 ms，平均差异 -12.295 ms（95% 自助区间 [-12.968, -11.694]）。
- 故障矩阵暴露**重复标识符**和**回滚限制**：重复 ID 产生两个结果块但只有一个唯一终端 ID；写入后失败会残留状态；重启后重复 ID 无法一对一闭合。
- 子边界消融：完整保护阻止未授权效果并隐藏 5/5 逃逸工具；移除后全部放行，验证了边界后果。
- 权限预言机：10/10 匹配声明决策，无假阳/假阴。
- 模型协议：5 个条件 3/3 通过，共 15/15；一个模型因 HTTP 404 被排除为可用性排除。
- 探索性维护：中介条件记录 3 次完整治疗激活，任务本地通过但整树回归失败；不能作为效果估计。
- 总体结论：支持关于**调度、权限路由、子权限和提供者有效轨迹闭合**的有界声明；**不建立**模型能力、语义安全、回滚或相对其他运行时的优越性。

## 7. 优点

- **显式可检查的执行轨迹**：通过类型化事件图使权限、调度、结果、生命周期成为可审计对象，提升可观测性。
- **设计分离清晰**：策略（policy）、任务环境（harness）与运行时（runtime）被明确区分为不同对象，避免推理错误。
- **批量权限预检**：所有 ask 决策先于任何 admitted 效果，降低部分授权后的效应泄露风险。
- **四类调度兼顾安全与并发**：Safe 并发、Queue 串行、Exclusive 屏障、Background 分离，避免不必要串行化。
- **终端结果闭合与孤儿修复**：即使工具失败、取消或重启，也尽力保持提供者协议有效，且不伪装为事务回滚。
- **实验报告坦白**：指出冻结套件存在失败、覆盖率不完整、权限预言机不执行效果、维护对不可估计效应等，增加了可信度。

## 8. 不足与局限

- **无跨运行时对比**：调度结果仅与自身 forced-serial 变体比较，1.835 倍比值不是通用加速比。
- **单主机、单工作负载**：真实 I/O 只覆盖本地文件、Git、回环 HTTP、一次写入，未涉及远程网络、大仓库、GUI 或竞争运行时。
- **权限预言机不执行效果**：只验证声明决策，未验证实际状态变化或对抗性绕过。
- **模型协议过于简单**：单一 Read-marker 任务无法推广到其他事件或任务。
- **子边界消融无法分离组件**：同时移除 gate 和 registry，不能估计各自贡献。
- **维护任务证据薄弱**：仅 1 对、1 个模型、1 个任务、无重复，不能建立维护有效性；整树严格规则下两者均失败。
