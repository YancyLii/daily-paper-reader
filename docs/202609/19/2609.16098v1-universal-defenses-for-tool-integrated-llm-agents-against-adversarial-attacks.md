## 摘要
大语言模型（LLM）智能体已在多个领域展现出令人印象深刻的能力，特别是在与外部工具集成以完成多步骤任务时。然而，它们正日益容易受到对抗攻击的影响，包括直接提示注入、间接提示注入、记忆投毒和后门攻击，这些攻击利用了模型对提示注入和工具操纵的开放性。本文在一个统一框架内，针对这四种攻击类型探索了实用且具有泛化能力的防御策略。我们提出了两种通用的基于工具的防御方法：攻击者工具过滤（Attacker Tool Filtering），它利用异常检测（如孤立森林）识别并移除可疑工具；以及正常工具恢复（Normal Tool Recalling），一种白盒方法，可在规划前恢复智能体的原始工具集。此外，我们还引入了基于提示的防御方法：思维链提示和自反思技术以增强推理，以及任务改写以缓解攻击。在四个开源 LLM（Gemma2-9B、Qwen2-7B、LLaMA3-8B 和 LLaMA3.1-8B）和三个闭源 LLM（GPT-3.5、GPT-4 和 GPT-5）上的实验结果表明，我们的方法显著降低了攻击成功率（ASR），在许多设置下 ASR 达到 0%，同时保持甚至提高了原始任务成功率。这些结果凸显了简单、模块化、多层防御在增强工具集成 LLM 智能体安全性和鲁棒性方面的前景。代码见 https://github.com/Xiaoyan-Lisa/Defenses-for-Tool-Integrated-LLM-Agents-Against-Adversarial-Attacks。

## Abstract
Large Language Model (LLM) agents have demonstrated impressive capabilities across a variety of domains, particularly when integrated with external tools for multi-step task completion. However, they are increasingly vulnerable to adversarial attacks, including direct prompt injection, indirect prompt injection, memory poisoning, and backdoor attacks, which exploit the model's openness to prompt injection and tool manipulation. In this work, we explore practical and generalizable defense strategies within a unified framework across these four attack types. We introduce two universal tool-based defenses: Attacker Tool Filtering, which uses anomaly detection (e.g., Isolation Forest) to identify and remove suspicious tools, and Normal Tool Recalling, a white-box method that restores the agent's original toolset prior to planning. Additionally, we incorporate prompt-based defenses: Chain-of-Thought prompting and self-reflection techniques to enhance reasoning and task paraphrasing to mitigate attacks. Experimental results across both four open-source LLMs (Gemma2-9B, Qwen2-7B, LLaMA3-8B, and LLaMA3.1-8B) and three proprietary LLMs (GPT-3.5, GPT-4, and GPT-5) show that our methods significantly reduce the Attack Success Rates (ASR), achieving 0% ASR in many settings, while preserving or even improving the original task success rate. These findings highlight the promise of simple, modular, multi-layered defenses for strengthening the security and robustness of tool-integrated LLM agents. The code is available at https://github.com/Xiaoyan-Lisa/Defenses-for-Tool-Integrated-LLM-Agents-Against-Adversarial-Attacks.

## 2. 论文提出的方法论

论文提出**三层防御框架**：

- **外层：提示级防御**
  - 在用户输入后、规划生成前，应用 **思维链（CoT）提示** 和 **任务改写（Paraphrasing）**。
  - CoT 采用结构化 JSON 格式，引导智能体逐步推理并选择安全工具。
  - 改写使用 GPT-4o-mini 对用户任务进行重新表述，显式引用正常工具，破坏对抗性指令结构和隐藏触发器。

- **中层：工具级防御**
  - **Attacker Tool Filtering（ATF，攻击者工具过滤）**：
    - 使用句子嵌入模型将每个工具描述转换为向量。
    - 训练孤立森林（Isolation Forest）进行异常检测。
    - 被判定为异常的工具会被过滤，智能体只使用剩余工具进行规划。
    - 形式化：对工具集 \(T=\{\tau_1,\dots,\tau_N\}\)，得到嵌入 \(E=\{\phi(\tau_i)\}\)；训练 \(F_{\text{IF}}=\text{IsolationForest}(E;\epsilon)\)；对每个工具预测异常标签 \(y_i\in\{0,1\}\)；过滤后工具集 \(T_{\text{filtered}}=\{\tau_i\mid y_i=0\}\)。
  - **Normal Tool Recalling（NTR，正常工具恢复）**：
    - 白盒方法：在规划前将当前可能被污染的工具集替换为用户原始可信工具集 \(T_{\text{user}}\)。
    - 不需要识别恶意工具，只需恢复可信工具配置。
    - 规划阶段：\(P=\text{LLM}(p_{\text{sys}}, q, O, T_{\text{effective}})\)，其中 \(T_{\text{effective}}\leftarrow T_{\text{user}}\)。

- **内层：自反思（Self-Reflection）**
  - LLM 同时扮演反思模块和评估器，对生成的计划进行验证和修正。
  - 反思提示要求计划必须使用允许的工具列表，步骤至少两步，工具使用字段非空，逻辑顺序合理。

- **核心思想**：
  - 工具层防御直接消除攻击者控制的工具，而不是仅修改提示。
  - 提示层防御增强推理、净化输入、引导安全规划。
  - 多层组合形成互补，提高鲁棒性。

## 3. 实验设计

- **基准与数据集**：
  - 使用 **ASB（Agent Security Bench）** 框架，这是一个综合基准，实现了 DPI、IPI、MP 和后门攻击四类攻击。
  - ASB 数据集包含 **10 个领域特定的 LLM 智能体**，每个智能体有正常工具和攻击者工具。
  - 每个智能体包含 **400 个任务**：200 个 aggressive attack 任务，200 个 non-aggressive attack 任务。

- **攻击变体**：
  - **DPI / IPI**：Naive Attack、Escape Characters、Context Ignoring、Fake Completion。
  - **MP**：Fake Completion + Context Ignoring 组合。
  - **后门攻击**：PoT（Plan-of-Thought）后门，包含非词触发（如“@_@”）和短语触发（如“with perspicacious discernment”）。

- **对比方法**：
  - 无防御（No Defense）。
  - ASB 中的 baseline：DPI 和后门使用 **paraphrasing**；IPI 使用 **delimiters**。
  - 本文方法：ATF + CoT + Paraphrasing + Reflection，以及 NTR + CoT + Paraphrasing + Reflection。

- **评估模型**：
  - 开源：Gemma2-9B、Qwen2-7B、LLaMA3-8B、LLaMA3.1-8B。
  - 闭源：GPT-3.5、GPT-4、GPT-5（GPT-5 结果在附录中）。
  - 主要正文表格包含 6 个模型，附录中补充 GPT-5。

- **评估指标**：
  - **ASR（Attack Success Rate）**：攻击任务中智能体实际使用攻击专用工具的比例。
  - **OTSR（Original Task Success Rate）**：原始正常任务成功完成的比例。

- **消融实验**：
  - 在 Context Ignoring DPI 攻击下，对 NTR 相关防御进行组件消融：
    - 完整方案（NTR+CoT+P+R）
    - 缺少 NTR
    - 缺少 CoT
    - 缺少 Paraphrasing
    - 缺少 Reflection
  - 用于衡量各组件对 ASR 和 OTSR 的贡献。

## 6. 论文的主要结论与发现

- **NTR 方法最有效**：
  - 在多种攻击场景下（IPI、MP、后门）实现 0% 或接近 0% 的 ASR。
  - 在开源模型上通常还能提高 OTSR。
- **ATF 也能降低 ASR**，但效果不如 NTR 稳定，不同模型/攻击下表现差异较大。
- **提示级防御与工具级防御结合具有互补性**：
  - 对多数模型，完整组合（NTR + CoT + Paraphrasing + Reflection）达到最低 ASR 和较高 OTSR。
  - Paraphrasing 在提示防御中影响最大，但单独使用效果有限。
  - NTR 是关键组件，省略 NTR 会导致 ASR 显著上升。
  - CoT 和 Reflection 对部分模型有益，但对 GPT 模型尤其 GPT-3.5 可能降低 OTSR。
- **模型安全性并不与规模成正比**：
  - GPT-3.5 和 GPT-4 在无防御时 DPI 的 ASR 高于小型开源模型（GPT-3.5 为 0.9469，GPT-4 为 0.9156）。
  - 防御后 GPT 模型虽然 ASR 降低，但 OTSR 可能明显下降，体现出更强的鲁棒性-效用权衡。
- **GPT-5 在无防御时更鲁棒**，ASR 较低，但 OTSR 也较低；NTR 能实现 0% ASR 并改善 OTSR。

## 7. 优点

- **统一性**：一个框架同时应对四类主要攻击，填补了通用防御的空白。
- **轻量、模块化**：方法简单，易于部署，不需要复杂训练或攻击先验知识。
- **白盒与黑盒结合**：NTR 利用白盒工具状态，ATF 利用无监督异常检测，提示防御利用黑盒能力。
- **保持任务性能**：在多数开源模型上，NTR 不仅降低 ASR，还提升 OTSR。
- **评估广泛**：覆盖 7 个模型、多种攻击变体、消融实验，并与现有 ASB baseline 对比。
- **可复现性**：代码开源，提供了详细算法、提示模板和实验设置。
- **发现重要现象**：更大模型并不天然更安全，防御对模型能力敏感，为后续研究提供参考。

## 8. 不足与局限

- **动态环境未评估**：论文明确承认未在动态、交互式环境中测试方法，真实世界部署的有效性尚待验证。
- **NTR 依赖白盒假设**：需要能够访问并恢复用户原始可信工具集，在部分实际系统中可能不具备条件。
- **ATF 表现不稳定**：在不同模型和攻击类型下，ATF 的 ASR/OTSR 结果不一致，需要进一步改进。
- **对 GPT 模型有副作用**：NTR 或完整防御在 GPT-3.5、GPT-4 上常导致 OTSR 明显下降，防御可能过度干预模型规划。
- **MP 攻击基线不足**：ASB 为 MP 提供的专用防御较少，论文在 MP 下只与无防御对比，削弱了该部分的对比强度。
- **算力与成本信息缺失**：未报告实验所需的硬件、推理成本或时间，难以评估资源需求。
- **改写依赖外部模型**：使用 GPT-4o-mini 进行改写会引入对额外 API 的依赖，也带来新的隐私或成本风险。
- **潜在偏差**：实验集中在 ASB 静态基准，任务和攻击分布可能不完全代表真实世界中的对抗多样性。
