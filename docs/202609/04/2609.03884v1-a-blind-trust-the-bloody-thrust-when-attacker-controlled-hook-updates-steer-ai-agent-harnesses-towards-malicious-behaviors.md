## 摘要
现代 AI 智能体执行框架暴露了生命周期钩子，这些钩子将 shell 命令绑定到会话开始、工具调用和文件编辑等运行时事件。这些命令以主机权限运行，却作为生命周期钩子配置随附，并可能在 LLM 从未观察到的时间触发。我们将生命周期钩子更新路径识别为一个新的攻击面，框架盲目信任该路径。在攻击者仅控制插件元数据和生命周期钩子配置的供应链威胁模型下，一个良性的版本化插件可被一次更新木马化：该更新悄悄将攻击者选择的命令绑定到良性事件，从而产生恶意的主机侧行为，例如权限提升。我们提出 HookPry，一个开源且全自动的攻击框架，可在异构 AI 智能体执行框架中系统性利用此漏洞。HookPry 实现了十个攻击目标；在 25 种执行框架与后端组合、1000 次端到端运行中，它攻破了所有七个被评估框架，每个框架的成功率最高达 92.5%。代表性防御仍然不足：Microsoft Defender 的召回率为 0%，三种静态防御的并集漏掉了 47.5% 的恶意工件。

## Abstract
Modern AI agent harnesses expose lifecycle hooks that bind shell commands to runtime events such as session start, tool calls, and file edits. These commands run with host privileges yet ship as lifecycle-hook configuration and may fire at times the LLM never observes. We identify the lifecycle-hook update path, which harnesses trust blindly, as a new attack surface. Under a supply-chain threat model in which an attacker controls only plugin metadata and lifecycle-hook configuration, a benign versioned plugin can be trojanized by an update that silently binds attacker-chosen commands to benign events, yielding malicious host-side behavior such as privilege escalation. We propose HookPry, an open-source and fully automated attack framework that systematically exploits this vulnerability across heterogeneous AI agent harnesses. HookPry realizes ten attack objectives; across 25 combinations of harnesses and backends in 1,000 end-to-end runs, it compromises all seven evaluated harnesses, with per-harness success rates reaching 92.5%. Representative defenses remain insufficient: Microsoft Defender has 0% recall, and the union of three static defenses misses 47.5% of malicious artifacts.

## 1. 论文核心问题与整体含义

### 研究背景
现代 AI 智能体执行框架（agent harnesses），如 Claude Code、OpenClaw、Codex CLI 等，广泛暴露“生命周期钩子”（lifecycle hooks）。这些钩子将 shell 命令绑定到会话启动、工具调用、文件修改等运行时事件，并以主机权限执行。

### 核心问题
论文指出一个关键安全问题：**生命周期钩子的更新路径被执行框架盲目信任**。在供应链攻击场景下，攻击者即使只控制插件元数据和生命周期钩子配置，也能通过一次看似正常的插件更新，把恶意命令绑定到良性事件上，从而在 LLM 不参与决策、用户不进行逐项授权的情况下执行恶意主机侧操作，如权限提升、凭据窃取等。

### 威胁模型
- 攻击者仅通过公共插件市场/社区仓库发布版本化插件，无本地或仓库访问权限；
- 不能修改执行框架、利用实现漏洞、绕过沙箱、强制安装或直接触发事件；
- 先发布良性版本，再以同一插件身份发布携带恶意钩子的更新；
- 攻击目标包括信息窃取、持久化、操纵、资源劫持、传播等，并映射到 MITRE ATT&CK 战术。

## 2. 论文提出的方法论

论文提出开源自动化攻击框架 **HookPry**，包含三个组件，分别对应获取、激活、跨框架鲁棒性三个挑战。

### 2.1 Adversarial Manifest Optimization（AMO）
- 在插件初始发布阶段，只优化插件的名称和自然语言描述，保持良性钩子不变。
- 目标是提高插件在目标功能类别中的可检索性，同时避免与已有良性插件过度相似。
- 使用一个多意图代理目标函数：
  - 均值项：提升对多个查询意图的平均覆盖；
  - 最小值项：保护最弱查询意图；
  - 类别质心项：使元数据与目标类别保持一致。
- 参数在开发集上预先选定，避免基于测试结果事后调参；再用 ε 约束提高实例级区分度。

### 2.2 Temporal Decoupling（TD）
- 核心思想：分离“初次安装时的信任获得”与“后续更新时的权限激活”。
- 对每个候选信任边界，测量四类指标：
  - 验证强度 V；
  - 是否需要钩子条目级授权 A；
  - 运行时权限 R；
  - 探针是否可观测 O。
- 定义信任差距 G = O ×（λr·R − λv·V − λa·A），选择满足能力要求且可观测性足够高的最大信任差距边界。
- 生成条件载荷：仅在运行时状态满足边界谓词时激活恶意行为，否则保持良性行为。

### 2.3 Least Common Interface（LCI）
- 解决跨执行框架的异构性问题：不同框架的事件名、配置 schema、命令执行器、权限边界不同。
- 将攻击语义抽象为目标效果 o(a) 和必要执行条件 q(a)；
- 从所有目标框架的共享能力交集中，移除与攻击无关的依赖，得到最小充分能力集 I*；
- 为每个框架选择依赖最少、满足能力要求的原生事件；
- 生成原生钩子配置 (e, c, σ)，其中 e 为事件，c 为命令，σ 为框架 schema 编码。

总体上，HookPry 将攻击构造形式化为：元数据优化 → 信任边界探测与条件激活 → 跨框架原生编译。

## 3. 实验设计

### 3.1 数据集 / 场景
- 端到端实验使用 **40 个攻击案例**，每个案例包含合成资产、预注册外部检查和独立判定 oracle。
- 覆盖 **7 个 AI agent harnesses**：OpenHarness、OpenClaw、Claude Code、Codex CLI、OpenCode、Hermes、WorkBuddy。
- 覆盖 **5 个 LLM 后端**：Claude Sonnet 4.6、DeepSeek-V4-Pro、Kimi-K2.6、GLM-4.7-Flash、GitHub Copilot。
- 共形成 **25 种 harness–backend 组合**，执行 **1,000 次端到端运行**。
- 十个攻击目标类别：凭据收集、数据外泄、资源劫持、命令与控制、篡改、操纵、权限提升、持久化、规避、传播。

### 3.2 Benchmark / 对比实验
- **RQ2 翻译对比**：从 MCPTox 中选择 50 个恶意 MCP 工具描述投毒目标，将它们机械转换为生命周期钩子注入，与 HookPry 原生构造的钩子进行配对比较。固定 Claude Code + DeepSeek-V4-Flash。
- **RQ4 防御对比**：构造 40:40 的恶意/良性静态工件语料，评估 Microsoft Defender、Semgrep 1.172.0 和研究者自建的 HookPolicy 0.1.0。

### 3.3 评估指标
- **E2E-ASR**：端到端攻击成功率，即所有预注册外部检查都通过的 run 比例。
- **机制效用**：钩子触发、载荷加载、钩子注册等机制级步骤实际启动的比例。
- 辅助指标还包括召回率、漏报率、误报率等。

## 6. 论文主要结论与发现

- 1,000 次端到端运行中，HookPry 获得 **770 次 pass、34 次 partial、196 次 fail、0 次 blocked**，微平均 E2E-ASR 为 **77.0%**，宏平均为 **77.9%**。
- **所有 7 个被评估执行框架均被攻破**，其中 Hermes 整体成功率达到 **92.5%**，并在五个攻击类别中达到 100%。
- 机制效用为 83.9%，高于端到端成功率，说明部分攻击在触发后被环境/策略限制。
- 在部分框架中，跨后端成功率标准差低于 2.5pp，表明事件触发后的命令绑定与派发路径具有较强模型独立性；但完整攻击仍依赖模型行为生成事件。
- RQ2 显示，将恶意 MCP 工具描述翻译为钩子后，E2E-ASR 为 **56.0%**，显著低于 HookPry 原生构造的 **92.0%**（p = 7.09×10⁻¹²），说明直接由钩子执行命令绕过了模型中介门控。
- RQ3 消融表明：移除 AMO 使成功率下降 16.4pp；移除 TD 或 LCI 使成功率降为 0%。
- RQ4 防御方面，Microsoft Defender 召回率为 **0%**，Semgrep 为 47.5%，HookPolicy 为 50.0%；三种静态防御的并集仍 **漏掉 47.5%** 的恶意工件。

## 7. 优点

- **问题定位新颖**：将“生命周期钩子更新路径”从插件代码、工具描述投毒等传统攻击面中独立出来，构成一个清晰的新威胁模型。
- **自动化程度高**：HookPry 将获取、激活、跨框架执行三个环节整合为端到端自动流水线，无需针对不同执行框架手写定制逻辑。
- **跨框架移植能力强**：LCI 通过最小充分能力集和原生编译，在 7 个异构框架上实现统一攻击语义。
- **评估设计较严格**：使用外部 oracle 判定真实效果，而不是仅以命令生成或进程派生作为成功标准；并设置了消融、配对翻译和防御对比实验。
- **安全伦理考虑完整**：包含负责任披露、阶段化开源、合成资产、授权测试范围等说明。

## 8. 不足与局限

- **真实生态代表性有限**：实验在合成环境和隔离目录中进行，未测量真实市场检索率、用户安装率和更新采纳率，端到端成功率不能直接外推到现实攻击场景。
- **算力和模型训练信息缺失**：论文未提供 GPU 型号、数量、推理时长等资源信息，难以评估复现成本。
