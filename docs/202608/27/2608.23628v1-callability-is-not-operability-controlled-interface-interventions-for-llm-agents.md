## 摘要
一次工具调用可能完全有效，却仍使自主智能体无法确定下一步该做什么。例如，如果某个外部效果已提交但其响应丢失，那么已提交状态和未提交状态对智能体而言可能无法区分，尽管它们需要不同的后续动作。我们研究可调用性与可操作性之间的这一差距：工具接口是否暴露了在操作不确定性下智能体安全继续执行所需的与动作相关的状态和语义。我们通过 Agent-First Tooling（AFT）将工具可操作性操作化，AFT 是一组接口机制，涵盖选择性能力发现、执行生命周期与恢复、显式外部效果语义、机器可读结果以及后置条件验证。我们引入 AFT-Bench，这是一个受控的接口干预框架，在任务、后端、初始状态、注入故障、智能体和语言模型均保持不变的情况下，仅改变暴露给智能体的接口。

## Abstract
A tool call can be perfectly valid yet still leave an autonomous agent unable to determine what to do next. For example, if an external effect commits but its response is lost, committed and uncommitted states may become indistinguishable to the agent even though they require different continuation actions. We study this gap between callability and operability: whether a tool interface exposes the action-relevant state and semantics needed for an agent to continue safely under operational uncertainty. We operationalize tool operability through Agent-First Tooling (AFT), a set of interface mechanisms spanning selective capability discovery, execution lifecycle and recovery, explicit external-effect semantics, machine-readable results, and postcondition verification. We introduce AFT-Bench, a controlled interface-intervention framework that holds the task, backend, initial state, injected failure, agent, and language model fixed while varying the interface exposed to the agent.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 论文研究 **LLM 智能体在工具调用中的可靠性问题**，核心区分了两个概念：
  - **可调用性（Callability）**：智能体能识别操作、构造语法有效的调用并完成协议交互。
  - **可操作性（Operability）**：工具接口是否暴露了在操作不确定性下智能体安全继续执行所需的**动作相关状态和语义**。
- **核心问题**：一次工具调用可能完全有效，但如果外部效果已提交而响应丢失，智能体可能无法区分“已提交”和“未提交”两种状态，而这两种状态需要不同的后续动作（例如盲目重试可能重复不可逆效果，拒绝重试可能留下任务不完整）。
- **操作歧义（operational ambiguity）**：当不同底层历史需要不同安全继续动作，但在接口中产生相同观察时，仅靠更强的模型推理无法保证正确继续，缺失的信息位于**智能体-工具边界**。
- **整体含义**：可靠的工具使用不仅是模型能力问题，还取决于接口是否保留并暴露了行动相关的状态和语义；工具可靠性由**模型策略与接口语义共同决定**。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **Agent-First Tooling（AFT）**：一个协议无关的工具接口操作模型，组织接口语义为多维档案：
  - 能力与表示语义：选择性能力发现、机器可读结构化输出。
  - 执行语义：可观察执行生命周期、可恢复调用、持久化执行状态。
  - 效果与治理语义：显式外部效果语义（幂等性、前置条件、提交点、权限、补偿）、后置条件验证。
- **AFT-Bench**：受控接口干预方法论，核心设计原则是**配对比较**：
  - 在每个比较中固定任务、后端、初始状态、注入故障、智能体、语言模型和执行预算，**仅改变暴露给智能体的接口语义**。
  - 接口条件包括累积阶梯（I0–I5）和机制移除消融，用于识别机制特异性效应而非生成综合“智能体友好度”分数。
- **系统模型与形式化**：
  - 后端环境 \(E = (S, U, P, Z_E)\)，接口 \(I\) 决定可观察内容和可用继续操作。
  - 接口诱导观察 \(z_t = \Gamma_I(h_t)\)；当 \(\Gamma_I(h) = \Gamma_I(h')\) 但 \(\mathcal{A}^{safe}_{>\tau}(h) \cap \mathcal{A}^{safe}_{>\tau}(h') = \emptyset\) 时，存在操作歧义。
  - 接口可通过**区分状态**（暴露更多证据）或**稳定继续动作**（幂等、守卫写等使同一继续动作跨多个可能状态安全）来减少歧义。
  - 任务定义为 \((x_\tau, s_0, \phi_\tau, \alpha_\tau, \psi_\tau, B_\tau)\)，其中 \(\phi_\tau\) 是目标后置条件，\(\alpha_\tau\) 是策略正确性接受谓词，\(\psi_\tau\) 是轨迹级安全谓词，允许安全的拒绝/中止被视为正确。
- **执行与故障注入**：
  - 故障由测试框架在后端定义执行边界注入，典型序列例如 `REQUEST_ACCEPTED → BACKEND_STARTED → EFFECT_COMMITTED → RESPONSE_GENERATED → RESPONSE_DROPPED`。
  - 结果标签从持久后端状态和 oracle 轨迹得出，而非智能体最终消息。
  - 运行时强制执行预算、调度、故障注入和记录，仅应用当前接口条件暴露的生命周期、恢复、幂等或验证保证，避免测试框架秘密修复弱接口。

## 6. 论文的主要结论与发现

- **七个预指定池化主对比全部满足计划推断标准，经多重比较校正后仍显著**。
- **选择性发现**：减少工具上下文暴露约 4,013 个 token（95% CI [1,976, 6,231]），同时能力召回满足非劣效性（配对差异 0.0139，下界高于 -0.10），证明在保留任务相关发现的同时大幅减少模型上下文中的接口表面。
- **恢复机制**：可恢复调用和持久执行状态在各自匹配的故障处理下均将恢复提高 100 个百分点（效应饱和，CI [1.00, 1.00]）。这两种机制分别针对瞬态中断和进程状态丢失，效果在所有模型和留一模型分析中稳定。
- **效果语义**：效果感知接口将重复效果减少 56.9 个百分点（CI [0.375, 0.764]），强效果语义将不安全提交减少 50.0 个百分点（CI [0.306, 0.681]）。安全中止/拒绝被视为正确，因守卫执行可将原本不安全的突变转化为安全中止。
- **后置条件验证**：将不正确终端声明减少 27.8 个百分点（CI [0.181, 0.375]）；部分成功验证的鲁棒性分析中减少 51.85 个百分点。验证修复智能体对执行结果的错误信念，而非修复执行本身。
- **模型异质性**：恢复机制跨模型稳定，效果安全在 GPT 上较弱，终端验证的边际效益强烈依赖模型（Qwen 0.3542，DeepSeek 0.4792，GPT 为 0）。这表明部分接口机制是运行时保证，而其他部分可能与模型策略存在替代关系。
- **SQLite 持久后端复制**：弱接口出现 9 个重复效果和 3 个不安全提交，效果感知接口为零，证实安全效应跨持久事务边界仍成立。
- **核心结论**：可调用性不等于可操作性；当不同操作状态需要不同动作但在接口中无法区分时，更强的模型推理不能保证正确继续；工具使用可靠性由模型策略和接口语义共同决定。

## 7. 优点：方法或实验设计上有哪些亮点

- **概念清晰**：明确区分 callability 与 operability，并用操作歧义的形式化定义夯实理论基础。
- **受控干预方法**：通过固定任务、后端、故障、代理和模型，仅改变接口语义，能够干净地归因于接口效应，避免混杂因素。
- **多层证据**：确定性实验、持久后端复制和自适应 LLM 矩阵相结合，兼顾内部效度和生态效度。
- **统计严谨**：预指定分析计划、证据冻结、Holm 多重比较校正、非劣效性检验、配对置换检验和聚类 bootstrap，结果可信。
- **正确处理安全非动作**：将安全中止/拒绝/升级视为成功，避免将“正确的不动作”误分类为任务失败。
- **跨模型异质性分析**：明确揭示接口机制与模型策略的相互作用，说明并非所有机制对所有模型同等重要，为未来研究提供方向。
- **协议无关设计**：AFT 可层叠在 MCP、函数调用、REST、CLI 等多种传输协议之上，应用前景广。

- **模型覆盖有限**：仅三个当代模型家族，不能确立模型无关的普适性；托管模型行为可能随时间漂移。
- **部分机制证据较弱**：可观察执行和最小结构化输出属于 AFT 模型，但其独立功效证据不如发现、恢复、持久状态、效果语义和验证的主结果强；事件丢失和解析器修复实验留作未来工作。
- **性能评估不足**：未评估生产规模网络、队列、地理分布式执行或高并发服务行为，只记录本地阶段级时间。
- **交互分析非确认性**：模型-接口交互分析只有 8 个任务簇，仅用于解释而非确认性声明。
- **操作语义的自动化获取限制**：幂等性范围、权限、补偿等属性可能需要显式开发者或策略输入，文中未给出从遗留系统自动推导和治理这些契约的完整方案。
