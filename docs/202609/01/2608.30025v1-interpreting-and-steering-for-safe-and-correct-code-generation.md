## 摘要
大型语言模型（LLM）经常生成包含漏洞的源代码，但很少有工作研究其中区分安全生成与易受攻击生成的内部机制。在这项工作中，我们系统地对 LLM 进行机制解释，旨在既理解代码安全与漏洞在 LM 组件中是如何被表征或驱动的，又将这些见解转化为可操作的引导策略，以鼓励更安全的代码生成。为此，我们引入了 CodeSec-Pairs，一个包含 9,342 个 Python 安全与易受攻击对比代码对的数据集，采样自 Llama-3.1-8B-Instruct。利用该数据集，我们探索了定位与代码安全相关的层和注意力头的方法，并进一步实验了不同的引导策略以在推理时减少漏洞。特别地，我们提出了 DuoSteer，一种双重引导方法，同时对注意力头施加安全性和代码正确性引导。在五类漏洞的实验中，DuoSteer 平均将漏洞率降低 26.9%，并将功能正确性提升 7.5%，不仅优于其他引导变体，也优于提示和监督微调基线。该优势在 Qwen-2.5-Coder-7B-Instruct 上也得到了复现，实验使用了从该模型采样的另外 2,500 个对比对。

## Abstract
Large language models (LLMs) frequently generate source code containing vulnerabilities, yet little work studies the internal mechanisms that distinguish safe from vulnerable generation in them. In this work, we systematically perform a mechanistic interpretation of LLMs, aiming at both understanding how code safety-vs-vulnerability is represented or driven by components in an LM and turning the insights into actionable steering strategies to encourage safer code generation. To this end, we introduce CodeSec-Pairs, a dataset of 9,342 Python safe-and-vulnerable contrastive code pairs, sampled from Llama-3.1-8B-Instruct. Utilizing the dataset, we explore approaches to localize layers and attention heads that relate to code safety, and further experiment with different steering strategies for inference-time vulnerability reduction. In particular, we propose DuoSteer, a double-steering approach that simultaneously applies safety and code-correctness steering to attention heads. In experiments over five vulnerability types, DuoSteer leads to an average of -26.9% vulnerability rate reduction and +7.5% functional correctness improvement, which outperforms not only other steering variants but also prompting and supervised fine-tuning baselines. The advantage also replicates on Qwen-2.5-Coder-7B-Instruct with another 2,500 contrastive pairs sampled from that model.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **动机**：大语言模型（LLM）在代码生成中应用广泛，但大量实证表明其生成的代码频繁包含安全漏洞（例如 CWE-22 路径遍历、CWE-502 不安全反序列化等）。
- **研究空白**：现有缓解手段（提示级干预、安全微调）主要停留在模型输入/输出边界，对模型内部如何区分“安全”与“易受攻击”的生成机制研究甚少。
- **核心问题**：
  1. 在代码 LLM 中，“安全 vs 易受攻击”的区分在哪些内部组件中被表示和驱动？
  2. 能否将这些内部机制转化为无训练的推理时干预，从而降低漏洞率且不牺牲功能正确性？
- **整体含义**：该工作把“安全代码生成”视为机制可解释性问题，通过定位因果相关的注意力头并施加“安全方向”和“正确性方向”的双重引导，为安全代码生成提供可解释、可操作的干预手段。

## 2. 论文提出的方法论

### 2.1 数据集构建：CodeSec-Pairs

- 从 Llama-3.1-8B-Instruct 采样，构建 **9,342 个 Python 安全/易受攻击对比代码对**，覆盖五类 CWE：CWE-022（路径遍历）、CWE-079（跨站脚本）、CWE-094（代码注入）、CWE-295（证书验证绕过）、CWE-502（不安全反序列化）。
- 每对代码由安全版本和易受攻击版本构成，分为 **intra-prompt pairs**（同一良性提示下采样得到）和 **cross-prompt pairs**（良性提示采样安全代码 + 漏洞诱导提示采样漏洞代码）。
- 每个对比对额外用 GPT-4.1 标注两维信息：
  - **结构距离**：Minimal / Refactor / Divergent
  - **修复机制**：Substitution / Guard-Addition / Deletion / Unclear
- intra-prompt pairs 用于训练探针和构建引导向量；cross-prompt pairs 仅用于因果 knockout。

### 2.2 定位漏洞相关组件

- **线性探测（Linear Probing）**：训练逻辑回归探针，在每层残差流或每个注意力头输出上区分安全 vs 易受攻击代码，测量该区分在何处被线性编码。
- **因果头敲除（Causal Head Knockout）**：对每个注意力头，将其输出置零，计算模型对“安全续写”相对于“易受攻击续写”的偏好变化（公式略），从而得到每个头的因果效应 Δ。若敲除后安全偏好下降，则该头为“安全促进型”。
- 两者结果高度不重合：探针排名与因果效应排名的 Spearman 相关在每类 CWE 上 |ρ| ≤ 0.072，p > 0.25；每类 CWE 中最重要的因果头在探针排名中仅位于第 65–250 位。

### 2.3 表征引导（Representation Steering）

- 使用 **mean-difference（MD）向量**作为引导方向：`v = x̄_safe − x̄_vuln`（层级或头级）。
- 对向量做 **σ 归一化**后乘以强度 α 注入：`x ← x + α · v/σ`，其中 σ 为对应表示的标准差。
- 评估三种引导配置：
  - **LAYER MD**：在最佳探针层注入全层残差流。
  - **PROBE MD**：在探针排名 top-k 的注意力头注入。
  - **CAUSAL MD**：在因果排名 top-k 的注意力头注入。

### 2.4 DuoSteer：安全与正确性双重引导

- 单向量安全引导虽能降低漏洞率，但常导致功能正确性下降（安全-正确性权衡）。
- **核心思想**：同时注入两个方向：
  - **安全方向**：来自安全 vs 易受攻击代码对。
  - **正确性方向**：来自安全且正确 vs 安全但错误代码对，以隔离正确性信号。
- 两个方向分别施加在各自的 **因果头部集合** 上。若某头同时属于两个集合，则两个向量在该头相加。
- 经验发现，安全因果头池和正确性因果头池大部分不重叠（top-32/64 中重叠仅 2–25 个），且两个方向在因果头处平均余弦约 −0.16，呈轻度反对齐。

## 6. 论文的主要结论与发现

- **安全/易受攻击区分在残差流中线性可解码，但位置因 CWE 而异**：层级探针准确率 71–87%，最佳层在 CWE-022/079/094/502 上为第 9–11 层，CWE-295 为最后一层；头级信号则高度 CWE 依赖（CWE-022 几乎无头信号，CWE-295 有 960 个头超过 0.65 准确率）。
- **探针排名不能预测因果重要性**：两者几乎不相关，最重的因果头通常不在探针高排位区域。因此，因果定位才是解锁强漏洞抑制的关键。
- **单向量安全引导存在安全-正确性权衡**：CAUSAL MD 能显著降 V，但常以 C 大幅下降为代价；Probe MD 效果很弱；Layer MD 介于其间。
- **DuoSteer 有效缓解权衡**：
  - 在五个 CWE 上平均降低漏洞率 26.9%、提升正确性 7.5%。
  - 最显著：CWE-502 漏洞率从 64.7% 降到 0%，正确率升至 94.1%；CWE-079 漏洞率降至 3.9%，正确率 82.3%。
  - 该优势在 Qwen-2.5-Coder-7B-Instruct 上复现，所有 CWE 联合分数均提升。
- **DuoSteer 优于非引导基线**：在联合分数上全面超过 Hint Prompting 和 SFT。提示方法常以正确性大幅下降为代价；SFT 在不同 CWE 上表现不对称且可能升高漏洞率。
- **因果头和正确性头的分离是 DuoSteer 成功的关键**：安全因果头池与正确性因果头池大体不相交，因此单向量无法同时覆盖两个轴；两方向在表示空间近乎正交（平均余弦 −0.16 到 +0.08），支持分别施加。
- **跨 CWE 可引导性差异可事后解释**：训练对中 Refactor 比例越高、修复机制越集中（如替换/加守卫），平均差向量越抽象、可迁移，引导效果越好；Unclear 主导的 CWE（022/295）效果最差。

## 7. 优点

- **新颖的视角**：将安全代码生成问题纳入机制可解释性框架，连接内部表征与推理时干预，而非仅黑盒调优。
- **贡献了 CodeSec-Pairs 数据集**：包含 9,342 对安全/易受攻击代码，带结构距离和修复机制标注，可供未来研究复用。
- **揭示探测与因果的分离**：用系统实验证明线性探针定位与因果重要性不重合，纠正“可解码即可干预”的常见假设。
- **提出 DuoSteer 双引导**：分别处理安全性和正确性，并在因果定位的头上分别注入，有效缓解安全-正确性权衡，且无需任何训练。
- **方法与基线的公平对比**：与提示增强、监督微调、单向量引导等多种方案对比，并涵盖跨模型复现。
- **鲁棒性分析与可部署性**：提供采样解码、统计检验、留出集配置选择、执行单元测试等分析，显示方法在实际解码和先验配置下仍有效。
- **清晰的机制解释和事后分析**：通过向量几何、结构距离、修复机制解释跨 CWE 差异，为方法适用边界提供依据。

## 8. 不足与局限

- **模型规模有限**：仅在两个 7–8B 开源指令模型上验证，未覆盖 70B/405B 或闭源 API 模型；白盒访问注意头激活是该方法的前提，闭源 API 尚不适用。
- **语言和漏洞类型覆盖窄**：所有实验均为 Python，覆盖五类 CWE；扩展到其他语言（Java、JavaScript、C/C++）或其他 CWE 需重新采集对比对和定位因果头。
- **上下文过于简单**：评测基于 SecCodePLT 的孤立函数桩，未考虑真实软件工程中的仓库上下文、检索片段、多轮编辑等复杂场景。
- **头定位并非完整电路解释**：单头敲除只测量隔离效应，未考虑头间交互或路径追踪；因果排名可能受零化方式影响，后续可用反事实激活替换或电路发现改进。
- **正确性判官依赖 LLM**：功能正确性由 GPT-4.1 判断，虽有与人类标注 κ≈0.87 的校准，但 CWE-022 和 CWE-295 无执行测试；且单元测试覆盖较窄，仅固定少量测试用例。
- **主表配置在评测集上扫参**：虽然附录 J 提供了留出集选择协议，但正文中的最佳性能上限存在轻微过拟合风险，读者应结合留出集结果解读。
- **方法可逆性风险**：激活引导方向取反可能诱导更不安全代码，作者建议仅限防御性使用，需要谨慎部署。
- **CWE-022 边界失效**：在该类漏洞上安全方向本身因果牵引不足，任何头级引导都无法在留出集上超过基线，说明方法对不同 CWE 的普适性不均。
